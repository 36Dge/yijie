## 决策与实现边界

采用原Runtime中的通用input-only会话约束，允许原文本模型生成和正常原生历史持久化；在初始化及每次turn处关闭额外指令来源和工具能力，由实际有效会话状态产生stable证据。Host沿原Manager、thread/turn、operation和持久用途隔离消费。它不是新用户权限模式，不包含调度/计划/电商语义，也不是返回true的人工资格开关。

本轮按整体`contract-impact=breaking`保守评审：新增Runtime本地候选及stable证据影响精确pin和下游解释；先Runtime权威/生成与验证，再Contracts兼容投影，最后Host消费。旧产物、旧投影和普通入口保留，新候选从相同上游与有效两补丁基线构建到新项目输出路径，不覆盖已有固定二进制，不重启FEAT-137、不使用其历史四补丁候选。任何后续修改均记录实际来源和差异。

修复顺序：原生初始化/工具封闭与查询证据 → 正常安全定向测试及候选构建 → stable同源schema和兼容投影 → Host资格与失效 → 同一Host/Runtime的正常start/resume/重开零模型验证 → 结构化审查和结果记录。只有真实证据成立才改变资格；失败不得用fixture或开关替代。

本轮先使用零真实模型/图片/商家/MCP外部调用检查。既有文本总额12、累计0保持逐次计数；不因长期目标擅自消耗额度、迁移日常库或扩大到页面。禁止强杀、权限破坏、攻击资源和执行文件伪装。日常库和Keychain保持不触碰。

最终记录必须区分Runtime受限能力、Host策略资格、Provider outputSchema资格、产品装配和D4；逐项以本轮实际检查为准。未完成项不会写成PASS。
