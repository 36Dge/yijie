## 2. 不能丢失的关键规则

1. **职责分开。** Desktop native拥有计划、时间计算、occurrence/run与SQLCipher账本；共用原worker、Coordinator和outbox。Host负责薄适配、执行映射及只读恢复，Runtime拥有真实thread/turn、审批和执行结果。没有引入云调度、Redis或退出后的常驻服务，也不能将Codex桌面产品的定时功能等同于当前fork能力。
2. **Runtime确有一次经授权的最小扩展。** 27的旧产物资格不足已由29解决：同一固定上游0.144.6上新增input-only限制和稳定策略查询，服务于受限草案；不是新增调度引擎或升级上游。之后各批“Runtime未改”指相对该合格候选，不表示整个FEAT从未修改Runtime。见[29报告](29-draft-runtime-unblock-report.md)及[ADR-0020 DEC-155-09](../../adr/ADR-0020-local-scheduled-task-authority.md)。
3. **保存不等于授权执行。** 后续已批准的行为是保存暂停计划，再显式确认有限自动授权。模型草案不能自证保存成功；native校验后用户确认，重复确认只能保存一个计划。不得按早期“默认开启”文字改回保存即执行。
4. **自动授权与单次许可独立。** 手动运行/重跑一次、最长10分钟，不替换或消耗原自动计划授权。发送前核对版本、目标、当前权限、期限与预算；首期实际任务沿Ask，不代答审批、不自动切换完全访问。受限草案的input-only资格不能替代普通Ask任务资格。
5. **三目标有不同身份。** 专属聊天首次建立后持续复用；每次新建聊天逐次独立；已有聊天明确选择可访问ID并沿原目录。新聊天使用native受管目录，不能伪造用户书签或默认挑首个项目。plan/run/conversation/session/thread/turn/operation不能混用。
6. **时间规则固定。** 仅一次、每天、工作日、每周；IANA时区保存后固定，工作日不暗含法定节假日。DST重复时刻一次、缺失时刻跳过；正常清醒延迟窗口60秒，退出或睡眠错过不补跑。重开先恢复事实，再计算未来，不能积压补跑或无界遍历。
7. **并发与未知要保守。** 定时运行全局最多一个未释放占用，并与前台共享预约；忙碌跳过/明确拒绝。已尝试且结果未知不自动重发，释放须依据可信终态、正常中断或受管generation正常关闭。不能承诺跨Runtime端到端exactly-once，也不能靠删预约或假终态解锁。
8. **计划状态、执行状态、业务结果分层。** 四状态筛选按计划当前生命周期；一次计划完成不意味着业务成功，循环单轮成功不结束计划。未执行槽不能伪装run；Runtime completed不能掩盖工具失败。当前“执行已结束/业务结果尚未评估”是诚实投影，不应为贴合截图改成无依据的成功。
9. **历史不可改写。** 编辑只影响未来；重跑按当前已保存配置审阅与原快照的差异，产生新run，旧历史不变。删除计划保留历史和对话，有在途/待审批/未释放unknown时拒绝删除；已删除计划不能重跑。执行时间来自Runtime，耗时用原生毫秒，不拿排队/计划/本机观察时间代替。
10. **唤醒、通知与范围取舍明确。** 保留的是App生命周期内防自动空闲睡眠，默认关闭，退出释放；不承诺从关机、合盖或手动睡眠唤起执行。系统通知已接受首期延期，应用内完成/失败/需处理的重要更新仍在范围。16小时上限已获本需求例外，不再是阻断，也没有授权删减Must。
11. **候选与日常入口分开。** 当前普通SQL15/Store5，显式隔离候选SQL26/Store6；兼容reader先于writer，旧迁移不改，不降库、不迁移日常库。候选完成不是普通入口已开放，也不是提交、发布或生产批准。

## 5. 必须保留的审计发现

### A-01：卡片与记录交互未完成（AC-005/006/009）

当前[管理页源码](../../../../yijie-desktop/src/pages/schedules/ScheduledTasksPage.vue)177–195行：卡片只有启用、立即运行、编辑、暂停、删除文字按钮，未接按plan_id查看历史；没有PDF三图标、hover/focus和tooltip组合。卡片/记录主体无对应点击处理，详情靠查看记录按钮打开。这是确定的原需求缺口，并非纯验收证据缺失。

建议先复用已有查询和`planFilter`补齐交互；有限启用/单次执行确认、未知先查证及删除保护保持。无需重构调度或增加模型调用。

### A-02：防自动空闲睡眠未实现（AC-010）

[platform_lifecycle.rs](../../../../yijie-desktop/src-tauri/src/chat/platform_lifecycle.rs)仅监听系统willSleep/didWake并转换生命周期。未找到IOPM防空闲睡眠assertion、受管开关及释放链，管理页也无该开关。**“能观察休眠”不等于“已保持唤醒”**。该能力已接受保留，不能用系统通知延期将它一起删掉。实际平台验证要覆盖正常开启、关闭、退出释放、手动睡眠后只恢复未来计划；不得强杀制造故障。

### A-03：应用内重要更新未接通（AC-010）

[App.vue](../../../../yijie-desktop/src/App.vue)具有NNotificationProvider，但未发现定时完成/失败/需处理事件到全局通知、去重及运行跳转的接线。管理页局部NAlert及手动刷新结果不能等同此能力。后台待审批/未知运行不应要求用户碰巧进入对应聊天才能发现。只补已批准的应用内路径，不扩展邮件、钉钉、短信或系统通知。

### A-04：文案尚未完全按需求收口（AC-003/008）

[ScheduledPlanForm.vue](../../../../yijie-desktop/src/components/schedules/ScheduledPlanForm.vue)66–67行仍为“例如：每日经营摘要/描述需要完成的任务”，尤其内容占位词缺少跨境业务示例；[scheduled-task-ui.ts](../../../../yijie-desktop/src/domain/scheduled-task-ui.ts)状态选项为“全部/已启用/已暂停/已完成”。需要对齐指定文案，但不改变按计划生命周期筛选的既定语义，也不承诺尚未授权的店铺数据访问。

### A-05：整体D4证据尚未形成

35/37/39/41/43/45分别证明不同阶段、不同运行的局部结果；不得把它们拼写成同一fresh run全部Must通过。37/39明确没有真实原生审批和系统睡眠验证，相关逻辑只有合成/组合证据；45不能填补这两项。整体代表性失败/可恢复路径及带历史删除等须按最终范围安排正常安全验证。

### A-06：需求文档的当前状态不够集中

00、02、03及ADR正文保留初稿“仅落需求/Q pending/16小时阻断/全部未执行”等段落；00 P05还有“默认开启”，04“外部调用台账”表仍列12/8，而顶部与最新feature.yaml为14/10。顶部虽声明历史语义，分散读取仍容易得出错误结论。
