## 2. 用户问题、结果与范围

**目标用户：** 使用易界桌面端的跨境电商卖家。用户希望周期性执行明确的经营分析提示词，不必每次手动输入，并能知道计划是否开启、何时运行、结果在哪里。

**预期结果：** 用户可以通过对话或表单建立同一类定时计划；在此设备满足运行条件时按计划执行，或手动触发；查看实际执行历史和对应完整对话；可以暂停、编辑与删除计划。仅有页面、假卡片或模拟运行结果不构成该需求完成。

**范围内：** 左导航/管理页、两种创建路径、运行目标与计划规则、任务卡片、启停/编辑、单次运行、删除确认、记录筛选/详情/重跑/对话跳转、必要的本地保存恢复、权限/审批、设备唤醒提示、统一 UI。运行管理与生成结果复用既有聊天事实，不能维护另一套聊天状态机。

**范围外：** 会员/订阅/推荐案例；项目创建及项目筛选；云端调度、远端机器、多设备接力、退出 App 后的系统守护进程或开机自启；Coze 工作流编排/电商节点执行；后台自动打开网页/发消息/改广告/发布商品；多租户生产调度、公开服务与生产 SLA；任意 Cron/RRULE 编辑器和无限高频计划；恢复 FEAT-137；未经批准升级/替换 Runtime；Git 提交、推送、部署。已有 FEAT-153/154 不因此增加节点业务实现。

Profile 采用当前默认 `demo_fast + local`。首期仅本人本机、合成或公开非敏感示例；若后续要处理真实商家敏感数据、重要生产计划、多租户、不可逆 migration 或组织级生产责任，先显式升级生产治理，不用本包 D4 替代。

### 3.1 页面和主流程

1. 从 canonical local direct-entry 进入易界；保持 ADR-0018 零登录首页行为。再点击左导航既有“定时任务”项，显示独立标题/说明和页面工具栏。候选路由 `/scheduled-tasks`，当前代码不存在该路由。

3. 主体两个 Tab：“我的定时任务”“执行记录”。切换 Tab 保留本页搜索/筛选上下文；默认进入我的定时任务，默认创建时间倒序，同时间以稳定 ID 打破顺序。排序候选仅创建时间倒序/正序，不虚构 PDF 未指定的排序项。
4. 无任务显示“暂无定时任务”与创建按钮；无搜索结果显示“未找到匹配的定时任务”及清空搜索；无执行记录显示“暂无执行记录”，不填充演示记录。刷新不重复创建/执行，不重置用户正在编辑的内容。
5. 搜索作用于当前 Tab 的任务名称与任务描述；执行记录内使用运行时快照进行匹配。Tab/任务/状态筛选相交；清空筛选恢复完整可访问列表。大列表采用增量加载/分页，保留稳定排序，不在 UI 线程扫描聊天全文。

### 3.2 通过对话创建

- 点击后跳转首页新建任务输入框，填入：`请帮我创建一个定时任务，每【时间间隔】在【时间/时区】执行【具体跨境电商任务】。` 用户可改写；不自动发送、不自动创建、不切换权限模式。
- 示例提示可为“每个工作日 09:00，汇总我提供的 Amazon 美国站公开商品链接的价格变化和 Listing 待优化项”；示例不等于已获取店铺授权或网络/付费调用授权，不默认读取卖家私有数据。
- 首页已有未发送草稿时，先提示保留草稿并取消跳转，或由用户明确选择替换为引导词；默认保留，不静默覆盖或拼接。已有会话正文/附件/草稿不得因该入口丢失。
- 发送之后复用既有对话链理解定时意图。缺名称、内容、时间/时区或运行目标时先澄清；保存前呈现结构化摘要并由用户确认。目标 ID、时间规则、scope 和授权由受信边界校验，不以模型文本/“已安排”的回复作为保存成功证据。
- 通过受管创建能力持久保存后，才显示成功及“查看定时任务”入口；与手动创建使用同一计划事实源，返回管理页能看到同一 ID。失败保留内容可重试；一次逻辑确认最多创建一份计划。03已查明固定Runtime没有计划创建工具，推荐stable outputSchema生成草案、native校验与用户确认后同源保存；不新增experimental工具服务，真实Provider合规率尚未验证。

### 3.3 手动创建与计划时间

### 3.4 “运行于”三种模式

三种模式来自 p2 图5；以下为候选明确语义，不代表 Codex fork 已提供自动化能力：

| 模式 | 运行与历史语义 |
|---|---|
| 此任务的新聊天（默认候选） | 此处“任务”指本定时计划；首次实际运行建立专属会话，其后复用同一会话，逐次 run 保留各自 turn 关联；保存计划本身不发起模型调用 |
| 每次运行时新建聊天 | 每次实际运行新建会话；重试必须先确认是否已创建/已提交，不能重复开会话；每份记录指向各自会话 |
| 已有聊天 | 通过可访问聊天列表和搜索明确选择 ID；展示名称与必要的更新时间消歧；不从名字猜 ID，不自动替换被删除或不可访问的会话 |

无已有聊天时保留两种新聊天模式并提供明确空态。目标正忙、等待批准、已删除、不可访问或不满足原生继续条件时，保存/执行分别给出可判定阻断说明；不将命令注入正在运行的 turn，也不新建替代会话掩盖失败。多个计划指向同一会话时仍须串行服从现有会话权威，见 §3.6。首期三模式支持程度是 Q-02，不能无声缩减。

03补充：现有新会话必须有project_id/bookmark；推荐新聊天使用明确显示的native受管工作目录引用，已有聊天沿原目录。该来源类型尚未批准，不能假装已有projectless能力或隐选用户首个目录。所谓原子懒绑定只覆盖本地会话/task引用，Host session与Runtime thread在确认后关联。

### 3.5 卡片、编辑和计划生命周期

- 卡片显示名称、任务内容摘要、频率/时间/时区、下次执行、运行于摘要与启停开关；长文本截断但可通过详情/tooltip 查看，不改变原数据。暂停/已完成时不展示虚假下一次执行倒计时。
- 计划生命周期与运行结果独立。候选计划状态：**已开启**（允许后续自动触发）、**已暂停**（不安排新触发）、**已完成**（仅一次计划的调度义务已结束）。一次计划某次执行失败仍可能已完成，详情必须显示实际失败；循环计划单次成功不能变成已完成。未能投递的错过/阻断保留原因，不伪造成功运行。
- 开关执行暂停/恢复并显示保存中；失败恢复已确认状态，提示可重试，不只改前端颜色。暂停不强行中断正在运行的一次。恢复只计算未来计划；仅一次已过期时需编辑时间后重新开启。
- 建议点击卡片主体打开编辑弹窗，复用创建字段；操作图标不冒泡触发编辑。保存后只影响未来运行；历史保留原名称、内容、时间规则与目标快照。运行中编辑不改本次内容；发生并发修改时提示刷新重审，禁止最后写入静默覆盖。
- 已完成计划不能仅切换开关复活到过去时刻；“立即执行”是独立手动运行，不修改原计划完成状态或下一次计划时间。

### 3.6 查看历史、立即执行、重新执行与并发

- 悬停卡片显示三个图标，文案依次为“查看历史记录”“立即执行”“删除任务”。键盘 focus-within 同样显示；tooltip、可访问名称和点击区域完整，不依赖悬停才能操作。
- 查看历史切换到“执行记录”，按稳定计划 ID 预筛选，显示所选任务和清除入口；无记录用正常空态。不能按同名字符串筛出其它任务。
- 立即执行必须先校验计划、目标、scope、权限、成本与运行条件；成功受理后创建一份运行记录，触发方式为“手动触发”。已暂停计划允许明确的手动运行，仍保持暂停；计划自动触发标“计划触发”。重复点击在请求中禁用并由权威端幂等兜底。
- 详情“重新执行”是新的手动运行，引用原记录用于追踪，不覆盖/翻转原运行结果；推荐默认使用当前已保存计划，执行前显示与历史快照的差异，由用户确认后运行。计划已删除则不可重跑，说明原因；不静默恢复删除的计划。
- 同一计划最多一个未结束的运行；同一目标会话有有效 turn/待审批时不并行注入。手动请求返回忙碌原因；自动冲突不无限排队，记录“本次未执行：目标忙碌”，保留下个周期。不同目标是否并发及上限交由 Q-01 冻结，沿用现有执行容量，不能增开无上限后台会话。
- 网络/工具/模型业务失败不自动重复真实调用；保存和只读加载可显式重试，重跑模型必须是新运行并再次符合权限/预算。不明确“是否已提交”的场景先查询/协调，不盲目 turn/start。
- 超时/断连不等于原生失败或取消；UI 显示“状态确认中”与刷新，保留同一 run/turn 关系。取消已发出的运行只通过既有原生中断及确认，不强杀进程，不通过关闭弹窗假造取消。

### 3.7 删除与数据生命周期

- “删除任务”先显示任务名、未来运行将停止、已有记录/完整对话保留的确认。默认取消；删除失败保留卡片和错误反馈，成功后移除列表项。
- 运行中或等待审批时暂不允许删除计划，明确提示先等待结束或在完整对话使用原生取消；删除操作不偷偷终止任务。确认删除后即撤销未来触发，不能只删 UI。
- 删除计划保留最小身份墓碑和历史快照，历史显示“已删除任务”；禁止因此删除聊天、附件或产物。历史筛选仍可按该 ID/历史名定位，重跑禁用但原对话可访问时仍可打开。
- 本地计划、启停状态、调度进度、run/会话/turn 关联须耐受正常退出重开；持久化权威由 Q-01 决定，复用现有加密存储/历史能力，不新增明文正文副本，不写用户真实数据作 fixture。
- 不擅自定义无限保留、后台清理或新数据迁移。历史保留和清理沿用已有合规/产品边界；新增元数据期限及回滚兼容需在实施前冻结。只追加可回退结构，旧聊天和 schema 14/15、Host schema 5 的有效记录不得改写。

### 3.8 执行记录和详情

- 执行记录工具栏保留“全部任务”及“全部状态”，移除“全部项目”。候选列：任务/运行状态、运行于、执行时间、耗时；整行可点击，必要操作保留清晰入口。“所属项目”不显示无意义的 `-` 项目占位。
- PDF 指定筛选项原样保留：全部状态、已开启、已暂停、已完成。**建议该筛选按计划当前生命周期过滤**，tooltip 明确“按定时任务当前状态筛选”；已有记录在暂停计划后会归入已暂停。删除计划历史仅在“全部状态”可见，并保留“全部任务”中的历史任务选项。该解释及“已完成”口径须 Q-03 批准。
- 单次运行另外显示：排队/运行中/等待批准/成功/失败/已取消，以及尚未投递/状态未知等真实诊断。最终字段/枚举由权威契约定义；这些是中文呈现要求，不能把原生 turn、item 和调度状态混成一个 enum。
- 详情字段：任务名称、执行状态、触发方式、执行时间（精确到秒并带时区）、执行耗时、运行于；失败时增加安全摘要，等待批准时指引完整对话。耗时来自实际开始/结束；运行中可显示已持续，不伪造最终耗时；尚未开始显示“未开始”。
- 底部有“重新执行”“查看完整对话”。后者跳到真实 `/chat/:sessionId` 并优先定位该次 turn；计划模式不同也必须找对本次记录。历史只读/会话被删除/不可访问时说明原因，不跳到无关首页冒充成功；没有真实会话的未投递记录禁用该按钮。
- 对话仍由 FEAT-132/134/136/144 的 native 事实与既有持久记录决定；不得合成 tool 成功、从助手最终话术推定执行完成，或复活已删除历史。业务任务成功口径须真实终态与错误事实共同呈现，不能只靠“turn completed”盖过 tool failed。

### 3.9 设备、唤醒、通知与权限

- 候选运行边界：易界及受管 Host 正常运行、设备唤醒、必要资源可用；退出/睡眠期间不承诺准点，不新建常驻守护进程。唤醒后建议跳过已错过周期，显示错过时间/原因并提供手动执行，禁止补跑风暴；仅一次过期不能无声丢失。
- PDF 保持系统唤醒开关必须是实际受管原生能力；候选默认关闭，仅用户主动开启后在本次 App 生命周期阻止自动休眠，不改变系统永久电源设置，不绕过手动睡眠/合盖限制。关闭或正常退出必须释放；不支持时禁用并说明，不能有假开关。保留该能力或批准延期由 Q-04 决定。
- 图4的通知默认“重要更新”解释为完成、失败、需要处理时给应用内提示；系统通知只有在权限与能力存在时触发，不因拒绝系统通知权限而阻止计划。没有既有通知通道时不可静默画成已接通；具体选项由 Q-04 冻结，不扩大为邮件/钉钉/短信发送。
- `schedule.read` 是当前可见性能力，不能直接当作创建/编辑/删除/触发授权。新增管理/执行能力由 Contract First 评审明确，native 固定 scope 与 Host context 不可被 renderer/提示词指定。
- 无人值守不等于完全访问。沿用 FEAT-152 当前权限模式和既有审批；需要批准则标等待批准并引导原对话，不自动确认、缓存跨次授权或切换 Ask/Auto/Full。权限丢失、目标无权、凭据过期时阻断本次真实执行并展示可恢复原因。
- 定时本身不授予店铺写入、消息发送或付费额度。计划创建的用户意图与每次具体工具/参数/有效期授权分开；外部敏感写入与付费调用遵循既有审批、审计和预算。日志仅计划/运行 ID、阶段和安全错误，不输出 prompt/secret/PII 全文。

## 4. UI 规范、状态与质量要求

视觉权威为 Desktop [终版决策 2.1.0](../../../../yijie-desktop/docs/design/docs/design/00-final-decisions.md)、[组件状态矩阵](../../../../yijie-desktop/docs/design/docs/design/04-components/09-component-color-state-matrix.md)、[尺寸规范](../../../../yijie-desktop/docs/design/docs/design/04-components/10-component-sizing.md)及现有组件。PDF 用于信息结构/交互参考，不复制其它产品的黑色主按钮、灰重阴影和品牌文案。

- 使用 YjPage/YjPageHeader/YjTabs/YjEmpty/YjIcon 和项目既有 Naive UI 表单、弹窗、表格等承载；纯白/石墨/青柠 token，普通卡片与输入无阴影、弹层轻投影，状态颜色同时有文字。避免硬编码第二套主题和随意修改全局组件。
- 最小原生外框 1180×760、推荐 1280×820；亮/暗/跟随系统均正常。外框与实际内容视口分别记录，不能假定760px全为内容高度；覆盖例如1180×728的较小内容区域。卡片按可用内容宽度自适应排列；表单过高在弹窗内部滚动，标题/底部操作可达，不能把保存挤出窗口。
- 常规操作按钮 36px，紧凑筛选 32px，标签 24px；2px 中性 focus；Lucide 图标。危险操作使用项目危险语义，主创建/保存遵循青柠主操作规则。
- Tab、搜索、开关、图标和弹窗支持键盘；可访问名称、焦点圈、modal focus trap 与关闭后焦点归还完整。Escape 服从未保存确认；对比度、长中文、长任务名均不破坏布局。
- 可取消的列表读取有超时/错误出口；计划卡片数量增大不阻塞输入或触发无上限轮询。后台更新不抢焦点，不折叠用户正在查看的详情；精确性能 SLO/全平台系统通知专项列为后续，不能影响本地可用性。

| 状态 | 可观察 UI 与恢复方式 |

## 6. 工程事实、假设、未知与契约

**Fact：** 当前定时任务导航禁用、无路由；API scheduler 为空占位；有 `schedule.read` 投影，无已核实的计划管理/执行契约。Desktop `/chat` 输入草稿、既有会话/原生 turn 执行、加密聊天记录、审批和历史可以作为复用基础。固定 yijie-codex 当前搜索未发现完整 automation/cron/rrule 调度 API/模块。详见 [01 §1—2](01-delivery-log.md#1-只读工程事实与仓库基线)。这是有限源码审计结果，不推断所有 Codex 版本均无此能力。

后续Q-01已正向枚举267份stable schema/87个ClientRequest method及handler/持久化类别，确认当前固定fork没有完整计划调度服务；Host已有operation幂等，但缺公共恢复查询；后台context最长300秒、新聊天必需项目目录、同库升级旧reader会拒绝等具体缺口见03。

**Assumption：** 首期只在本机 App/受管 Host 生命周期运行；三种目标按 §3.4 解释；重跑用当前计划、错过不补跑、默认每天09:00、字段长度、通知/唤醒默认都是本包候选建议。

**Unknown：** 03的推荐职责/权限/目录/并发/回退是否被Owner接受；候选时间库依赖组合与Provider结构化输出的真实资格；macOS打包后的正常唤醒/退出行为。计划权威推荐已明确为Desktop native，不再将归属笼统留空；不能把Codex应用能力当作固定fork公开API。

**Conflict：** PDF 四个“状态”与运行成功/失败混用；参考图“新建项目/所属项目”与运行于聊天模式不同；PDF 图示功能完整性与当前只有聊天执行链的工程事实不一致。处理方式为 Q-01—Q-04 明确冻结，不删除 PDF 需求、不暗中填造能力。

当前文档变更 `contract-impact=none`：只新增/更新需求材料，不改wire、数据库或运行语义。**未来完整FEAT-155维持breaking评审**：Q-01已证实同库新migration会使旧binary拒绝整个Chat库，新增workspace/能力/IPC亦需严格consumer兼容；不能仅因新增接口/表称additive。需兼容reader先行和forward回退，详见03 §11；这不是声称本轮已有代码发生破坏。

权威分层：固定 Runtime canonical schema负责原生执行边界；yijie-contracts负责易界跨仓API/tool、共享领域payload及必要Runtime兼容投影；Desktop-owned私有IPC封套/UI投影与本地存储分别由Desktop源schema/migration治理，再由对应provider/consumer按方向接入。私有IPC沿用[FEAT-126已接受权威](../FEAT-126-public-task-authorization-hardening/04-contract-change-plan.md)，组合而不复制Contracts共享定义；新增跨进程边界仍须分类、同源生成与conformance，不能以同一发布单元豁免。新增请求 provider 先可接收；新响应/事件先让旧 reader 容忍或升级 consumer；持久格式先 reader 兼容后 writer。私有存储由所属仓 migration 管理，不把数据库行当跨仓 DTO。这里不新建实际契约、不选择数据库 schema、不伪造 pin/tag/consumer 批准。
