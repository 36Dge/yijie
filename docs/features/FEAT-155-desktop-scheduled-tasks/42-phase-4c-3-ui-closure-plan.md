# FEAT-155 · 4C-3 视觉与交互收口执行方案

2026-09-23。本轮只读复核与方案设计，未开始修复、启动服务或调用模型。建议下一步**只收口UI-4C3-01，完成4C-3验收后报告并停止**。这是40方案的剩余工作，不新增产品阶段或改变FEAT-155的目标。当前事实以[41实施报告](41-phase-4c-3-single-run-and-rerun-report.md)及其证据为准。

## 1. 为什么先做这一步

4C-3已完成单次授权与自动计划分离、独立重跑、新旧运行关联及精确结果定位。124项原生回归、35项前端定向、68个实际契约交换通过；真实重跑HTTP200/native completed，正常暂停和退出重开无补发。无需为同一执行事实再次消耗真实模型额度。

剩余问题直接影响用户能否看清配置和许可后确认：AX树能读到确认内容，但截图没有弹层；暗色截图出现shell已变暗、卡片仍浅色；默认取消焦点、关闭返回焦点及长内容滚动尚未完整验证。**不能仅凭AX可点击判定弹层可见，也不能仅凭截图异常断言产品有同样故障。** 当前根因未知，先取得区分证据，再决定是否改代码。

| 已核实的源码事实 | 对下一步的约束 |
|---|---|
| `ScheduledTasksPage.vue`以现有NModal/NCard展示自动、单次确认与记录详情；单次取消焦点依赖after-enter，返回焦点依赖after-leave。 | 检查真实显示状态、过渡完成、焦点及详情→重跑切换，不能只检查review变量非空。 |
| 当前安装的Naive Modal使用VLazyTeleport、BodyWrapper/Transition/vShow；应用未在该页面自造弹层。 | 沿现有组件链定位，不预设为z-index问题，不先替换组件或新增浮层系统。 |
| `App.vue::applyColorScheme`先设根data-theme，再读取token，更新Naive基础theme及themeOverrides；根NConfigProvider统一传递。 | 分别观察系统事件、根token、provider及实际卡片/弹层的计算样式；不把shell变色等同整个主题更新。 |
| 当前theme测试验证静态亮暗token/控件，manual测试主要验证调用与回执；这些不证明真实WKWebView弹层绘制和焦点。 | 如确认产品缺陷，只补能捕获该缺陷的定向检查；最终仍用canonical App实际观察。 |

推荐“原生同窗取证→按根因最小修正→一次实际收口”。直接重写弹层/主题缺少依据且扩大影响；直接按工具故障忽略则缺乏用户可见性证据。两者均不推荐。

## 2. 执行顺序与完成标准

| 顺序 | 执行内容 | 完成标准 |
|---|---|---|
| 1 | 固定原生入口与零费用条件 | 记录当前源码/构建、实际进程与窗口、隔离候选根及台账；确认验收计划暂停。使用canonical显式候选入口，真实Provider不接通；普通15/5、候选25/6保持。 |
| 2 | 区分渲染问题与捕获问题 | 在同一真实窗口、同一交互时刻对照可见画面、AX、只读样式/状态；比较既有表单/自动确认与单次/重跑确认。形成可复核根因或明确的最小缺失证据，不重复机械Raise/重启。 |
| 3 | 实施有依据的最小修正 | 若产品有缺陷，仅修确认框显示、主题同步、滚动或焦点；若仅观测链异常，修正取证方式并取得真实可见性证据，产品可零改动。不通过关动画、强制样式等猜测补丁制造通过。 |
| 4 | 零真实调用交互回归 | 立即运行、列表重跑、详情重跑的差异/许可可见；无差异和长内容可读；亮暗、1180×760、键盘取消/焦点返回通过，取消不产生grant/run。 |
| 5 | 实际复核、正常清理与报告 | 同一候选fresh启动核对原生画面及既有结果定位；必要时用声明式本机Provider验证确认路径。正常退出重开无补发；恢复原外观、验收计划暂停、验证服务正常退出。关闭UI-4C3-01后才标记4C-3验收收口，报告后停止。 |

### 取证的最小顺序

1. 从canonical launcher确认App已启动，再按完整App路径和窗口选择CUA对象；不让`getApp`在退出后意外启动无环境实例。记录实际构建和窗口，避免把不同副本或旧画面合并成证据。
2. 只打开、审阅和取消确认框，先不提交执行。对照短内容与有历史差异的长内容，记录遮罩、标题、正文、按钮、显示区域及焦点。可用时通过原生检查器只读观察DOM、计算样式和异常；不新增远程调试服务或放宽CSP/capability。
3. 对于弹层，顺序核对show状态、Teleport挂载位置、display/visibility/opacity、过渡是否完成、尺寸和裁剪、遮罩与层级、当前activeElement。对主题，核对系统事件及root data-theme、解析后token、Naive基础theme/overrides与实际Card/Modal样式。只记录必要诊断，不收集用户正文、凭据或完整会话数据。
4. 若工具仍无法呈现真实窗口，在具体窗口与操作已准备好后，请用户简短核对实际可见性及键盘表现；不把旧的“尚无答复”当作继续等待的前置门禁，不预先认定必须人工参与。浏览器/组件渲染可以辅助区分，但不能替代Tauri原生验收。
5. 每次验证必须针对一个可证伪假设。如果没有新事实，整理缺失证据和具体阻塞，不循环重启、不修改无关布局，也不宣称纯工具问题。

### 修改边界

- 优先落在`ScheduledTasksPage.vue`及相关确认/表单样式与焦点处理；只有证据证明共享主题/provider链是根因时，才最小修正`App.vue`或现有主题适配，并回归一个普通聊天/设置页的同类控件。
- 保留Naive/Yj组件、现有设计token、中文语义、默认取消、局部loading和原请求查证。主题切换不刷新路由、不重建执行意图、不丢输入；确认框切换不让两个焦点锁同时争用，不让Enter从后台按钮意外提交。
- 列表和详情两个重跑入口分别记录返回焦点；原触发元素已不存在时，回到本页合理且可见的操作位置。先用实际行为确认是否有缺口，不把源码形状当作已证实缺陷。
- 不改grant、run、outbox、授权/重试/恢复语义，不新增command、schema或依赖；不直接写SQL修正UI，不补造历史时间或Provider phase。发现执行边界必须变更时，先重做契约影响判定，不能以视觉修复名义夹带。

本轮文档`contract-impact=none`：没有跨进程、持久化或重放行为变化。预计修复也限于纯UI，按none处理的前提是上述边界保持；FEAT-155整体及已实施4C-3的breaking分类保留。

## 3. 验收、预算与证据

| 场景 | 必须观察到的结果 |
|---|---|
| 立即运行 | 已开启/暂停/已完成计划的当前状态与一次/最长10分钟许可准确；不改变自动授权语义。 |
| 独立重跑 | 列表及详情入口均可见原/现名称、内容、时间规则和目标；无变化明确说明，新运行和旧历史语义清楚。 |
| 最小窗口与长内容 | 亮暗主题下1180×760外框可用；长差异内部滚动，取消/确认可到达，没有正文覆盖按钮或遮罩下交互。 |
| 键盘 | 默认焦点取消；Tab/Shift+Tab在弹层合理移动，Escape取消后返回可见触发位置；重新打开行为一致。未知/提交中遵循现有查证规则，不允许取消伪装成撤回。 |
| 主题切换 | 底层卡片、弹层、遮罩、正文和焦点同步更新，原review/输入/稳定请求不丢失；完成后恢复原系统外观。 |
| 取消及只读 | 打开/取消/查证不新增grant、run、outbox或扣额；历史/结果定位仍指向既有正确conversation/turn。 |
| 正常恢复 | 正常退出重开，旧单次不补发；已保存计划、旧记录、额度和已知unknown事实保持。 |

**本批真实文本、图片、商家/MCP外部调用均为0。累计保持10/12、剩余2次，不申请也不消耗追加额度。** 实际页面诊断和结果定位复用隔离候选中的既有合成历史；新的测试状态可由组件fixture或临时库提供，不直接篡改现有运行账本。开始原生验证前确保真实Provider没有上游转发路径；不通过修改Runtime/可执行文件来模拟禁止外发。

需要复核实际确认按钮接线时，只使用明确声明的本机HTTP Provider和短合成文本，建议本机最多2次，独立记录为0真实调用；新本机台账不得清空或复用此前付费台账。先确认弹层真正可见再提交，不仅凭AX点不可见的确认按钮。未修改发送相关代码且原证据仍适用时，无需重跑完整模型流程。

检查随实际修改确定：UI改动执行Desktop lint、build及受影响的主题/确认/管理定向测试；新增测试应验证已查明的缺陷，避免只复制实现。共享主题变化增加一个现有页面的实际回归。私有IPC生成漂移可只读检查；纯UI修复不重复整个原生124项。若意外涉及native行为，应扩大相关验证并重新判断范围。标准全量入口的既有Contracts dirty保护不绕过，历史禁止的故障fixture不运行；所有限制单列。

交付一个新的收口报告，保存当前源码与构建来源、实际窗口截图或明确的人工观察记录、键盘/主题/最小窗口结果、无外部调用与正常清理证据。人工观察不能被写成工具已验证的截图，合成fixture不能被写成真实执行证据；保留41的历史失败与未决结论，以新报告明确哪些被后续证据解决。

本方案已按AC-006、AC-009、AC-010相关UI子项反向检查：先分辨产品与观测问题，根因未定前不猜修复；复用已通过执行证据，保留未知、权限和费用边界；无契约/存储扩展。源码复核不等于证明根因已解决，也不是独立人工批准。
