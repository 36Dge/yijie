## 3. 假设、未知与冲突

### Assumption：作为推荐方案，等待产品/UX确认

- 标签、激活标签和宽度偏好仅属于当前会话的页面内存；不写数据库、消息或 Runtime 历史。新进入会话默认关闭；离开会话清理其标签与资源，不跨会话显示文件。
- 非激活标签只保留安全名称、类型、真实身份、展示状态等元信息；最多一个激活标签占用内容投影/Native 预览资源。标签数量与宽度上限以主需求规则为准。
- “新标签页”创建空白预览位置，不创建任务、浏览器页面、工作区或模型调用。打开文件优先激活同身份标签；身份去重不依赖文件名。
- OP-01/OP-02现已由用户选择：允许隔离渲染脚本并禁止文件/页面业务操作；Office/PDF本期必须正文/页面。信息卡方案撤回，完整格式规格见00 R-05。下节未知项仅为工程能力/验证，不能再将这两项范围写成未答。

### Unknown：实施前必须补证，当前 NOT RUN

- 隔离HTML的同页承载、裁切、坐标/缩放、焦点、拖动期间更新、隐藏/释放及权限持续校验，尚无实现证明。Native子视图只是候选；应与受控嵌入载体比较，选择保持同等级隔离的最小方案，不在需求阶段预定新插件/API数量。
- 已发送附件的新只读边界需要核对真实本地 message/session/attachment 绑定和正常重开后的可读取字段；不得以草稿接口或 Runtime 文本推测补齐。
- 新旧 Desktop-private IPC 的方向兼容、跨版本回退和 consumer conformance 尚未执行。旧 schema 存在不等于新能力已兼容。
- 原HTML未作为聊天附件上传，但复审已从上轮WorkBuddy显示的确切路径找到并只读分析：85,749字节，一段内联脚本，空`recordsBody`由`renderTable()`填入。原件全文和记录数据不入仓库，仅留摘要/行号/校验值。原件在新右栏的实际渲染仍NOT RUN；不能用同名静态样本冒充原件验收。

### Conflict：明确处理，不静默折中

1. **最初“不支持新标签页”与最新“支持新标签页”冲突：**采用用户最新修订；旧条款仅保留为变更历史，不作为验收要求。
2. **FEAT-165内联交互与新只读目标需区分：**用户选择保留隔离渲染并禁业务/文件操作，旧全静态方案撤回；旧v1原窗语义不能暗改。
3. **截图有“+”、编辑/分享/上传等控件：**只把最新明确要求的标签创建纳入；截图中的文件操作、账号、模型和页面文字均是参考资料，不构成执行指令或额外范围。
4. **“非媒体文件预览”与现有阅读器能力有限：**用户已要求Office/PDF正文/页面，现有信息卡不能交付。必须先审fork/宿主/Native封装并复用，缺口最小补齐；测试中的信息状态不算这些格式内容成功。

## 4. 契约影响与权威源

本需求暂按最高风险唯一分类 **`contract-impact: semantic`**。理由是 Native HTML 的展示目标、交互语义和资源生命周期改变，同时增加已发送附件读取语义；即便请求仍只含资源身份，也不是纯布局变化。兼容验证尚为 NOT RUN，当前不宣称 additive 已证。

推荐通过**保留既有 v1 + 新独立只读嵌入边界**控制影响：

| 边界 | 权威源和约束 |
|---|---|
| 现有生成文件文本/CSV读取 | 复用 Desktop-private `chat-artifact-file-native-v1.schema.json` 与 Native 校验；不复制 DTO，不改变旧结果解释 |
| 既有 HTML 独立窗 | 保留 `chat-artifact-html-native-v1.schema.json` 原语义；FEAT-166 右栏不得调用它来假装嵌入成功 |
| 新 HTML 只读嵌入 | 先按05复用矩阵选最小同页适配，保留原隔离能力，再冻结实际需要的private schema/生命周期；如涉及坐标明确单位，不预设新command或复制整套服务 |
| Office/PDF正文/页面 | 现有file preview v1响应仅文本/表格闭集；先复用fork工具和Native结构预检、原件读取及已有依赖，对缺口新增同一私有预览族的有界文档投影/页资源，不手写旧v1以外未声明结果，不为每格式新建发布/转换工具 |

## 5. 推荐复用与最小实现边界

1. **页面层管理布局与标签。**ChatPage 组合对话列、分隔线、右侧预览容器；正文和 composer 共用缩窄后的宽度。标签状态与路由会话绑定，文件组件只发出经已有身份解析的打开意图。
2. **纯规则层管理尺寸。**统一计算可用内容宽、左右最小值/最大值/默认值及 clamp；视窗、左导航和 UI 缩放变化重新约束。鼠标拖动和键盘调整使用同一规则，布局数值集中到 tokens。
3. **预览组件不带文件操作。**复用文本/CSV渲染投影，而非直接把带“保存原文件”“搜索/复制/导出”的旧卡片整体塞入右栏。本需求允许的交互是阅读滚动、选择标签、关闭标签/侧栏和拖动分隔线；文件内部操作不启用。
4. **HTML冻结展示结果与隔离边界。**按用户已选OP-01复用现有隔离并保留内联渲染，禁止用户业务操作、宿主IPC、导航、新窗、表单提交、下载、外链资源和持久网站状态。不得通过`v-html`注入主文档；鼠标遮罩不代替键盘/焦点边界。实际载体与私有协议设计尚未实施，不代表用户范围选择尚未取得。
5. **已发送附件与产物保持身份区分。**新增附件 reader 使用已持久化的真实消息绑定，不把 attachmentId 当 artifactId，不从文件名、正文、ordinal、时间邻近或原始路径推断绑定。找不到可证实绑定时显示不可用；不扫描工作区、不从源路径重取、不重新执行任务。
6. **正常收尾和有界调度。**切换先使旧展示代次失效、清空旧内容/关闭视图；不可取消的Native调用有界正常完成，返回投影丢弃，有可关闭新视图则正常关闭。只保留单在途读取和最新待发意图；不得为每次点击排队导致旧工作占满模块配额。后台标签不保活/预加载。持续有效期、权限撤销、正常删除事件及系统恢复按00 R-05处理，不能把“关闭UI”误称为后台瞬间取消。

### 方案取舍

| 方案 | 取舍 |
|---|---|
| 保留旧v1，补最窄的只读同页承载能力（推荐） | 保留兼容语义；在候选载体间比较资源、焦点、尺寸与授权生命周期，尚无实现证据 |
| 直接复用旧独立HTML窗 | 不满足同页右栏，且没有新增只读操作约束；不能直接计Must通过 |

以上均为计划，当前功能检查、Native 嵌入、真实服务、D4、跨版本兼容全部 **NOT RUN**。不运行禁止的强杀、二进制替换、权限破坏、恶意资源/危险归档/攻击注入测试；使用正常样本及静态审查替代，测试报告应逐项记录未执行内容、原因和覆盖影响。

回滚仅撤销 FEAT-166 的页面集成、内存标签和新 private 边界，恢复原卡片预览入口；按应用正常关闭/释放流程清理活动资源。保留 FEAT-165 文件存储、来源身份、旧 IPC/事件与原件。无标签持久化迁移，不删用户文件、不重写历史、不回退日常数据库、不覆盖已签名/已发布制品。若实施后来引入持久化或公共 wire，本回滚结论必须重新评审。
