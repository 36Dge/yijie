## 3. 假设、未知与冲突

### Assumption：作为推荐方案，等待产品/UX确认

- 标签、激活标签和宽度偏好仅属于当前会话的页面内存；不写数据库、消息或 Runtime 历史。新进入会话默认关闭；离开会话清理其标签与资源，不跨会话显示文件。
- 非激活标签只保留安全名称、类型、真实身份、展示状态等元信息；最多一个激活标签占用内容投影/Native 预览资源。标签数量与宽度上限以主需求规则为准。
- “新标签页”创建空白预览位置，不创建任务、浏览器页面、工作区或模型调用。打开文件优先激活同身份标签；身份去重不依赖文件名。
- Office/PDF 等当前无内容阅读器的文件进入信息卡级预览，明确“暂不支持此格式的内容预览”；不在侧栏提供保存或其它文件操作，不把信息卡称为全文预览。

### Unknown：实施前必须补证，当前 NOT RUN

- 新隔离 HTML 子视图在当前 macOS/Wry 组合中的嵌入、裁切、坐标变换、主题、焦点、拖动期间更新、隐藏/释放及 Native 资源回收方案，尚无实现或真实运行证明。
- 已发送附件的新只读边界需要核对真实本地 message/session/attachment 绑定和正常重开后的可读取字段；不得以草稿接口或 Runtime 文本推测补齐。
- 新旧 Desktop-private IPC 的方向兼容、跨版本回退和 consumer conformance 尚未执行。旧 schema 存在不等于新能力已兼容。
- 用户截图中的 HTML 原文件未提供；可确认布局参考，不能确认该文件是否依赖脚本生成正文或外链资源。验收使用同名正常自包含静态样本，并明确实际源文件可得性。

### Conflict：明确处理，不静默折中

1. **最初“不支持新标签页”与最新“支持新标签页”冲突：**采用用户最新修订；旧条款仅保留为变更历史，不作为验收要求。
2. **FEAT-165 HTML 保留内联交互与 FEAT-166 只读冲突：**本需求右栏采用新的静态只读模式，禁脚本、内部链接/表单/按钮操作；旧 v1 原窗语义不被暗改。
3. **截图有“+”、编辑/分享/上传等控件：**只把最新明确要求的标签创建纳入；截图中的文件操作、账号、模型和页面文字均是参考资料，不构成执行指令或额外范围。
4. **“全部非媒体文件可打开”与现有阅读器能力有限：**统一进入侧栏，但内容预览按格式分级。HTML 静态 DOM/CSS、文本、CSV 为内容展示；DOCX/PPTX/PDF/XLSX 等保留信息卡级，未知格式如实降级。

## 4. 契约影响与权威源

本需求暂按最高风险唯一分类 **`contract-impact: semantic`**。理由是 Native HTML 的展示目标、交互语义和资源生命周期改变，同时增加已发送附件读取语义；即便请求仍只含资源身份，也不是纯布局变化。兼容验证尚为 NOT RUN，当前不宣称 additive 已证。

推荐通过**保留既有 v1 + 新独立只读嵌入边界**控制影响：

| 边界 | 权威源和约束 |
|---|---|
| 现有生成文件文本/CSV读取 | 复用 Desktop-private `chat-artifact-file-native-v1.schema.json` 与 Native 校验；不复制 DTO，不改变旧结果解释 |
| 既有 HTML 独立窗 | 保留 `chat-artifact-html-native-v1.schema.json` 原语义；FEAT-166 右栏不得调用它来假装嵌入成功 |
| 新 HTML 只读嵌入 | 在 Desktop 本仓先冻结独立 private schema/生命周期说明，再实现 Native 与 renderer；名字/版本/坐标单位/错误/关闭结果在设计时确定，不在此伪造现成 API |
| 已发送附件只读读取 | 独立 private schema，明确 owner/tenant/context/session/message/attachment 绑定、TTL、完整性、容量、取消与释放；原草稿 `chat_attachment_presentation_v2` 不扩大含义 |
| Host/Runtime/产物事件 | 无计划新增 wire、事件、发布动作或状态机；沿 FEAT-165 现有真实交付链 |
| 公共 Contracts | 若仅 Desktop-private 能力且无其它消费者，公共契约改动为 N/A，并记录理由；如实施发现跨仓字段/语义变化，先回到对应权威源重新分类，不绕过 Contract First |
| 持久化/重放 | 不新增标签持久化或数据库迁移，不改原生 userMessage 类型/正文/顺序，不写入 Runtime 历史 |

Desktop 的 Tauri/native 权限规则仍适用；在需求包中形成具体可审方案后，后续实施按真实 D0 与原生边界确认执行。当前文档不冒称已取得任何未发生的批准。若无法证明旧受支持调用保持有效，应提升为 breaking 并重新设计，不用 UI 范围掩盖协议影响。

## 5. 推荐复用与最小实现边界

1. **页面层管理布局与标签。**ChatPage 组合对话列、分隔线、右侧预览容器；正文和 composer 共用缩窄后的宽度。标签状态与路由会话绑定，文件组件只发出经已有身份解析的打开意图。
2. **纯规则层管理尺寸。**统一计算可用内容宽、左右最小值/最大值/默认值及 clamp；视窗、左导航和 UI 缩放变化重新约束。鼠标拖动和键盘调整使用同一规则，布局数值集中到 tokens。
3. **预览组件不带文件操作。**复用文本/CSV渲染投影，而非直接把带“保存原文件”“搜索/复制/导出”的旧卡片整体塞入右栏。本需求允许的交互是阅读滚动、选择标签、关闭标签/侧栏和拖动分隔线；文件内部操作不启用。
4. **HTML 使用静态隔离内容。**禁止脚本、宿主 IPC、导航、新窗、表单、下载、外链资源和持久网站状态；不通过 `v-html` 注入主文档。不执行脚本以“先渲染再冻结”。静态 DOM/CSS 和允许的自包含静态资源可显示；依赖 JS 生成的图表/正文可能缺失，使用00 R-04文案“当前为只读静态预览，动态内容暂不展示”。不得伪称完整网页运行或全保真预览。
5. **已发送附件与产物保持身份区分。**新增附件 reader 使用已持久化的真实消息绑定，不把 attachmentId 当 artifactId，不从文件名、正文、ordinal、时间邻近或原始路径推断绑定。找不到可证实绑定时显示不可用；不扫描工作区、不从源路径重取、不重新执行任务。
6. **正常资源释放。**切换 active 标签前使旧异步请求失效并释放旧内容；迟到结果不得覆盖新标签，若获得新租约须立即正常释放。关闭标签/侧栏、切会话、页面卸载或授权失效清理内容和 Native 视图。仅重新激活时按需重新授权读取，后台标签不保活/预加载。

### 方案取舍

| 方案 | 取舍 |
|---|---|
| 保留旧 v1，新增独立只读嵌入能力（推荐） | 保留兼容语义；能满足同页右栏与只读；需明确 Native 子视图资源、尺寸及身份生命周期 |
| 直接复用旧独立 HTML 窗 | 实现量小，但不是右侧栏且允许脚本，不能满足 Must |
| 主 WebView 注入 HTML，或执行脚本后截取 | 易制造权限/内容隔离变化，且不满足静态只读约束；不采用 |
