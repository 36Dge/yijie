## 2. 范围与推荐默认

**In scope**：共用 Composer 模型入口；两个模型目录与就绪状态；普通文本、多轮、既有附件路径、原生工具/审批/Artifact 的模型适配；每会话选择与每次提交快照；历史恢复；定时草案对话与共用执行链的模型一致性；正常错误恢复；local canonical 启动装配。

**Out of scope**：模型市场、自定义模型/URL、用户密钥管理界面、推理档位选择器、语音/视频新通道、自动模型路由/降级、模型质量排名、云同步、公网/生产上线、修改 Coze 工作流节点的模型、替换图片生成专用供应商。工具产生图片与聊天模型理解图片是不同能力。既有工具、权限与审批规则继续适用，不因换模型开放新工具或网络权限。

“所有对话”的本期口径为通过易界 Chat 与相同 Host/Codex 执行链的普通新聊、普通续聊、计划草案聊天，以及计划触发的聊天执行。内部标题生成等辅助模型请求列为受影响回归项，不增加用户级单独配置；其模型路由必须明确，不能意外回落到未配置供应商。独立 Coze 工作流 LLM 节点和专用图像工具不属于本入口控制范围。

| R04 时机与并发 | 只在会话空闲、权限可用、无 queued/submitting/uncertain/streaming/stopping/待审批及未释放预约时切换；原生再次原子校验，不能只靠按钮置灰。执行中保留当前模型标签并禁用，提示“当前任务结束后可切换”；停止按钮继续可用。不隐式停止/强杀、不新增 steer 或运行中消息队列。跨会话的选择不能污染另一 target；过期回执不覆盖新 target。 |
| R05 发送与幂等 | 按发送/Enter时冻结 model、provider、effort、配置版本与目标，随同 operationId/contentBlocks 写入同一次 durable submission/outbox。相同原请求重试沿用原快照和 ID；同文改模型是新的显式意图，不复用旧请求身份。未知结果只查原请求，禁止自动改供应商、重新创建 ID 或重复付费提交。已接收记录不跟随以后下拉选择变化。 |

| R08 异常与恢复 | 缺凭据、能力不支持、版本不兼容、鉴权/余额/限流/网络/超时等均给安全文案和恢复出口。Kimi 不可用仍保留默认意图并标记不可用，用户可显式选 MiniMax；无静默 fallback。调用已受理但结果未知时先恢复原请求事实；失败后的重新提问是新请求并明确可能再次计费。正常取消/停止沿原生协议，不伪造完成。 |
| R09 计划草案与自动执行 | 计划草案使用相同模型入口，保持 input-only、结构化校验、无工具与审阅后仅保存暂停。草案选用的模型不暗授未来执行权限。新计划执行配置须保存可审阅模型快照，默认 Kimi/max；三类目标在启用/单次/重跑确认里显示有效模型。已有计划/有效授权/已受理 run 保留原模型事实；来源不明须重新确认。已有聊天目标若当前模型与计划快照不一致，阻止该次投递并提示重新审阅，不能后台切换前台会话。变更计划模型快照后旧 grant 不可复用；当次 run 永久冻结模型，不改变旧历史。冲突恢复时，已有聊天或已绑定专属聊天采用该聊天当前已确认模型生成新候选，明确审阅后更新计划配置并重新授予；用户也可先把聊天显式切回原计划模型再重验原授权。每次新建/尚未绑定专属聊天在计划保存时独立初始化Kimi/max并冻结，草案生成所用模型不自动变成执行模型；授权前展示该快照。只补已有确认/快照链，不另造计划模型设置中心。 |
| R10 权限和数据 | 模型选择不改变 owner/tenant/scope、Ask/Auto/Full 或原生工具审批。服务端/原生对模型与 scope 再校验；不接受前端提供 URL 或凭据。只读历史/无权会话不可切换和发送。选择与实际执行模型分开记录，记录限模型标识、配置版本、操作状态与安全错误，不记录密钥或完整业务内容。 |

## 3. 主流程与交互

1. 未来实施后通过既有 canonical 日常入口免登录直达 `/chat`；native scope 与 Host 内部凭据继续受管。
2. 新任务输入框尾部显示 `Kimi K3 ▾`。菜单仅列 Kimi K3、MiniMax M3，勾选当前项；Kimi 行注明“推理强度：max”。没有额外设置页。
3. 用户输入文本/添加既有附件，可在发送前选择另一模型；选择成功保留正文、附件、权限模式与项目。新会话首次发送才创建实际任务。
4. 发送时原生校验目录版本、模型就绪、权限和 target，冻结快照。仅 durable acceptance 后按既有语义清空匹配草稿；随后显示实际执行事实。
5. 完成本轮后用户可在同一会话切换模型再继续；正常退出/重开恢复该会话选择和旧历史，不触发付费恢复请求。
6. 不可用或失败时保留正确选择/请求事实，说明可修复项；重试同请求或显式改选新请求，不把未知执行当从未执行。

## 5. 治理边界与停止条件

本轮纯文档变更 `contract-impact=none`；**未来功能按最高风险 `breaking` 规划**：旧 Desktop decoder 只认 MiniMax、现有 IPC 严格拒绝未知字段，模型默认/持久出站及恢复语义改变。不能仅称“新增一个选项所以 additive”。实现前应形成版本化扩展与方向兼容证据；未形成前不得激活新值。
