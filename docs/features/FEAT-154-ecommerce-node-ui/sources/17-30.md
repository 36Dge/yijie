# 跨境电商工作流节点定义：节点 17–30

本文仅保留每个节点的目的与边界、输入、处理逻辑、平台分支、输出、业务结果与错误码。

## 节点 17：商品图片生成

### 17.1 目的与边界

基于真实商品素材、商品事实和已核准卖点，生成白底图、场景图、功能图、尺寸图和卖点信息图候选。节点必须保证视觉内容与指定商品和 SKU 一致，不得臆造外形、颜色、结构、数量、配件、使用效果、认证标志或真人背书；不得把虚构商品图伪装成实拍主图；不负责图片技术适配、平台上传或商品发布。

### 17.2 输入

| 变量名 | 类型 | 必选 | 说明 |
| --- | --- | ---: | --- |
| `product_snapshot` | `object` | 是 | 已确认的商品外观、材质、尺寸、颜色、包装清单、功能、限制和变体事实 |
| `source_assets` | `list<image>` | 是 | 商品实拍图、包装图、细节图和 Logo；需标记 SKU、视角和来源 |
| `asset_rights` | `object` | 是 | 素材所有者、授权用途、平台、市场、期限和人物肖像授权 |
| `target` | `object` | 是 | Amazon 或 TikTok Shop、站点、语言、类目和素材位置 |
| `image_brief` | `object` | 是 | 图片类型、数量、比例、风格、信息层级和禁止内容 |
| `approved_claims` | `list<object>` | 是 | 有事实或证据支持、允许视觉化的卖点和声明 |
| `brand_assets` | `object` | 否 | 品牌色、字体、Logo、视觉规范及使用授权 |
| `variant_scope` | `list<string>` | 是 | 本次图片对应的 SKU、颜色和尺寸 |
| `generation_config` | `object` | 是 | 候选数、模型、随机种子、审核门槛、超时和部分成功策略 |

### 17.3 处理逻辑

#### 步骤 1：锁定商品、SKU 和素材用途

1. 锁定商品事实版本、目标 SKU 和平台位置，区分主图、附图、详情图与推广素材。
2. 多变体共用图片只能表现共有事实；颜色、尺寸和包装数量必须分别生成。
3. 商品事实或目标位置变化后，旧候选只能作为历史草稿，不能继续进入发布审核。

#### 步骤 2：执行素材权利门禁

- 仅使用自有、已许可或供应商明确授权的素材；“可下载”不等于可生成衍生作品。
- 识别第三方 Logo、人物、艺术作品、背景和竞品素材；缺少商业使用或衍生授权时阻断。
- 真人形象需核对肖像授权、市场和期限；不得根据名人、达人或普通人照片生成虚假代言。
- 不以去水印、换脸或重绘规避授权问题。

#### 步骤 3：建立不可改变的视觉事实

从商品快照和实拍图提取轮廓、部件数量、接口、颜色、纹理、材质、包装内容、Logo 位置、尺寸比例及禁止场景。缺少背面、内部结构或使用状态的可靠素材时输出补拍需求，不生成猜测视图。

#### 步骤 4：建立图片组蓝图

按“识别商品、理解差异、建立尺度、展示使用、降低疑虑、形成购买理由”分配图片任务，避免重复换背景。尺寸图必须读取真实数值和单位，不得依据透视自行估算。

#### 步骤 5：按位置选择生成方式

- 主图只允许以真实商品实拍为主体做受控抠图、背景清理、曝光和构图，不重新生成商品本体。
- 场景图可生成环境，但商品主体优先来自真实抠图，环境不得改变商品尺度、用途或配件。
- 功能图用实拍细节、标注和已验证说明表达；无证据时不生成性能效果。
- 信息图先锁定文案和数值，再排版；不得让图像模型自行生成文字、尺寸或认证图标。

#### 步骤 6：候选一致性和合规检查

逐图检查 SKU、颜色、形状、部件、Logo、商品数量、包装内容、尺度、使用方式、文字、数字和单位。拦截虚构赠品、认证徽章、平台徽章、竞品品牌和不现实效果。健康、安全、环保、认证、比较、测试及前后对比声明必须绑定证据；动态价格、销量、星级和平台徽章默认不写入。

#### 步骤 7：异步任务与人工审核

每张目标图片作为独立子任务，状态区分 `queued`、`generating`、`validating`、`succeeded`、`review_required`、`failed` 和 `expired`。仅对超时、限流等瞬时错误重试；事实冲突、权利不明和平台位置不允许不得自动重试。部分成功时保留有效图片并返回失败位置。主图、人物、强功效声明和低置信度事实必须人工审核。

### 17.5 输出

| 变量名 | 类型 | 说明 |
| --- | --- | --- |
| `image_set` | `list<image>` | 按用途和 SKU 分组的有效图片候选 |
| `candidate_groups` | `list<object>` | 各位置的备选图、排序和推荐原因 |
| `asset_manifest` | `object` | 图片对应商品、SKU、用途、来源素材和生成方式 |
| `fact_consistency_report` | `object` | 外观、数量、颜色、尺寸、文字和声明检查结果 |
| `rights_report` | `object` | 输入素材、人物、品牌和生成内容的权利状态 |
| `disclosure_advice` | `object` | AI 标记、披露要求和禁止发布位置 |
| `review_tasks` | `list<object>` | 待确认的事实、权利、主图和高风险声明 |
| `missing_capture_requests` | `list<object>` | 因缺少真实视角或细节产生的补拍需求 |
| `task_summary` | `object` | 整体及逐图异步状态、失败原因和重试建议 |

### 17.6 业务结果与错误码

| 代码 | 分类 | 默认处理 |
| --- | --- | --- |
| `IMAGE_GEN_SUCCESS` | 业务结果 | 返回完整图片组和审核报告 |
| `IMAGE_GEN_PARTIAL_SUCCESS` | 业务结果 | 返回有效图片，并列出失败位置 |
| `IMAGE_GEN_REVIEW_REQUIRED` | 复核 | 保留候选，禁止直接进入发布 |
| `IMAGE_GEN_MISSING_VIEW` | 复核 | 输出补拍清单，不生成猜测视图 |
| `IMAGE_GEN_FACT_CONFLICT` | 阻断 | 等待商品事实确认 |
| `IMAGE_GEN_RIGHTS_UNVERIFIED` | 阻断 | 不使用权利不明素材 |
| `IMAGE_GEN_PLATFORM_SLOT_FORBIDDEN` | 阻断 | 生成方式不适用于目标位置 |
| `IMAGE_GEN_PRODUCT_DRIFT` | 阻断 | 候选改变商品外观、数量或功能 |
| `IMAGE_GEN_NO_VALID_CANDIDATE` | 业务结果 | 返回失败原因，不强行选图 |
| `IMAGE_GEN_TIMEOUT` | 可重试 | 复用原任务标识重试未完成项 |
| `IMAGE_GEN_PROVIDER_ERROR` | 可重试 | 对瞬时服务错误有限重试 |

## 节点 18：商品图片处理与平台适配

### 18.1 目的与边界

将已有商品图片加工为目标平台、站点和素材位置可用的衍生图片，包括抠图、白底化、主体居中、裁剪、清晰度改善、瑕疵清理、压缩、格式转换和比例适配。节点只能改善展示和技术兼容性，不得重建缺失细节、修改实际颜色、改变包装内容或增加功能；图片文案翻译由节点 19 负责。

### 18.2 输入

| 变量名 | 类型 | 必选 | 说明 |
| --- | --- | ---: | --- |
| `source_images` | `list<image>` | 是 | 原始图片、不可变版本、来源和权利状态 |
| `product_snapshot` | `object` | 是 | 用于核对商品、SKU、颜色、尺寸和包装内容 |
| `target` | `object` | 是 | 平台、站点、类目、图片位置和目标比例 |
| `slot_plan` | `list<object>` | 是 | 图片拟用于主图、附图、变体图、尺寸图、描述图或封面图 |
| `variant_mapping` | `object` | 是 | 输入图与目标 SKU/变体的映射 |
| `edit_scope` | `object` | 是 | 允许动作及禁止改变区域 |
| `quality_thresholds` | `object` | 是 | 清晰度、压缩、主体占比、背景和安全区要求 |
| `upload_mode` | `string` | 否 | 仅输出资产，或同时上传平台素材服务 |
| `processing_config` | `object` | 是 | 批量大小、超时、重试和部分成功策略 |

### 18.3 处理逻辑

#### 步骤 1：输入体检和角色识别

检查解码、色彩空间、透明通道、方向、分辨率和压缩损伤；识别商品、包装、道具、人物、文字、水印和边框；判断图片适合整体、细节、场景、变体还是尺寸说明，并使用商品事实识别错 SKU、错颜色和缺失配件。

#### 步骤 2：去重和图片组选择

识别完全重复、近重复和同角度图片，保留清晰、完整、颜色准确的版本；建立前、后、侧面、细节、场景和尺寸覆盖矩阵。缺少关键视角时输出缺图结果，不用重复裁剪冒充不同视角。

#### 步骤 3：受控抠图和背景处理

- 分别处理商品、阴影、透明部件、毛发和细小配件。
- 白底化保留必要接触阴影，但背景颜色满足目标规则。
- 背景替换不得侵蚀边缘、删除部件或误处理透明、反光区域。
- 包装、人物和道具是否保留由目标位置决定；所有处理均生成新版本并保留原图。

#### 步骤 4：构图、裁剪和清晰度改善

根据主体计算居中、占比和安全边距，优先扩展背景而不是裁掉商品；多件套按整套内容计算主体。不得拉伸图片。可做降噪、锐化、曝光和有限超分辨率，但不得生成不存在的纹理、刻度、文字或接口。严重模糊或尺寸过小应标记重拍。

#### 步骤 5：瑕疵、权利和真实性门禁

仅清理背景灰尘、噪点、支架和非商品区域污点；保留商品固有接缝、纹理、色差和真实标签。发现未授权水印、第三方 Logo、错误认证标志或敏感内容时阻断；去水印不能用于规避授权。

#### 步骤 6：平台预检、编码与上传回读

逐图校验格式、大小、宽高、比例、主体完整度、背景、文字、水印、边框、重复角度和目标位置限制。使用不明显破坏细节的压缩参数。选择平台上传时保存素材 ID/URL、宽高和用途，并回读检查平台是否自动裁剪、转码或改比例。上传成功不等于图片已审核或在 Listing 生效。

#### 步骤 7：批量异步和失败隔离

逐图区分 `processing`、`platform_uploading`、`succeeded`、`review_required` 和 `failed`。单张损坏不终止其余任务；仅对下载、转码、限流和平台临时错误重试，裁剪失败和商品不一致需人工处理。

### 18.4 平台分支

**Amazon：** 主图执行纯白背景、真实商品、主体完整、无无关文字/水印/边框和合理主体占比检查；附图可表达场景、细节和尺寸但仍须准确。当前公开技术范围为最长边 500–10,000 像素，支持 JPEG、TIFF、PNG 或非动画 GIF；类目特殊规则覆盖通用参数。[Amazon 官方商品图片指南](https://sell.amazon.com/blog/product-photos)

**TikTok Shop：** 图片按主图、变体图、描述图、认证图或尺寸图标记。开放接口使用的商品图片须先上传 TikTok Shop 并保存返回 ID/URL；主图技术尺寸为 300×300 至 4,000×4,000 像素，比例超出指定范围时平台可能自动转为方图，因此须回读检查。[TikTok Shop Upload Product Image](https://partner.tiktokshop.com/docv2/page/upload-product-image) 商品图库最多九张，当前接口建议至少五张且第一张白底，图片顺序即展示顺序。[TikTok Shop Edit Product](https://partner.tiktokshop.com/docv2/page/edit-product-202309)

### 18.5 输出

| 变量名 | 类型 | 说明 |
| --- | --- | --- |
| `adapted_images` | `list<image>` | 按平台位置和 SKU 输出的处理后图片 |
| `slot_assignments` | `list<object>` | 推荐顺序、用途和不适用原因 |
| `processing_report` | `object` | 每张图片的处理动作和前后质量变化 |
| `platform_validation` | `object` | 技术、内容和类目规则检查结果 |
| `platform_media_receipts` | `list<object>` | 条件输出；上传后的素材 ID/URL 和回读信息 |
| `missing_asset_requests` | `list<object>` | 缺少视角、细节、尺寸或合格主图的补拍需求 |
| `review_tasks` | `list<object>` | 裁剪、颜色、透明部件、权利或商品不一致问题 |
| `task_summary` | `object` | 批量及逐图状态、失败和重试信息 |

### 18.6 业务结果与错误码

| 代码 | 分类 | 默认处理 |
| --- | --- | --- |
| `IMAGE_ADAPT_SUCCESS` | 业务结果 | 返回全部目标位置图片 |
| `IMAGE_ADAPT_NO_CHANGE` | 业务结果 | 原图已满足要求，返回原图引用 |
| `IMAGE_ADAPT_PARTIAL_SUCCESS` | 业务结果 | 返回有效图片和未完成位置 |
| `IMAGE_ADAPT_MISSING_REQUIRED_VIEW` | 复核 | 输出补拍需求 |
| `IMAGE_ADAPT_VARIANT_MISMATCH` | 阻断 | 图片与目标 SKU 不一致 |
| `IMAGE_ADAPT_RIGHTS_UNVERIFIED` | 阻断 | 不处理或上传权利不明素材 |
| `IMAGE_ADAPT_SUBJECT_DAMAGED` | 阻断 | 抠图、清理或裁剪损坏主体 |
| `IMAGE_ADAPT_QUALITY_INSUFFICIENT` | 复核 | 禁止用超分辨率伪造细节 |
| `IMAGE_ADAPT_PLATFORM_RULE_FAILED` | 阻断 | 返回位置和失败规则 |
| `IMAGE_ADAPT_UPLOAD_PARTIAL` | 业务结果 | 返回成功素材句柄及失败列表 |
| `IMAGE_ADAPT_UPLOAD_TIMEOUT` | 可重试 | 仅重试未完成项 |
| `IMAGE_ADAPT_INPUT_INVALID` | 致命 | 文件损坏或输入不可识别 |

## 节点 19：图片文案翻译与重绘

### 19.1 目的与边界

识别图片中的营销文案、尺寸说明和操作步骤，在事实与版式约束下完成目标语言翻译、单位本地化、原文字清理和重新排版。节点不更改商品实物包装上的真实标签，也不通过重绘伪装目标市场版本；法规标签、认证编号、型号、商标和实际包装文字默认保留原貌，只有确认实际交付包装同步变更时才允许制作一致的新包装图。

### 19.2 输入

| 变量名 | 类型 | 必选 | 说明 |
| --- | --- | ---: | --- |
| `source_images` | `list<image>` | 是 | 待翻译图片及来源、SKU、用途和权利信息 |
| `source_locale` | `string` | 是 | 原文语言和地区 |
| `target` | `object` | 是 | 平台、站点、目标语言、类目和图片位置 |
| `product_snapshot` | `object` | 是 | 商品名称、参数、尺寸、单位、包装和限制条件 |
| `approved_claims` | `list<object>` | 是 | 允许翻译或改写的声明及证据 |
| `terminology` | `object` | 否 | 品牌词、行业词、禁译词、固定译法和禁用表达 |
| `layout_assets` | `object` | 否 | 可商用字体、图标、Logo、品牌色和原始设计文件 |
| `localization_config` | `object` | 是 | 单位转换、语气、双语策略、置信度阈值和审核策略 |

### 19.3 处理逻辑

#### 步骤 1：先判断目标位置是否允许文字

主图或其他禁止文字的位置直接生成去文案任务，不把译文重新绘制。目标市场禁止商品图库附加文字时，结果只能用于描述图、广告或站外内容。

#### 步骤 2：识别文字区域和角色

检测文字框、阅读顺序、旋转、字号、颜色和背景，区分营销标题、功能说明、尺寸、步骤、商标、型号、认证和真实包装文字。对低分辨率、遮挡、艺术字体及手写内容输出 OCR 置信度；同一数值识别冲突时不自动选择。

#### 步骤 3：建立源文案与事实对照

逐项核对商品名、数量、材质、尺寸、兼容型号和功效。源图含错误或过期信息时先标记冲突，不能因“原图已有”就翻译无证据声明。实际包装文字与后加营销文字必须分层，不能把中文实物标签重绘成英文来暗示交付包装已本地化。

#### 步骤 4：翻译和本地化

- 优先表达目标市场消费者可理解的含义，不逐字硬译。
- 品牌、型号和专有词按术语表处理。
- 单位转换保留原值、换算和舍入精度，尺寸三边顺序保持一致。
- 操作步骤保留顺序、条件和警示，不为排版删除安全限定词。
- 健康、安全、法律和认证文字采用受控翻译并强制人工复核。

#### 步骤 5：版面适配、清除和重绘

根据目标文本长度、阅读方向和重要性决定换行、缩写、字号和区域扩展；RTL 语言同步调整箭头、步骤和对齐。只使用有商业授权且支持目标字形的字体。清除原营销文字时保留商品边缘、纹理、刻度和真实包装文字；标注线必须仍指向正确部位。无法安全清除时输出可编辑设计任务，不强制生成位图。

#### 步骤 6：回读和人工审核

对成品再次 OCR，检查漏字、乱码、源语言残留、数字、单位、型号、数量、警示、溢出、对比度、遮挡和标注关系，并确认商品外观未被修改。低 OCR 置信度、法规标签、功效声明、单位换算、RTL 语言或主体受损必须人工审核。批量任务允许部分成功，各语言版本分别执行站点规则和回读检查。

## 节点 20：商品视频脚本生成

### 20.1 目的与边界

### 20.3 处理逻辑

#### 步骤 1：锁定视频位置和转化任务

区分 Amazon 商品详情页视频、TikTok Shop 商品 Listing 视频和 TikTok 可购物短视频。Amazon 详情页优先解释功能、操作和疑虑；TikTok Listing 视频快速呈现商品及用途；TikTok 信息流短视频需尽早建立情境、人物和观看理由，不能仅改画幅复用同一脚本。

#### 步骤 2：建立可说、可演示和不可说清单

- 可说：有商品事实或证据支持的功能和参数。
- 可演示：能用真实商品和现有条件复现的动作。
- 需限定：结果会因环境、用户或使用方式变化的声明。
- 不可说：无证据功效、虚假认证、确定性结果、伪造评价、竞品贬损和虚假稀缺。

没有可演示证据时，不能用生成画面代替证明。

#### 步骤 3：选择内容结构

根据目标选择商品概览、使用演示、开箱、安装教程、FAQ、场景种草或品牌故事。每种结构必须覆盖真实商品、用户问题、证据、限制和 CTA，不能固定套用同一“痛点—产品—购买”模板。

#### 步骤 4：构建时间轴和镜头证据

按目标时长分配钩子、演示、卖点、证据、限制和 CTA；每条口播绑定事实或画面；逐镜头写明 SKU、景别、动作、道具、人物和时长。不可拍摄镜头应改写或输出补拍需求。安装、安全和操作内容不得为缩短时长删除关键条件。

#### 步骤 5：生成钩子并校验三层信息

钩子可以来自痛点、意外用法、问题或直接演示，但不得制造恐惧、使用无法证明的绝对词、伪造倒计时或平台背书。钩子承诺必须在后续真实解释。画面负责证明、口播负责解释、字幕负责静音理解；三者在数字、步骤和功效上不得矛盾，重要限定词不能只放在一闪而过的小字中。

#### 步骤 6：可行性、权利和平台门禁

逐镜头核对商品、视角、人物、场地和道具。涉及儿童、宠物、专业人士、危险动作或特殊环境时增加安全和授权审核。检查音乐、图片、视频、人物、商标和参考内容的商业使用权；识别健康、安全、功效、比较、前后对比和用户见证风险。动态价格和促销仅在有效期覆盖计划发布时间时进入脚本，并要求发布前复核。

#### 步骤 7：候选比较和人工审核

生成结构明显不同的候选，按事实完整性、前段信息效率、可拍摄性、平台匹配、重复度和风险排序。硬门禁失败的脚本不参与推荐；高风险声明、人物背书和不完整素材进入人工审核。

### 20.4 平台分支

**Amazon：** 优先生成 Product overview、How-to、Setup、Troubleshooting、Unboxing 或 Brand story 等详情页意图脚本。官方当前允许 `.mov` 或 `.mp4`，长度 1–12 分钟、最高 1080p、最大 5GB；实践建议多数商品视频控制在 30–90 秒，并在前 5–10 秒突出重要特征，最终时长仍由视频类型决定。[Amazon 官方商品视频指南](https://sell.amazon.com/blog/amazon-product-video)

## 节点 21：商品短视频生成

### 21.1 目的与边界

### 21.2 输入

| 变量名 | 类型 | 必选 | 说明 |
| --- | --- | ---: | --- |

| `source_media` | `list<object>` | 是 | 实拍视频、图片、Logo、动画和背景素材及授权 |
| `target` | `object` | 是 | 平台、站点、视频位置、语言和目标规格 |
| `voice_assets` | `list<audio>` | 否 | 已授权口播、配音或声音风格 |

### 21.3 处理逻辑

#### 步骤 1：冻结制作版本和镜头映射

锁定脚本、商品事实、SKU、素材、授权和目标规则版本。为每个分镜查找真实商品素材，同一商品不同颜色或套装不得混剪成一个 SKU。优先使用实拍，AI 仅用于不改变事实的转场、背景、简单动画和增强；缺少真实演示时输出补拍需求。

#### 步骤 2：生成或组装镜头

- 对实拍进行裁剪、稳定、调色、降噪和节奏调整。
- 对图片可做有限推拉或标注动画，但不得伪装为真实功能演示。
- 生成场景时锁定商品主体，检查每帧颜色、部件、Logo 和比例连续性。
- 不生成虚构专家、名人、达人或顾客证言。
- 安装、承重、防水等效果必须来自真实素材或明确说明动画，不能用生成结果冒充测试。

#### 步骤 3：时间轴和事实连续性

对齐钩子、口播、演示、字幕和 CTA；删除重复镜头但保留看清商品和步骤的时间。逐镜头检查是否始终为同一商品/SKU，颜色、数量、尺寸和配件是否变化，口播和字幕是否有对应证据，是否出现脚本外功效、价格或促销，以及生成补帧是否导致结构漂移。单帧异常只重做相应镜头。

#### 步骤 4：音频、音乐和人物权利门禁

核对音乐的商业使用、平台、地区、媒介和期限；核对配音演员授权及声音克隆许可，一般录音授权不能自动视为可复制声音。不得模仿名人、专家、达人或用户制造背书。人物肖像、场景艺术作品和第三方商标也须有授权。权利不明时可输出无音乐或无人物替代版，但不能输出可发布候选。

#### 步骤 5：字幕、图形和披露检查

文字不得遮挡商品、操作部位或平台交互区域；标题、价格、折扣和声明与当前事实一致；字号、对比度和停留时间适合移动端。输出有字幕和无字幕母版供节点 22 使用。平台 Logo、奖章和认证图形不得由模型自行生成。AI 生成或显著修改的视频必须保留披露建议。

#### 步骤 6：异步渲染控制

每个比例、语言和创意候选作为独立子任务，状态区分 `queued`、`rendering`、`validating`、`succeeded`、`partially_succeeded`、`failed`、`cancelled` 和 `expired`。仅对下载失败、限流和瞬时渲染错误重试；权利、事实或平台规则失败不得自动重试。重试仅处理失败镜头或版本；超时后先查询原任务，避免重复生成和计费。

#### 步骤 7：技术和内容终检

检查解码、时长、比例、分辨率、帧率、码率、音画同步、文件大小、黑帧、长静帧、循环、闪烁和破损帧；重新执行商品识别、字幕 OCR 和音频转写，核对商品、声明、权利和 AIGC 披露。只有硬门禁通过的成片进入推荐。

### 21.4 平台分支

**Amazon：** 输出适合 Product overview、How-to、Unboxing、Setup 等详情页意图的视频版本，保持商品展示直接、清晰和真实。当前官方规格为 `.mov` 或 `.mp4`、1–12 分钟、最高 1080p、最大 5GB；封面需准确代表商品和视频内容。上传、审核通过和详情页展示是不同状态，本节点不宣称平台已批准。[Amazon 官方商品视频指南](https://sell.amazon.com/blog/amazon-product-video)

| `terminology` | `object` | 否 | 品牌词、型号、禁译词、固定译法和目标市场术语 |
| `voice_profile` | `object` | 否 | 声音、语气及其授权范围 |
| `music_and_audio_rights` | `object` | 是 | 原音乐、音效和声音的跨市场使用权 |
| `localization_config` | `object` | 是 | 字幕样式、语速、单位、口型同步和审核门槛 |

### 22.3 处理逻辑

#### 步骤 1：音轨分析和原文重建

分离人声、音乐和音效，执行带时间戳的 ASR 和说话人识别，并与原脚本对齐。商品名、型号、数值和专有词使用商品事实纠错，不能只依赖通用模型。噪声、多人重叠和低置信度片段进入人工确认。

#### 步骤 2：声明和画面对齐

将每句口播、屏幕文字和商品动作绑定。原视频含错误口播、字幕或过期促销时先阻断，不能通过翻译扩散错误。确认目标 SKU、颜色、数量和商品链接一致，并在本地化前重新校验动态价格、折扣、日期和库存有效期。

#### 步骤 3：翻译和市场化改写

- 保留事实、限定词、警示和操作顺序。
- 品牌、型号、材料和兼容对象按术语表处理。
- 单位本地化需保留原值、换算和舍入方式。
- 文化化表达只能改变语气和例子，不改变用途或适用人群。
- 双关、俚语和 CTA 可重写，但新表达仍需通过平台规则。

#### 步骤 4：字幕分段和版面处理

按语义断句，避免拆开数值与单位、否定词与动词；按实际可读时间控制每屏字数和行数。字幕避开商品核心区域、原视频文字和平台交互区域。竖版、方版和横版分别计算安全区，重要警示和限定词需有足够停留时间。

#### 步骤 5：配音方式和声音权利决策

可选原声、普通授权 TTS、授权配音演员或明确许可的声音克隆。必须确认声音所有者授权合成、克隆、商业使用和目标市场，并检查是否会被误认为名人、专家、达人或实际用户。无声音授权时输出字幕版，不寻找“相似声音”规避授权。

#### 步骤 6：时长、口型和混音

先通过措辞匹配镜头，再有限调整语速和停顿；仍不匹配时延长 B-roll、调整镜头或输出剪辑建议，不删除警示和限定词。口型同步属于可选高风险变换，需检查面部身份和 AIGC 披露。混音检查人声清晰度、音乐音量、峰值、爆音、噪声、声道及音画同步，并保留重要环境声和操作反馈。

#### 步骤 7：反向校验和异步多语言控制

对成片重新执行 ASR 和字幕 OCR，核对商品名、型号、数字、单位、否定词、漏译、残留源语言、配音字幕一致性、画面冲突和新增声明。每个语言与平台版本独立经历 `transcribing`、`translating`、`synthesizing`、`rendering`、`validating`、`succeeded`、`review_required` 或 `failed`。失败语言不影响其他语言；重试复用已确认转写和译稿，避免版本漂移。

### 22.4 平台分支

## 节点 23：商品合规判断

### 23.1 目的与边界

在选品、采购或上架前，根据商品事实、销售市场、店铺资格与平台最新规则，判断商品属于明确禁售、限制销售、需要资格或认证、存在运输限制、证据不足，还是暂未发现确定性阻断项。

本节点只做“平台准入与合规风险判断”：不判断知识产权风险，不审核 Listing 文案和素材，也不创建草稿或提交商品。其最高正向结论只能是“当前证据与规则快照下可继续准备上架”，不能保证平台最终审核通过，也不能替代目标国家法律意见。规则存在解释空间、平台规则与法律要求冲突、官方规则未覆盖或文件真实性无法机器确认时，必须转人工或法律复核。

### 23.3 处理逻辑

#### 步骤 1：锁定商品、市场与类目

建立“商品—变体—平台—市场—店铺—履约方式”唯一判断范围。不同国家、Amazon marketplace、TikTok Shop 店铺或履约方式不得复用同一个结论。类目不确定时并行评估候选类目；候选类目产生不同资格或认证要求时返回“类目待确认”，不得选择限制最少的类目。

#### 步骤 2：建立事实与证据门槛

根据儿童使用、入口、皮肤接触、医疗用途、食品、化妆品、电器、电池、无线功能、液体、气雾剂、危险品、植物、二手或成人用品等特征，动态生成必需事实。每项条件评估为 `已证实`、`已否定`、`未知` 或 `证据冲突`；未知不能按“否”处理。

#### 步骤 3：执行确定性禁售检查

将商品事实与目标市场的官方禁售清单、明确禁止类目及条件规则匹配。只有规则范围、商品事实和目标市场均明确命中时才输出 `PROHIBITED`；关键词或图片相似只能形成风险线索，必须补证或转人工。

#### 步骤 4：识别限制销售与资格路径

将禁售与“满足条件后可销售”分开，生成类目级资格、单商品资格、邀请制资格、品牌资格、店铺经营范围和平台审批要求。TikTok Shop 的受限商品可能要求类目级、商品级或邀请制资格，且平台可在上架后再次要求文件；必须按目标市场读取对应政策，不能把美国站规则直接复制到其他站点。[TikTok Shop Restricted Products Policy](https://seller-us.tiktok.com/university/essay?default_language=en&identity=1&knowledge_id=3238037484275457)

#### 步骤 5：生成合规要求图并核验证据

按条件依赖生成商品信息、认证或检测、标签警示、责任主体和危险品运输要求。例如只有“含电池”为真后才检查电池类型、数量、容量、SDS 和危险品字段。对文件核验商品型号、变体、市场、发证主体、标准、签发与失效日期及覆盖范围；文件真伪或法律效力无法自动确认时返回人工复核，不能因“上传了文件”就判定合规。

#### 步骤 6：执行店铺级实时资格检查

Amazon 仅对目标 marketplace 中已有目录 ASIN 调用 Listings Restrictions，记录该卖家上架该 ASIN 的限制原因和申请入口；没有 ASIN 时不能拿品牌或商品类型代替查询。Product type 的字段约束由 Product Type Definitions 校验，其他类目、品牌或卖家资格走当前平台提供的对应资格路径。Listings Restrictions 只识别目录商品的卖家上架限制，不能替代全部产品安全与法律审查。[Amazon Listings Restrictions API](https://developer-docs.amazon.com/sp-api/docs/listings-restrictions-api)

TikTok Shop 刷新目标店铺的叶子类目及 `permission_statuses`，再调用 Get Category Rules 获取认证、尺寸表、包装尺寸等要求。官方文档要求在创建商品前按店铺和类目获取这些规则。[TikTok Shop Store Product Categories](https://partner.tiktokshop.com/docv2/page/store-product-categories)；[TikTok Shop Get Category Rules](https://partner.tiktokshop.com/docv2/page/get-category-rules-202309)

接口不可用时返回“平台资格未核实”，不得沿用过期缓存判定通过。

#### 步骤 7：拆分销售资格与运输限制

危险品、液体、电池或温控商品可能允许销售，但不适合某个仓库、承运商或履约方案。分别输出销售结论和运输结论；除非销售规则本身禁止，否则不得把运输限制误报为平台禁售。

#### 步骤 8：合并决策并生成整改动作

按“确定性禁售 → 店铺资格未完成 → 必需证据缺失或失效 → 证据／规则冲突 → 运输限制 → 暂无阻断”合并。任一必需条件为未知时不能输出 `ELIGIBLE_CANDIDATE`。每个问题必须返回命中事实、官方来源、证据缺口、责任角色和整改动作；不得建议修改类目或隐去字段来规避审核。

### 23.4 平台分支

**Amazon：** 按 marketplace 和 seller 获取当前 Product Type Definition，检查必填、条件必填、安全与合规属性；只有已解析到目录 ASIN 时才调用 Listings Restrictions 查询该卖家的上架限制。Product Type Definition 是字段与条件约束，不是完整法律合规证明；“无 Listing restriction”也不代表产品合法或无需认证。[Amazon Product Type Definitions](https://developer-docs.amazon.com/sp-api/docs/retrieve-a-product-type-definition)

## 节点 24：知识产权与品牌侵权风险检查

### 24.1 目的与边界

对商品本体、包装、品牌字段、标题、文案、图片、视频、音频和供应链文件进行知识产权风险初筛，识别假冒或仿冒、未授权商标或 Logo、无授权图片／视频／音乐／字体、专利或外观设计、商业外观及姓名肖像等风险，并验证品牌授权链的地域、类目、渠道和期限。

本节点是风险筛查，不是不侵权法律意见，也不代表平台或权利人作出侵权认定，不自动提交投诉、申诉或反通知。商标近似、合理使用、转售权或平行进口、专利权利要求、外观设计、商业外观、版权原创性和授权效力等存在法律解释空间时，必须转人工或法律复核。

### 24.2 输入

### 24.3 处理逻辑

#### 步骤 1：建立资产与权利清单

为商品或包装商标、Listing 品牌词、图片、角色、视频、音乐、字体、产品结构、装饰设计、包装外观和人物身份建立独立记录。裁剪、翻译、重绘或 AI 改写版本仍要追溯原始来源，不能因加工后看起来不同就视为新权利。

#### 步骤 2：提取多模态风险信号

对图片和视频执行 OCR、Logo、角色和人物识别，对音频执行语音、音乐和口播识别，对文案提取品牌词、型号词及“兼容”“同款”“复刻”等关系表达。低清晰度、遮挡、变形 Logo 或疑似角色只形成候选线索，不直接认定侵权，也不直接忽略。

#### 步骤 3：核验商品、品牌与文件一致性

比较实物、包装、Listing 品牌字段、发票、授权书、图片 Logo、型号和各变体。实物明显带品牌却选择“无品牌”、故意模糊 Logo、把品牌词改写为变体字符等情况提高风险等级。

#### 步骤 4：执行商标初筛

按目标法域和相关商品类别检查完全相同文字／图形、拼写读音、翻译缩写和视觉近似，并分析品牌词是否造成关联、授权或官方身份误解。授权文件必须覆盖当前主体、市场、类目、渠道和期限。未检索到相同商标不等于无风险；数据库覆盖不足、申请中权利或近似判断不确定时转人工。

#### 步骤 5：核验版权与素材许可

逐一确认图片、视频、音乐、字体和文案是否原创，或是否取得复制、修改、翻译、商业推广和平台分发权；同时检查地域、期限、转授权和改编范围。供应商提供、网络可下载、已去水印或 AI 重绘都不能单独作为授权证据。

#### 步骤 6：分流专利、外观和人格权风险

机器只用于发现结构、造型、包装装潢和人物身份的高相似候选，不完成专利权利要求解释或法律实质近似判断。核心结构、同模具商品、显著近似包装、有效专利／外观权利或姓名肖像授权不明时，直接进入专业复核。

#### 步骤 7：验证真实性和授权链

分别判断“商品是否真实”和“卖家是否有权使用品牌或素材”。检查每层授权方、被授权方、品牌、商品类别、市场、平台、有效期和再授权权利。发票可证明采购线索，但通常不能单独证明拥有图片、视频或品牌内容使用权。

#### 步骤 8：形成基于证据的决策与处置

每项发现记录匹配对象、权利类型、冲突依据、授权证据、证据缺口、目标法域和受影响素材。高相似但有完整授权与中等相似但完全无来源证据应产生不同结论。建议动作只能是补授权、替换无来源素材、删除无必要第三方元素、重新制作原创素材、更正品牌字段或转法律复核；不得建议错拼品牌、遮挡 Logo 或去除水印来规避审核。

### 24.4 平台分支

**Amazon：** 检查品牌字段与实物、包装、发票和授权关系，区分创建品牌商品详情页、在已有 ASIN 上创建报价以及使用品牌素材的不同权利问题。已有 ASIN、可添加报价或未被系统拦截都不能作为不侵权证明。Amazon 将商标、版权和专利列为知识产权类型，并向权利人提供 Brand Registry 和 Report a Violation；本节点只形成风险报告，不代表权利人投诉。[Amazon：How to report an IP violation](https://sell.amazon.com/blog/report-a-violation-to-amazon)；[Amazon Brand Registry](https://sell.amazon.com/blog/what-is-amazon-brand-registry)

**TikTok Shop：** 检查商品、Listing、视频、LIVE 相关素材和店铺信息中的商标、版权、专利和人格权，核验 Qualification Center 中品牌授权的层级、地域、类目和期限。TikTok Shop 明确禁止未经授权使用第三方知识产权，并要求部分品牌商品先完成品牌授权；实物带品牌却选择 “No brand”、隐藏 Logo 或使用 “dupe”“replica”等表达应作为高风险。[TikTok Shop Intellectual Property Policy](https://seller-us.tiktok.com/university/essay?knowledge_id=6837901778306818)；[TikTok Shop Requirements for Brand Authorization](https://seller-us.tiktok.com/university/essay?identity=1&knowledge_id=2419888845686570&role=1&source_type=normal)

## 节点 25：Listing 全素材合规审核

### 25.1 目的与边界

在提交 Amazon 或 TikTok Shop 前，对一个确定版本的完整 Listing 统一审核，覆盖标题、卖点、描述、属性、规格、变体、搜索字段、主图、附图、信息图、A+／详情内容、商品视频、字幕、口播、音乐和营销声明，并检查图、文、视频、属性和实际商品是否一致。

本节点只审核待提交内容包，不执行真实发布；它消费节点 23 的商品合规结论和节点 24 的知识产权结论，但不替代专业法律判断。平台未报错、文本通过敏感词匹配或 AI 内容语言流畅都不代表合规。Amazon 也明确要求卖家自行审核 AI 建议内容，确保准确、完整并符合适用法律和平台政策。[Amazon：How to use Amazon AI to create product listings](https://sell.amazon.com/blog/amazon-listing-ai)

### 25.3 处理逻辑

#### 步骤 1：冻结待审版本

为 Listing、每个素材、商品事实和上游报告生成版本标识。审核结果只对该版本有效；标题、图片、视频、字幕、属性或变体发生变化后，相关审核立即过期，不能用旧审核结果覆盖新素材。

#### 步骤 2：提取全部可见和可听内容

除结构化字段外，提取图片 OCR 文本、Logo、水印、二维码、联系方式和角标，以及视频逐帧文字、口播、字幕、商品演示、背景音乐、包装数量和配件；同时读取分辨率、比例、格式、时长和大小。不得只审核后台文本而忽略图中文字和视频口播。

#### 步骤 3：建立原子声明清单

把“防水”“续航 12 小时”“适合 3 岁以上儿童”“FDA approved”“100% organic”“美国制造”“销量第一”等拆为最小可核验声明，记录出现位置、适用 SKU、限定条件、量化单位、目标人群和证据。相同声明在多个渠道出现时合并追踪，但分别检查其平台位置规则。

#### 步骤 4：执行事实与跨素材一致性检查

逐项比较名称、品牌、型号、材质、成分、容量、数量、套装、配件、尺寸、重量、功率、电池、颜色、变体、包装、用途、警示、产地和保修。事实未知时标记“无证据”，不能用模型常识补全。标题为两件套但图片展示三件、视频演示防水而事实仅为防泼溅、父商品把单个变体特征描述为全部变体共有等情况均作为冲突。

#### 步骤 5：执行确定性平台规则检查

使用目标市场当前规则检查字段必填、长度、格式、枚举和条件规则，以及促销、排名、绝对化表达、站外导流、平台名称或徽章、主图、附图、视频、A+、高风险声明和法定披露。字符数、图片规格等动态值必须来自当前平台和类目规则，不长期硬编码。

#### 步骤 6：核验声明证据

区分可由商品规格证明的事实、需要测试报告的性能、需要官方文件的认证、需要明确市场和时间范围的排名／比较，以及涉及疾病、安全、儿童或高风险功效的声明。证据必须匹配型号、变体、测试条件、市场和声明强度；特定实验条件结果不能无条件改写成普遍、永久有效。

#### 步骤 7：执行知识产权和媒体语义门禁

节点 24 存在 `BLOCKED`、未解决高风险素材或品牌授权缺口时，本节点不能通过。重新检查最终成品是否引入新的品牌、人物、音乐、图片或包装元素。图片和视频还要验证其真实表示消费者会收到的商品，不使用误导性渲染、错误数量、危险演示、虚假前后对比或与字幕口播冲突的画面。

#### 步骤 8：识别已有商品页错误复用

编辑已有 Listing 时比较商品身份、品牌、型号、核心功能、包装数量和变体结构。如果变更实质上把原商品页变成另一个商品，必须阻断并要求创建新商品，不能继承旧评论、销量或商品 ID。TikTok Shop 当前 Product Listing Policy 明确禁止把已有商品页改作不同商品。[TikTok Shop Product Listing Policy](https://seller-us.tiktok.com/university/essay?default_language=en&knowledge_id=3196690250417921)

#### 步骤 9：分类整改并重新审核

将问题分为 `SAFE_AUTO_FIX`、`EDITOR_REVIEW`、`EVIDENCE_REQUIRED`、`COMPLIANCE_REVIEW`、`LEGAL_REVIEW` 和 `BLOCKING`。自动修复只允许不改变语义的空格、标点、大小写、格式或明确技术尺寸调整；不得静默删除警示、修改商品事实或把无证据强声明改成另一项无证据声明。每次修订后重新执行声明提取、跨素材一致性、平台规则和上游门禁；只有阻断项清零且版本一致时才输出 `PASS`。

### 25.4 平台分支

## 节点 26：商品发布与上架校验

### 26.1 目的与边界

把已审核的标准商品数据映射为 Amazon 或 TikTok Shop 当前接口字段，依次完成本地确定性校验、平台实时发布预检、用户明确选择后的内部／平台草稿或真实提交、异步审核跟踪和发布后状态核验。

本节点必须区分“本地校验通过”“平台预检通过”“提交请求被接受”“平台正在审核”“商品已发布”和“商品可购买／可发现”。预检不得写入平台；真实提交必须由明确 `submission_mode` 和授权触发。HTTP 成功、Amazon `ACCEPTED` 或 TikTok Shop 返回 product ID 都不能单独作为上架成功。

### 26.2 输入

| `product_compliance_result` | `object` | 是 | 节点 23 的结论、资格和证据状态 |
| `ip_risk_result` | `object` | 是 | 节点 24 的结论和授权状态 |

### 26.3 处理逻辑

#### 步骤 1：执行发布门禁

确认节点 23 所需资格和证据已完成，节点 24 无未解决高风险或品牌授权缺口，节点 25 已通过；如为 `CONDITIONAL_PASS`，还必须核验全部非阻断警告的具名接受记录。验证三份报告及 `approved_listing_package` 都绑定当前提交版本。任何平台写入缺少明确授权，或任一内容在审核后变化时立即中止。

#### 步骤 2：识别新建、匹配已有商品或编辑

Amazon 根据 GTIN、UPC、EAN、ISBN、ASIN 等识别是否已有目录商品，再决定创建新商品、创建 offer-only Listing 或编辑 seller SKU。TikTok Shop 先根据内部映射、seller SKU 和 product ID 判断新建、编辑或跨市场复制；GSPOP 跨境店铺必须读取 Global Listing Rules 后再选择本地创建或 Replicate Product 路径。不得只用相似标题匹配已有商品，也不得用编辑接口把旧商品变成新商品。

#### 步骤 3：刷新平台定义并构建映射

提交前重新获取 Amazon Product Type Definition、枚举、条件规则和适用 ASIN 的 Listings Restrictions，或 TikTok Shop 叶子类目、店铺权限、Category Rules、Attributes 和 Brands；GSPOP 还必须获取 Global Listing Rules，锁定 `listing_method`、源店铺、目标市场和仓库库存规则。缓存按 marketplace／Shop ID 隔离；规则、类目、listing method 或授权上下文变化时重新映射。保存每个目标字段的商品事实、Listing、变体、平台规则或默认值来源，禁止为通过必填校验而编造材质、成分、品牌、认证、产地、价格或库存。

编辑现有商品时先比较当前平台基线与待提交版本，只修改用户授权字段；基线已变化则中止，避免覆盖其他系统或人工的新修改。

#### 步骤 4：执行本地确定性校验

检查必填和条件必填、数据类型、枚举、长度、单位、币种、叶子类目／product type、seller SKU 唯一性、父子体和变体组合、价格、库存、履约、包裹信息、素材引用、品牌、认证和责任主体，以及新建／编辑操作的商品身份。失败时不得调用真实提交接口。

#### 步骤 5：执行平台发布预检

Amazon 先按 Product Type Definition JSON Schema 校验，再对 `putListingsItem` 或 `patchListingsItem` 使用 `mode=VALIDATION_PREVIEW`。官方说明该模式用于在生产环境预览错误而不持久化目录数据。[Amazon Listings validation preview](https://developer-docs.amazon.com/sp-api/docs/building-listings-management-workflows-guide)

TikTok Shop 对走本地创建路径的未上架新商品使用 Check Product Listing，并结合 Get Category Rules 和 Get Attributes 检查候选商品；GSPOP 先读取 Global Listing Rules，若选择跨市场复制则同时校验源本地商品、目标店铺、目标类目／属性映射和仓库规则。已有商品应读取当前商品，再走 Edit／Partial Edit 和后续审核，不能把已有商品质量诊断当作发布预检。[TikTok Shop Listing quality diagnosis](https://partner.tiktokshop.com/docv2/page/listing-quality-diagnosis)

预检通过只代表当前预检未返回阻断问题，不保证真实审核通过。

#### 步骤 6：生成提交计划并确认真实写入

在任何平台写入前展示平台、市场、店铺、新建／编辑／跨市场复制操作、商品和 SKU 数量、字段变更、价格库存、内容版本、预检结果和警告。只有展示对象与 `submission_approval` 完全一致才可继续；`PREVIEW_ONLY` 必须在此结束。Amazon 的 `SAVE_DRAFT` 只保存内部映射包并返回，不调用 Listings Items；TikTok Shop 的 `SAVE_DRAFT` 仅在当前接口与商品状态支持 `AS_DRAFT` 时执行。

#### 步骤 7：执行真实提交

Amazon 只有在 `PUBLISH` 时执行平台写入：新建或全量更新使用 `putListingsItem`，已有 Listing 局部修改使用 `patchListingsItem`，批量商品可使用 `JSON_LISTINGS_FEED` 并逐消息跟踪。Amazon Listings Items 没有与 TikTok Shop `AS_DRAFT` 对等的平台草稿；`SAVE_DRAFT` 只能保存工作流内部草稿。官方说明 `ACCEPTED` 仅表示初始校验通过并已提交目录继续处理，`INVALID` 表示同步问题阻止接受；接受后仍可能出现异步问题。[Amazon Listings management workflow](https://developer-docs.amazon.com/sp-api/docs/building-listings-management-workflows-guide)

TikTok Shop 本地创建路径使用 Create Product：平台草稿明确传 `save_mode=AS_DRAFT`，真实上架明确传 `save_mode=LISTING`，并使用店铺内唯一的 idempotency key；已有商品按变更范围使用 Edit Product 或 Partial Edit Product。GSPOP 必须以 Get Global Listing Rules 返回的 `listing_method` 为准：本地创建模式在各目标店铺使用 Create Product；跨市场复制模式先锁定合格的源本地商品，再调用 Replicate Product。不得继续调用已退役的 Global Product 管理流程。[TikTok Shop GSPOP 新版发布工作流](https://partner.tiktokshop.com/docv2/page/a5crrkzs)；[旧 Global Product 流程退役公告](https://partner.tiktokshop.com/docv2/page/fapus8ql)

#### 步骤 8：跟踪异步审核并执行发布后校验

Amazon 处理 `LISTINGS_ITEM_STATUS_CHANGE` 和 `LISTINGS_ITEM_ISSUES_CHANGE`，必要时调用 `getListingsItem` 获取 issues、`BUYABLE` 和 `DISCOVERABLE`。问题既可能在同步提交阶段出现，也可能在接受后的异步处理中出现。[Amazon listing notifications and issues](https://developer-docs.amazon.com/sp-api/docs/notification-type-values)

TikTok Shop 通过 Product status change webhook 或 Get Product 获取创建／编辑审核状态；跨市场复制还要处理 Global replication status change webhook，并用 Get Global Replicated Products 核对每个目标市场的本地 product ID 和失败原因。Create／Edit／Replicate 请求被接受后仍输出 `SUBMITTED_PENDING_REVIEW`，收到各目标商品通过、失败或冻结状态后再更新业务结果。[TikTok Shop Products API overview](https://partner.tiktokshop.com/docv2/page/products-api-overview)；[TikTok Shop GSPOP 新版发布工作流](https://partner.tiktokshop.com/docv2/page/a5crrkzs)

发布后核验平台商品 ID／ASIN 与 seller SKU 绑定、标题、属性、素材、价格、库存、变体、可购买和可发现状态。“商品对象存在”与“商品可购买”必须分开。

#### 步骤 9：控制重试与部分成功

仅对网络超时、限流和临时平台错误受控重试，并复用相同幂等键或请求身份。政策、资格、必填、证据、审核拒绝、内容违规或商品身份冲突不得原样自动重试。批量发布逐商品、逐 SKU 返回结果；部分成功时输出 `PARTIAL_SUCCESS`，不得把整个批次简单标为成功或失败。

### 26.4 平台分支

**Amazon：** 使用 Catalog Items 判断是否匹配已有 ASIN，Product Type Definitions 获取字段约束，仅对已解析 ASIN 调用 Listings Restrictions 查询该卖家的上架限制，`VALIDATION_PREVIEW` 做不落库预检，Listings Items API 或 `JSON_LISTINGS_FEED` 执行提交。最终根据异步通知和 `getListingsItem` 的 issues、`BUYABLE`、`DISCOVERABLE` 判断，不能只依据 HTTP 200 或 `ACCEPTED`。[Amazon Listings Management Workflow](https://developer-docs.amazon.com/sp-api/docs/building-listings-management-workflows-guide)

**TikTok Shop：** 按 Shop ID 刷新叶子类目、权限、Category Rules、Attributes 和 Brands。GSPOP 先调用 Get Global Listing Rules：本地创建模式按目标店铺 Check Product Listing 后调用 Create Product；跨市场复制模式对源本地商品调用 Replicate Product，并通过复制 webhook／Get Global Replicated Products 跟踪每个目标市场。已有商品使用 Edit／Partial Edit 并跟踪重新审核。只有 Create／Edit 支持且当前状态允许时才映射 `SAVE_DRAFT` 为 `AS_DRAFT`；其他路径返回不支持，不伪造平台草稿。任何同步成功都不代表商品已 Live。[TikTok Shop GSPOP 新版发布工作流](https://partner.tiktokshop.com/docv2/page/a5crrkzs)

## 节点 27：库存与履约风险监控

### 27.1 目的与边界

将店铺、仓库、平台履约和在途补货数据对齐到 SKU—仓库—时间粒度，预测缺货、积压、超卖、迟发、履约取消和库存不同步风险，并给出有证据、可排序、可回滚的处置建议。

节点只负责监控、预测、诊断和建议；默认不自动补货、改库存、取消订单、切换履约或调整广告。当前可售、已占用、平台预留、不可售和在途必须分开；未入库的在途不得计入当前可承诺库存。预测是概率估计，不承诺销量或到货日。涉及写库存、下采购单或处置订单时必须人工确认并重新读取最新状态。

### 27.2 输入

| 变量名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `platform_context` | `object` | 是 | Amazon 或 TikTok Shop、市场、店铺／卖家、时区和币种 |
| `sku_warehouse_mapping` | `object` | 是 | 商品 ID、平台 SKU、卖家 SKU、变体、仓库和履约渠道的稳定映射 |
| `inventory_snapshots` | `list<object>` | 是 | 可售、预留／占用、冻结、不可售、在途、待质检、来源和快照时间 |
| `orders_and_demand` | `list<object>` | 是 | 订单创建、支付、取消、发货、送达及 SKU 数量和历史销量 |
| `fulfillment_events` | `list<object>` | 是 | 发货截止时间、包裹、承运商、运单、揽收／轨迹和取消原因 |
| `supply_plan` | `object` | 否 | 采购单、在途批次、最早／最晚到货、交期分布、MOQ、箱规和收货耗时 |
| `business_events` | `list<object>` | 否 | 促销、广告放量、价格变化、节假日、断货区间和异常大单 |
| `cost_and_constraints` | `object` | 否 | 采购／仓储／缺货成本、安全库存、目标服务水平、容量和最大库存天数 |
| `monitoring_policy` | `object` | 是 | 预测周期、风险阈值、最低样本、数据最大延迟和提醒频率 |
| `existing_actions` | `list<object>` | 否 | 已补货、调拨、暂停推广或人工忽略记录，用于防止重复建议 |

### 27.3 处理逻辑

#### 步骤 1：锁定对象和数据新鲜度

构建“平台—市场—店铺—商品—SKU—仓库—履约渠道”唯一键，统一时区但保留原始时间。检查快照过期、分页不全、时间戳回退和同一 SKU 的冲突最新值。关键数据过期时只报“数据陈旧风险”，不生成精确补货数。

#### 步骤 2：对齐 SKU、仓库与库存状态

只通过稳定 ID 映射合并数量，不用标题相似度直接合并。不同来源统一为可售、占用、预留／冻结、不可售、在途和待收货，同时保留平台原状态。分别计算：

- 当前可承诺库存 = 当前可售 − 未计入平台扣减的有效订单占用；
- 预计未来可用 = 当前可承诺 + 在预测日前有足够到货置信度的在途批次。

平台、ERP 和 WMS 中的同一库存只选一个数量事实源，其他源用于对账；差异超阈值时采用保守值并降低置信度。

#### 步骤 3：校正需求序列

分开标记取消、退款、退货、测试单和异常大单。断货期的观测销量属于受限销量，不能解释为需求下降。将促销、价格、广告、节假日和星期因素作为事件变量；样本不足时可使用同类先验，但必须标为低置信度。同时输出平均需求与高分位需求情景，不只给单点预测。

#### 步骤 4：计算库存覆盖与风险日期

按 SKU 和仓库滚动计算每日需求、订单占用、预计到货和可用余额，输出库存覆盖天数、首次可能缺货日及概率、到货前最大缺口、积压数量和低周转库存。交期使用历史分布或最早—最可能—最晚区间；交期不可信时不给精确到货承诺。

#### 步骤 5：识别超卖与履约风险

对比平台可售、外部可售、订单占用和已提交库存更新，识别负库存、重复占用、仓库漏同步和库存突变。对每个待履约订单计算距发货截止的剩余时间，检查包裹、运单、揽收和首条轨迹。“未到截止”、“临近截止”、“已超时”和“状态冲突”分开。样本不足时只报事件，不报异常率趋势。

#### 步骤 6：限定归因

每条风险保留库存差异、订单截止、到货批次、无轨迹时长或取消原因等直接证据。原因分为已确认、高概率和待验证：只有平台状态或原因码支持时才标“已确认”；仅有时间或统计相关时不得断言供应商、仓库、承运商或平台责任。

#### 步骤 7：策略门禁与动作建议

快照过期、映射不全、交期未知或样本不足时，降级为补数／核查建议。补货建议同时检查利润、现金占用、MOQ／箱规、仓容和已有采购单；商品即将停售、合规冻结或贡献利润为负时不直接建议补货。动作候选包括补货／加急／调拨、降低促销或广告放量、推迟采购、库存再平衡、优先处理临近截止订单和核查轨迹。每条建议输出优先级、依据、数量区间、完成时限、置信度、人工确认和回滚方式。

### 27.4 平台分支

**Amazon：** FBA 必须分开可履约、在途、预留、不可履约和调查中库存，不把 FBA 汇总数当作全部可售量；FBA 与 FBM 使用不同风险口径。FBA 关注可履约量、预留、不可售和入仓；FBM 关注自有仓可用、订单截止和承运轨迹。Amazon 官方说明 FBA Inventory API 可在 marketplace 粒度获取这些数量，并可订阅库存变化通知。[Amazon FBA Inventory API](https://developer-docs.amazon.com/sp-api/lang-en_EN/docs/fba-inventory-api)；[Amazon Notification Type Values](https://developer-docs.amazon.com/sp-api/docs/notification-type-values)

**TikTok Shop：** 订单创建时可处于 `UNPAID`，官方要求卖家在库存系统扣减或占用，因此未支付占用与已支付待发货必须分层，不得忽略或等权处理。[TikTok Shop Order API](https://partner.tiktokshop.com/docv2/page/650b1b4bbace3e02b76d1011) 履约区分 `FULFILLMENT_BY_TIKTOK` 和 `FULFILLMENT_BY_SELLER`，后者还区分平台物流与卖家物流；卖家履约重点监控 `shipping_due_time`、包裹、运单和揽收，平台履约不生成卖家发货动作。[TikTok Shop Fulfillment API](https://partner.tiktokshop.com/docv2/page/650b2044f1fd3102b93c9178)

## 节点 28：评论与差评洞察

### 28.1 目的与边界

将商品评论、退货／退款原因、售后记录和消费者反馈转化为可验证的问题主题、趋势、影响范围，以及产品、Listing、素材、包装、物流和客服改进动作。

商品评论、卖家反馈、退货原因、客服会话、内容评论和竞品评论必须分源统计。节点不删除、隐藏或操纵评论，不生成诱导好评、报复差评或选择性索评策略。情绪判断不等于缺陷定性；单条差评、主观偏好、物流抱怨或使用错误不得直接认定产品质量问题。只处理已授权的合法数据，输出不替代质检、法律鉴定或召回决策。

### 28.2 输入

| 变量名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `platform_context` | `object` | 是 | 平台、市场、店铺、商品 ID／ASIN、SKU／变体和时间窗 |
| `review_records` | `list<object>` | 条件必填 | 可合法访问的逐条评论；包含评论 ID、评分、标题、正文／片段、语言和时间等可用字段 |
| `platform_insights` | `object` | 条件必填 | 平台直接提供的聚合主题、趋势、样本口径、更新时间和覆盖范围；不得伪装成逐条评论 |
| `return_refund_records` | `list<object>` | 条件必填 | 订单／SKU、原因、状态、数量、金额和消费者说明 |
| `service_feedback` | `list<object>` | 条件必填 | 已脱敏工单／会话、咨询意图、问题与处理结果 |

### 28.3 处理逻辑

#### 步骤 1：验证来源、权限与身份

为每条原始记录或平台聚合洞察保留平台、市场、店铺、商品、SKU／变体、来源类型、粒度和采集时间。通过评论、退货申请或工单 ID 去重；只有文本相似但 ID 不同的记录不得直接删除。分开商品评论、卖家反馈、退货、客服、内容评论和平台聚合洞察。姓名、电话、地址和订单联系信息等非必要个人数据先脱敏。

#### 步骤 2：规范文本并保留证据

有逐条文本时识别语言、拼写变体、表情、否定、反讽和混合语言；翻译时同时保留原文、规范化文本和译文，主题证据始终可回溯到原文片段。评分、文本情绪和退货行为分开保存；五星评论也可能包含问题，低星也可能只抱怨物流。只有平台聚合洞察时，不反推或生成不存在的评论文本，只保留平台主题定义、样本口径、趋势和更新时间，并将结论限定在聚合层级。

#### 步骤 3：抽取属性情绪与高风险信号

抽取“对象—属性—评价—场景—严重度”，情绪按具体属性而非整条评论判断。区分明确事实、主观偏好、疑问和无法判断。伤害、过敏、起火、破损或儿童安全等信号进入独立人工复核队列，不与普通体验问题混排。

#### 步骤 4：聚类主题并对齐 SKU

使用质量／耐用、尺寸适配、功能性能、材质气味、包装、物流、安装使用、兼容性、描述预期和售后服务的统一分类。先语义成簇，再用商品事实与问题词典校正。同一评论可进多个主题，但总评论数只计一次。按 SKU、颜色、尺寸、批次、市场和时间分层，小样本主题标为“信号”而非稳定结论。

#### 步骤 5：计算频率、趋势和影响

同时输出提及数、涉及消费者数、评论占比、退货占比、评分影响和趋势。有订单或销量基数才计算每百／每千订单问题率；无基数时只报提及数。改版前后、批次、变体或市场对比必须统一观察窗和样本口径。竞品只作同口径参考，不与自有数据合并比例。

#### 步骤 6：限定归因与优先级

候选原因分为产品／制造、Listing／预期、包装／物流、使用／兼容、服务和未知。只有评论、退货原因、批次或履约证据交叉支持才提高置信度；“同时增长”只视为相关，不宣称因果。优先级综合发生频率、用户影响、趋势、商业影响、可控程度和置信度；安全风险不受低频限制，直接人工复核。

#### 步骤 7：生成改进动作并风控

将问题映射到产品／质检、Listing／FAQ、图片视频、包装物流和客服动作。内容修改只可使用已确认商品事实，消费者猜测不得写成新声明。安全、侵权、潜在召回或大规模批次问题只输出“暂停扩散并人工调查”，不由节点自行结案。每项动作附责任域、依据、预期指标、观察期和停止条件。

### 28.4 平台分支

**Amazon：** Customer Feedback API 提供 ASIN 和 browse node 层级的评论主题／趋势；退货洞察仅在 browse node 层级，数据按周更新、仅为英文且只覆盖官方列出的部分站点。因此不得把它当作实时逐条评论接口，也不能把类目退货主题直接归因给某一 ASIN。商品评论与 seller feedback 必须分开。[Amazon Customer Feedback API](https://developer-docs.amazon.com/sp-api/docs/customer-feedback-api)

## 节点 29：客服回复生成

### 29.1 目的与边界

基于消费者问题、商品事实、订单与履约状态、店铺政策和平台允许动作，生成目标语言的售前、物流、取消、退货退款、投诉和售后回复草稿，并提示需要客服执行或升级的下一步。

节点默认只生成草稿，不自动发送，不自动退款、取消、补发、赠券或承诺赔偿。只能引用已验证的商品、订单、物流和政策事实；数据缺失时应追问或标记待核实，不得编造。文本回复与实际售后动作必须分离：未执行动作不得写成“已退款／已补发”。安全、法律、媒体投诉、拒付、疑似欺诈或人身伤害必须转人工。

### 29.2 输入

| 变量名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |

| `conversation_context` | `object` | 是 | 会话／消息 ID、最新消费者消息、必要历史、时间和消费者语言 |
| `product_facts` | `object` | 是 | 商品 ID／SKU、规格、兼容性、功能、限制、使用和安全说明 |
| `order_context` | `object` | 条件必填 | 订单、商品行、支付、取消、发货、送达状态和更新时间 |
| `logistics_context` | `object` | 条件必填 | 包裹、承运商、运单、预计送达、最后轨迹和异常 |
| `aftersales_context` | `object` | 条件必填 | 退货／退款申请、原因、状态、可执行动作、金额和时限 |

### 29.3 处理逻辑

#### 步骤 1：锁定会话、订单和最新状态

验证会话、店铺、市场、订单和商品的归属，禁止用消费者提供的订单号越权读取他人信息。订单、物流和售后状态超时先刷新。按消息 ID 和已发送回执检查重复，并只保留完成本次服务所需的个人信息。

#### 步骤 2：识别多意图与风险

识别售前规格、兼容、库存、订单修改、物流、取消、退换货、退款、破损、少件、错件、投诉和使用问题，并区分“询问状态”、“要求动作”、“表达不满”和“提供新证据”。人身伤害、过敏、起火、儿童安全、法律威胁、欺诈和拒付标为强制升级。

#### 步骤 3：建立回复事实包

事实优先级为最新平台订单／售后状态 > 已生效店铺政策 > 已确认商品事实 > 审核过的 FAQ。为每个拟回复事实记录来源和时间。消费者陈述与平台状态冲突时，先确认问题并说明正在核查，不指责消费者或承运商。不确定内容转为明确追问，不猜测。

#### 步骤 4：选择方案并限定动作边界

根据意图决定直接回答、请求补充、解释状态、引导合法自助路径或人工处理。退款、补发、优惠券和取消先检查平台资格、店铺权限、金额和订单状态。未执行的动作只能写为待确认方案或下一步。多方案按消费者成本、履约可行性和店铺政策排序。

#### 步骤 5：生成本地化回复

使用消费者的目标语言与当地服务表达，保留型号、订单号和平台术语。回复结构为“确认问题 → 已知事实 → 明确下一步 → 需要的信息／时限”。金额、日期、尺寸、否定和条件句在翻译后再校验，避免改变承诺边界。

#### 步骤 6：内容、政策和发送门禁

检查虚假状态、无依据承诺、绝对保证、责任定性、站外引流、营销推广、诱导改评、敏感信息和内部备注。涉及金额、时限、保修和物流日期时与事实包逐项对照。所有结果均为草稿：事实型低风险回复可标记“可提交客服审核”，退款、补发、取消、优惠和投诉必须人工确认，高风险必须升级。交付草稿前重新查询当前可用消息类型和订单状态；状态改变即废弃旧草稿。本节点不调用平台发送接口，也不把“可发送”写成“已发送”。

### 29.4 平台分支

**Amazon：** Messaging API 的消息类型不是所有订单都可用。官方流程要求先通过 `getMessagingActionsForOrder` 获取当前订单允许的动作，由卖家选择消息类型，且仅在该类型支持时才可写自定义内容。因此先输出“建议消息类型 + 草稿”再校验；无可用动作时只返回 Seller Central 人工处理建议，不把任意自由文本假设为可通过 API 发送。[Amazon Messaging API](https://developer-docs.amazon.com/sp-api/docs/messaging-api)

## 节点 30：广告与流量投放优化

### 30.1 目的与边界

统一分析 Amazon 广告以及 TikTok Shop 广告、自然内容和达人内容的流量与转化数据，在明确利润、库存和归因口径的前提下，诊断流量损失点，并给出关键词、商品、素材、预算、出价、目标 ROI 和内容协同建议。

节点默认只提供分析和变更建议，不自动创建、暂停或修改广告。Amazon 广告归因销售与 TikTok Shop GMV Max 的总渠道归因含义不同，不能直接横向比较。广告报告只是平台规则下的归因结果，没有对照实验时不宣称因果增量。任何预算、出价或目标 ROI 建议都受库存、利润、履约容量、冷却期和最大变更幅度限制。节点不保证曝光、销量、排名、ROAS 或 GMV。

### 30.3 处理逻辑

#### 步骤 1：锁定分析粒度和数据版本

构建“平台—账户—市场—活动—广告实体—商品—日期—归因设置—币种”唯一键。检查分页、报表完成状态、时区、币种和活动状态。同一订单或销售额若同时出现在活动、广告组、广告和商品层，只在选定粒度计入一次。广告、Listing、价格、库存和促销变更形成时间线，不用变更后数据解释变更前表现。

#### 步骤 2：统一指标与利润口径

重算 CTR、CPC、CVR、CPA、ROAS／ACOS，检查零分母、四舍五入和平台汇总差异。多币种按明确汇率日期转换并保留原币。区分下单、支付、取消、退款、毛销售和净销售；基于商品、平台、履约、折扣和预期售后损耗计算贡献利润与盈亏门槛。归因窗尚未走完的转化标“未成熟”，不与成熟周期直接比较。

#### 步骤 3：分解流量漏斗

按商品、活动、广告组、关键词／搜索词、placement、素材、达人和日期分层，诊断：展示不足是资格、预算、出价、库存或相关性；展示有但点击低是主图／标题／价格／素材；点击有但转化低是 Listing、评价、规格、配送或落地一致性；有转化但利润差是广告成本、折扣、费用、退款或低毛利。同时检查商品页与库存，避免把承接或缺货问题错当出价问题。

#### 步骤 4：样本、归因与根因边界

为点击、订单、花费和运行天数设最低证据门槛，样本不足时输出“继续收集”而不是暂停结论。大促、价格变化、断货、平台故障和异常流量单独标记；处于冷却期时除超预算、合规或断货等紧急情况外不再调整。Amazon 保留广告归因销售与店铺总销售两个口径；TikTok Shop 分开广告、自然、达人／affiliate 和店铺 GMV，使用 GMV Max 总渠道归因后不得再叠加同一自然／达人订单。没有对照时只表述“平台归因表现”或“相关变化”。

#### 步骤 5：生成平台适配的候选策略

Amazon 候选包括预算再分配、出价、搜索词转关键词、否定词候选、匹配方式、placement、低效商品降级和 Listing 协同修复。TikTok Shop 候选包括商品选择、授权素材／达人内容、新素材测试、目标 ROI、预算和 Product／LIVE GMV Max 策略。每个候选输出当前值、建议值／区间、证据、预期影响范围、置信度和风险。只建议当前产品真正支持的字段，不为自动化产品虚构可手动控制的关键词、受众或单素材出价。

#### 步骤 6：策略门禁、排序与回滚

库存覆盖低、商品不可售、Listing 受限或履约容量不足时禁止扩量；贡献利润为负或成本缺失时不因表面 ROAS 达标增加预算。变更不得超过卖家设定比例，大幅调整拆分多阶段并限制频率。否定词、暂停、删除素材或显著改预算必须人工确认。对自动化广告优先调整允许的目标和预算，不与平台自动分配冲突。按“预期贡献利润改善 × 置信度 ÷ 执行风险”排序，区分立即止损、稳态优化和学习实验，为每项变更附基线、观察期、成功指标、停止条件和回滚动作。

### 30.4 平台分支

**Amazon：** Amazon Ads API 支持程序化管理活动和获取报告，官方明确列出自定义报表、关键词／出价优化和预算优化等用途。在实际广告类型支持的范围分析关键词、搜索词、匹配方式、placement、商品和预算。否定词建议必须保留原搜索词证据并检查是否误伤高转化长尾词。广告归因销售与自然销售分开，不用广告 ROAS 代表商品整体利润。[Amazon Ads API](https://advertising.amazon.com/about-api)
