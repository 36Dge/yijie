# 跨境电商工作流节点定义

## 1.节点 1：商品采集

**执行粒度**：单商品或批量来源  
**节点边界**：负责可靠取得并统一封装原始商品事实，不负责优化文案、判断最终类目或重建平台变体。

### 1.1 输入

| 变量名 | 类型 | 必填 | 说明与约束 |
| --- | --- | --- | --- |
| `sources` | `list<object>` | 是 | 每项包含 `source_type`、`uri/file_id/product_id`、可选 `platform`、`marketplace`、`credential_ref`。 |
| `product_hint` | `object` | 否 | 已知品牌、型号、GTIN、语言或预期类目，用于校验，不可覆盖来源事实。 |
| `idempotency_key` | `string` | 否 | 同一批采集请求的幂等键，防止重复写入和重复计费。 |

### 1.2 业务配置

| 配置项 | 类型 | 建议默认值 | 说明 |
| --- | --- | --- | --- |
| `collection_scope` | `list<string>` | `core,attributes,variants,media` | 需要采集的字段范围。评论和竞品经营信号由“竞品商品采集”负责。 |
| `max_items` | `integer` | `100` | 批处理上限；超出时分页或返回明确错误，不静默截断。 |
| `follow_pagination` | `boolean` | `true` | 对授权 API 或文件分片是否继续翻页。 |
| `dedup_strategy` | `string` | `platform_id_gtin_fingerprint` | 依次使用平台 ID、GTIN/MPN、稳定字段指纹去重。 |
| `store_raw_snapshot` | `boolean` | `true` | 保存原始响应快照引用及哈希，便于审计和重放。 |
| `strict_source_policy` | `boolean` | `true` | 只允许授权接口、用户上传文件和允许访问的来源；不绕过登录、验证码或访问控制。 |

### 1.3 处理逻辑

1. **请求预检**：校验来源类型、文件格式、URL 协议、目标主机和批量上限；URL 连接器拒绝本机、内网地址及异常重定向，限制响应大小和下载时长。
2. **连接器路由**：根据 `source_type` 选择授权平台 API、文件解析器、网页结构化数据解析器或上游对象适配器。优先使用 API/JSON-LD/表格字段，只有结构化数据缺失时才调用文本或视觉模型抽取。
3. **限流与幂等**：按店铺、平台和凭证执行并发控制；对 429、网络中断和可恢复 5xx 使用指数退避与随机抖动；通过 `idempotency_key + source_identifier` 避免重复采集。
4. **原始快照与来源记录**：保存响应时间、来源标识、内容哈希和快照引用。大文件、页面和媒体只返回引用，不把原始二进制塞入工作流变量。
5. **字段解析**：分离标题、描述、卖点、价格、币种、品牌、规格、属性、SKU、库存、图片、视频和物流字段；保留原始字段名及原始值。
6. **变体行识别**：识别父商品、可售 SKU 和规格组合，但此时只保留来源关系，不擅自创建缺失组合；正式重建由节点 4 完成。
7. **实体解析和去重**：先按平台商品 ID/子 SKU 去重，再按 GTIN/MPN，最后使用品牌、型号、标题核心词和主图哈希构造指纹。疑似重复但证据不足时保留两条并输出冲突。
8. **字段级一致性检查**：检查币种是否存在、价格是否非负、图片是否可访问、SKU 是否重复、父子数据是否自洽；`product_hint` 仅用于发现冲突。
9. **质量评分**：按字段完整度、解析确定性、来源可靠性和新鲜度计算 `completeness`、`confidence`、`freshness`，分别输出，避免用一个总分掩盖问题。
10. **批量结果归并**：单项失败不丢弃其他成功商品。所有来源均被正常查询但没有识别出商品时，返回 `NO_PRODUCT_FOUND + needs_review`；只有鉴权/权限失败，或来源整体不可用且没有任何可返回结果时才抛出致命异常。

### 1.4 输出

| 变量名 | 类型 | 说明 |
| --- | --- | --- |
| `products` | `list<object>` | 统一为 `ProductObjectV1` 的商品列表。 |
| `collection_summary` | `object` | 请求数、成功数、部分成功数、失败数、去重数、耗时、来源分布。 |
| `rejected_sources` | `list<object>` | 无法处理的来源及 `source_ref`、错误码、是否可重试。 |
| `raw_snapshot_refs` | `list<object>` | 原始快照引用、内容哈希和采集时间。 |

### 1.5 业务结果与错误码

`INVALID_SOURCE`、`UNSUPPORTED_FILE_FORMAT`、`AUTH_FAILED`、`PERMISSION_DENIED`、`RATE_LIMITED`、`SOURCE_UNAVAILABLE`、`PARSE_FAILED`、`NO_PRODUCT_FOUND`、`BATCH_LIMIT_EXCEEDED`。

`NO_PRODUCT_FOUND` 是业务结果；单来源 `PARSE_FAILED` 为 warning 并可返回 `partial`；整体契约无效、鉴权/权限失败或全部依赖不可用且无降级才是 fatal。

## 2. 节点 2：商品信息清洗与标准化

**执行粒度**：单商品或商品列表  
**节点边界**：只修复格式和统一表达；不改写营销内容、不凭空补齐商品事实。

### 2.1 输入

| 变量名 | 类型 | 必填 | 说明与约束 |
| --- | --- | --- | --- |
| `products` | `list<object>` | 是 | `ProductObjectV1` 或可映射到该结构的商品列表。 |
| `target_marketplace` | `object` | 是 | 包含平台、国家/站点、语言、目标币种和单位制。 |
| `fx_rates` | `object` | 否 | 显式提供汇率、基准币种、报价币种、时间和来源；缺失时不得自行猜测汇率。 |
| `normalization_dictionary` | `object` | 否 | 品牌保护词、属性别名、颜色/材质/单位词典等用户扩展规则。 |

### 2.2 业务配置

| 配置项 | 类型 | 建议默认值 | 说明 |
| --- | --- | --- | --- |
| `strictness` | `string` | `balanced` | `conservative`、`balanced`、`strict`。影响自动修复与转人工门槛。 |
| `html_policy` | `string` | `preserve_structure` | 去除脚本和标签，但保留段落、列表及必要换行。 |
| `unit_system` | `string` | `target_market_default` | 目标站点常用单位；始终保留原始值。 |
| `currency_policy` | `string` | `preserve_original` | 可选 `preserve_original` 或 `convert_with_supplied_rate`。 |
| `deduplicate_media` | `boolean` | `true` | 使用 URL 规范化、内容哈希和感知哈希识别重复媒体。 |

### 2.3 处理逻辑

1. **Schema 和类型检查**：先验证必需对象层级，对数字字符串、布尔文本和空数组进行安全类型转换；无法确定的值进入问题清单，而不是强制转换。
2. **文本净化**：执行字符编码修复、Unicode 规范化、HTML/脚本清理、空白折叠和控制字符移除。保留型号、商标符号和有意义的项目符号，避免把“清洗”变成文案改写。
3. **字段别名归一**：通过版本化字段字典把 `colour/color`、`net_weight/item_weight` 等来源字段映射到统一路径；无法映射的字段保留在 `unmapped_attributes`。
4. **单位处理**：解析“10 x 20 x 30 cm”等复合表达，统一长度、重量、容量和温度单位；保留 `original_value/original_unit`、换算公式和舍入精度。尺寸字段缺少维度含义时不得自行猜测长宽高顺序。
5. **币种处理**：校验 ISO 币种；只有输入包含有时间戳和来源的汇率时才换算。原币金额、汇率、汇率日期及目标金额同时保留，防止后续财务计算失去审计链。
6. **受控词汇归一**：对颜色、材质、尺寸、容量和包装数量使用目标市场词典归一。品牌、型号、认证和成分等高风险事实只允许格式修复，不允许语义推断覆盖。
7. **内容去重**：清除完全重复的卖点和属性；近似文本只标记相似度，除非规则能证明重复，否则不自动删除。媒体使用内容哈希/感知哈希去重，并保留主图优先级。
8. **变体一致性检查**：检查重复 SKU、重复规格组合、父级属性与子级冲突、价格币种混用和库存负数；此节点只报告问题，不重建结构。
9. **异常值检测**：用字段规则和同一商品变体分布识别负价格、零重量、尺寸数量级异常、单位错位和离群价格。跨商品离群判断必须在可比类目内进行。
10. **可逆变更日志**：每次自动修改记录 `field_path`、原值、新值、规则 ID、原因和置信度。任何低置信度语义调整转为 `needs_review`。
11. **质量复评**：分别计算完整度、格式合法率、一致性和“进入下一节点”的标准化数据就绪度；它不表示商品整体可发布。缺失字段不等于错误，报告中需区分 `missing`、`invalid`、`conflict`、`unmapped`。

### 2.4 输出

| 变量名 | 类型 | 说明 |
| --- | --- | --- |
| `normalized_products` | `list<object>` | 清洗后的 `ProductObjectV1`，包含原值引用。 |
| `change_log` | `list<object>` | 字段级原值、新值、规则、原因、置信度和是否可回滚。 |
| `quality_reports` | `list<object>` | 每个商品的完整度、合法率、一致性、异常字段和待补字段。 |
| `review_items` | `list<object>` | 需要人工确认的冲突或低置信度映射。 |
| `unmapped_attributes` | `list<object>` | 无法进入统一模型但被保留的来源属性。 |

### 2.5 业务结果与错误码

`INVALID_PRODUCT_SCHEMA`、`ENCODING_ERROR`、`UNIT_AMBIGUOUS`、`FX_RATE_MISSING`、`FX_RATE_STALE`、`DUPLICATE_SKU`、`ATTRIBUTE_CONFLICT`、`NO_VALID_PRODUCT`。

`UNIT_AMBIGUOUS`、`FX_RATE_MISSING`、`DUPLICATE_SKU`、`ATTRIBUTE_CONFLICT` 和 `NO_VALID_PRODUCT` 默认输出复核/隔离结果；只有输入列表整体无法解析或没有任何可返回的合法对象时才是 fatal。

## 3. 节点 3：类目与属性智能匹配

**执行粒度**：商品列表 × 目标平台/站点列表  
**节点边界**：输出目标平台有效叶子类目或 Product Type 及属性映射，不发布商品、不编造缺失属性，也不把类目匹配等同于商品合规判断。

### 3.1 输入

| 变量名 | 类型 | 必填 | 说明与约束 |
| --- | --- | --- | --- |
| `normalized_products` | `list<object>` | 是 | 节点 2 输出，必须包含商品 ID、内容、属性和来源证据。 |
| `targets` | `list<object>` | 是 | 每项包含 `target_id`、`platform`、`marketplace`、`locale`；每个目标独立计算。 |
| `category_hints` | `list<object>` | 否 | 来源类目或卖家提示，默认只是软提示，不能直接当最终结果。 |
| `visual_features` | `list<object>` | 否 | 已有图片识别结果，必须包含图片哈希、模型版本和置信度。 |
| `matching_overrides` | `object` | 否 | 允许/禁止类目、卖家确认属性；覆盖操作必须记录原因和时间。 |
| `reference_time` | `string` | 否 | 选择平台类目和属性规则快照的基准时间。 |

### 3.2 业务配置

| 配置项 | 类型 | 建议默认值 | 说明 |
| --- | --- | --- | --- |
| `taxonomy_registry_ref` | `string` | 当前稳定快照 | 平台、站点对应的类目树、Product Type、弃用和迁移关系。 |
| `attribute_schema_registry_ref` | `string` | 与类目快照一致 | 必填、推荐、枚举、单位和条件属性规则。 |
| `crosswalk_ref` | `string` | 当前稳定版本 | 来源类目、平台中立本体和目标类目的映射。 |
| `candidate_top_k` | `integer` | `20` | 混合召回保留的候选数量。 |
| `min_auto_confidence` | `float` | `0.90` | 自动匹配门槛，实际由平台/类目族校准配置覆盖。 |
| `min_score_margin` | `float` | `0.15` | 第一、第二候选最小分差。 |
| `enable_visual_signal` | `boolean` | `true` | 图片可用时启用视觉信号，失败后可降级。 |
| `semantic_model_ref` | `string` | 固定已发布版本 | 只用于候选召回/重排，不能生成不存在的类目 ID。 |

### 3.3 处理逻辑

1. **加载一致的元数据快照**：按目标平台、站点和 `reference_time` 同时加载类目树、有效叶子节点、Product Type、属性 Schema、枚举/单位和弃用迁移关系。输出中回传实际版本，禁止混用不同生效时间的类目与属性规则。
2. **构造商品特征**：组合标题、卖点、用途、品牌型号、结构化属性、来源类目和规格量纲。可从主图提取主体/使用场景特征，但视觉推断的权重低于商品明确属性，且不得回写为商品事实。
3. **多路候选召回**：并行执行确定性 crosswalk、类目名称/同义词词法检索、语义向量检索、属性 Schema 兼容度检索和可选视觉检索，合并去重得到 Top K。
4. **候选硬过滤**：剔除已弃用、目标市场不存在、不是可提交叶子节点、与显式排除条件冲突的候选。无有效候选属于正常业务结果 `unmatched`，不是系统异常。
5. **层级与事实冲突检查**：检查类目完整路径；对文本、关键属性、规格量纲、视觉主体和来源类目相互矛盾的情况施加可解释惩罚。套装、多用途或组合商品存在多个合理类目时必须转人工复核。
6. **解释型评分**：按版本化配置计算：

   ```text
   candidate_score =
       w1 × crosswalk_confidence
     + w2 × lexical_similarity
     + w3 × semantic_similarity
     + w4 × attribute_compatibility
     + w5 × visual_similarity
     + w6 × confirmed_history_prior
     - conflict_penalties
   ```

   权重按平台、市场和类目族校准。输出全部分项，不能只给黑盒总分。
7. **约束重排**：LLM 或分类模型只能在已经通过硬过滤的候选集合中重排，输出必须符合 JSON Schema 并引用支持证据；禁止模型自行生成类目 ID。
8. **置信度校准**：相似度不直接等于概率。使用已验证的校准器综合 Top1 得分、Top1/Top2 分差、关键证据覆盖和冲突数量。满足置信度、分差、证据覆盖且无阻断冲突时才自动通过；否则为 `review_required`。
9. **属性映射**：选定类目后，按“卖家确认值 > 商品直接事实 > 可证明的确定性派生值 > 模型候选”映射平台属性 ID，完成类型、枚举、单位、单值/多值及条件依赖转换。
10. **禁止无证据补值**：例如明确写有 `Pack of 2` 可以派生包装数量；图片上看似有两个物体只能作为建议。没有证据的必填属性进入 `missing_required_attributes`。
11. **多目标隔离**：Amazon US、Amazon UK、TikTok Shop US 等目标独立加载规则、独立评分；一个目标失败不能覆盖其他目标结果，类目 ID 也不得跨站点复用。
12. **最终校验**：复核类目有效性、属性归属、值域、条件必填项、映射覆盖率和冲突；任何人工覆盖都进入审计证据。

推荐判定初值：`confidence ≥ 0.90`、Top1/Top2 分差 `≥ 0.15`、关键证据覆盖 `≥ 0.80` 且无冲突时自动匹配；`0.65～0.90` 或候选接近时要求复核；低于 `0.65` 时不匹配。阈值必须版本化并通过人工确认样本持续校准。

### 3.4 输出

| 变量名 | 类型 | 说明 |
| --- | --- | --- |

| `review_items` | `list<object>` | 类目歧义、属性冲突、必填缺失及低置信度建议。 |

### 3.5 业务结果与错误码

`INVALID_TARGET`、`TAXONOMY_UNAVAILABLE`、`ATTRIBUTE_SCHEMA_VERSION_MISMATCH`、`NO_VALID_CANDIDATE`、`AMBIGUOUS_CATEGORY`、`DEPRECATED_CATEGORY`、`ATTRIBUTE_VALUE_INVALID`、`REQUIRED_ATTRIBUTE_MISSING`、`VISUAL_ANALYSIS_FAILED`、`MODEL_UNAVAILABLE`。

其中 `NO_VALID_CANDIDATE`、`AMBIGUOUS_CATEGORY` 和 `REQUIRED_ATTRIBUTE_MISSING` 是业务结果，应输出复核信息；只有元数据/契约整体不可用时才进入异常分支。

## 4. 节点 4：SKU／变体结构重建

**执行粒度**：单个父商品及其来源 SKU 列表，可批量处理多个父商品  
**节点边界**：重建“父商品—规格轴—可售 SKU”结构并映射目标平台；不创造并不存在的可售组合、条码、价格或库存，也不执行发布。

### 4.1 输入

| 变量名 | 类型 | 必填 | 说明与约束 |
| --- | --- | --- | --- |
| `product` | `object` | 是 | 标准商品事实，至少包含 `product_id`、标题和基础属性。 |
| `source_skus` | `list<object>` | 是 | 每项至少包含稳定 `source_sku_id` 和 `options`；可含条码、价格、库存、媒体引用。 |
| `targets` | `list<object>` | 是 | 平台、站点、节点 3 选定的类目 ID/Product Type 和 Schema 版本。 |
| `platform_schemas` | `list<object>` | 条件必填 | 平台类目允许的变体主题/销售属性、值域和限制；未传入时由版本化连接器取得。 |

### 4.3 处理逻辑

1. **输入和快照校验**：验证商品 ID、来源 SKU ID、平台目标和数据类型；对输入、平台 Schema、别名字典及配置分别计算哈希，保证同输入同版本可重放。
2. **规格轴和值归一**：按“人工锁定映射 > 稳定属性/值 ID > 规范化后完全相同 > 版本化别名字典 > 可逆单位等价 > 模糊候选”处理。模糊字符串和 LLM 只能提出建议，不能直接合并 `navy` 与 `blue` 等可能有业务差异的值。
3. **识别销售规格轴**：对每个属性计算不同值数量、SKU 覆盖率、区分 SKU 的能力、加入后组合冲突下降量，以及目标类目是否允许该销售属性。所有 SKU 值相同的字段通常下沉为父级属性。
   - 若商品只有一个有效 SKU，或所有 SKU 都没有产生差异的销售属性，则进入 `simple_sku` 模式：输出一个无规格轴的标准 SKU，并执行可执行的 ID/关联校验；这不是异常。
   - 若 `source_skus` 为空，节点不得创造 SKU；返回 `needs_review` 和 `SOURCE_SKU_EMPTY` 业务结果。只有输入契约无法解析时才抛 fatal。
4. **稳定组合键**：对标准轴和值生成稳定 ID，再按固定轴顺序构造与输入顺序无关的组合键，例如 `color=black|size=m|pack_quantity=2`。
5. **冲突检测**：至少检测一个来源 SKU 对应多个组合、多个 SKU 占用同一组合、条码跨商品冲突、规范化碰撞、规格缺失、价格币种冲突和负库存。完全重复采集记录可去重，但不得重复累加库存。
6. **理论矩阵分析而非造 SKU**：

   ```text
   expected_count = |V1| × |V2| × ... × |Vn|
   missing_set = expected_set - observed_set
   ```

   默认只输出 `observed_set` 中真实存在的可售 SKU。缺失组合进入 `missing_combinations`；即使开启 `planned_full_matrix`，计划项也必须 `inventory=0`、`variant_ready=false`，不得伪造条码和价格。稀疏矩阵本身不一定是错误。
7. **关联价格、库存和媒体**：依次使用内部 SKU ID、来源 SKU ID、唯一条码、人工锁定组合和标准组合键关联。任何键出现一对多时返回 `join_ambiguous`，不能靠标题或文件名近似匹配。
8. **稳定父/子 SKU 生成**：已有且无冲突的标识优先保留；新子 SKU 使用 `product_id + combination_key` 的稳定哈希或模板，冲突后缀也使用稳定短哈希，不使用随机数。
9. **Amazon 映射**：从目标类目 Schema 取得允许的 Variation Theme，将标准轴映射到主题属性。父体只承载共享信息；子体必须有完整且唯一的变体属性元组。轴超出平台支持时按配置拒绝或拆分为多个父体。
10. **TikTok Shop 映射**：从目标类目 Schema 取得销售属性 `property_id/value_id`；只有 Schema 允许时才使用自定义值。每个 SKU 校验属性数量、值域、组合唯一性、价格、库存及媒体绑定。
11. **变体映射就绪判定**：只判断变体结构和本节点实际验收字段是否足以交给后续发布准备流程。必须满足无未解决组合冲突、所有销售轴和值确定映射、未人工创造可售组合，以及目标平台的变体 Schema 校验通过。价格、库存或条码只有在本次输入提供且被目标变体 Schema 声明为本阶段必检字段时才纳入；Listing 内容、媒体完整性、合规、资质和账号权限不属于本判定。因此 `variant_ready=true` 绝不代表商品整体可上架。

质量指标采用确定性比率：

```text
source_valid_rate = 有效来源 SKU 数 / 来源 SKU 总数
option_complete_rate = 完整规格元组 SKU 数 / 有效 SKU 数
platform_mapping_coverage = 映射成功 SKU 数 / 有效 SKU 数
variant_ready_rate = 通过全部已评估变体校验的 SKU 数 / 有效 SKU 数
```

任一分母为 0 时不得计算或填 0：省略对应比率，并在 `quality_report` 中设置 `availability=unscored` 与 `reason_code`（例如 `SOURCE_SKU_EMPTY` 或 `NO_VALID_SKU`）。因此“无法评分”和“评分为 0”在契约上可区分。

**执行粒度**：同一平台、站点、类目和可比时间窗口下的一批候选商品  
**节点边界**：汇总已有证据并进行可审计排序；不负责采集竞品、不把得分解释为成功概率，也不替代合规、法律或税务结论。

| 配置项 | 类型 | 建议默认值 | 说明 |
| --- | --- | --- | --- |
| `policy_version` | `string` | 必须指定 | 指标、权重、门禁、公式和来源可靠度版本。 |

建议默认维度权重：需求热度 `0.25`、竞争机会 `0.15`、价格带适配 `0.10`、利润空间 `0.25`、季节与进入时机 `0.10`、评论痛点机会 `0.08`、内容缺口机会 `0.07`。这是初始策略而非永久规则；Amazon 与 TikTok Shop 可配置不同 profile。合规风险不参与加权稀释，直接作为硬门禁。

### 5.3 处理逻辑

1. **锁定策略与比较口径**：校验候选 ID、平台、类目、时间窗、单位和权重；所有观测必须保留来源、记录 ID、采集时间、样本数和可靠度。不同周期先换算为同口径并记录假设。
2. **稳健清洗**：去除重复观测；高偏态的搜索量、销量、评论数先 `log1p`；评分用值可 P5/P95 缩尾，但原始值必须保留。多来源明显冲突时不能静默平均，应输出冲突并降低置信度。
3. **先执行硬门禁**：
   - 合规：`pass/hold/reject`；未知或资质待补为 `hold`。
   - 利润：保守情景利润和利润率达标才 `pass`；成本缺失为 `hold`；保守情景亏损为 `reject`。
   - 价格带：可盈利售价与观察到的竞品价格带无交集时，默认 `hold/validate` 并标记 `no_benchmark_overlap`；只有策略提供明确支付意愿/价格弹性证据或硬性最高价格时才可 `reject`。
   - 数据充分性：关键证据或观测权重不足为 `hold`。

   `reject` 保留诊断但不排名，`hold` 只输出临时结果，只有 `pass` 进入正式排名。门禁失败是业务结果，不是系统异常。
4. **需求热度**：以可验证搜索需求、销量/GMV 速度和趋势为子指标，例如：

   ```text
   demand_score =
       0.45 × normalized_search_demand
     + 0.35 × normalized_sales_velocity
     + 0.20 × normalized_growth
   ```

   同一估算源派生的搜索量和销量需标记相关性，避免重复放大。
5. **竞争机会**：先算竞争压力，再取反：

   ```text
   competition_pressure =
       0.25 × competitor_count
     + 0.25 × review_barrier
     + 0.15 × rating_barrier
     + 0.20 × seller_concentration
     + 0.15 × ad_saturation
   
   competition_opportunity = 100 - competition_pressure
   ```

   “竞品少”必须和真实需求同时成立，不能单独视为机会。
6. **价格带适配**：使用梯形函数；低于可行下界和高于市场上界为 0，目标区间内为 100，两侧线性衰减。目标区间由节点 8 的可盈利底线与可比竞品价格分布共同决定。
7. **季节与时机**：在 12～24 个月序列上计算变异系数、前三高峰月集中度和距下一高峰月数，并结合采购、生产、入仓和内容准备提前期。已经错过备货窗口的历史高峰不能带来高分。
8. **评论痛点机会**：模型可做主题抽取，但分值由统计和商品证据决定：

   ```text
   theme_weight = mention_rate × severity × evidence_confidence
   pain_opportunity =
     100 × Σ(theme_weight × candidate_solution_coverage) / Σ(theme_weight)
   ```

   候选没有事实证据解决某痛点时，覆盖度为 0。若有效评论样本数为 0、`Σ(theme_weight)=0`，该维度为 `unscorable` 并进入缺失权重处理，不能返回 0 分冒充“没有机会”。
9. **内容缺口机会**：

   ```text
   gap_score =
     100 × Σ(content_importance × competitor_absence_rate × candidate_supported)
           / Σ(content_importance)
   ```

   竞品未覆盖某内容不自动代表高价值，必须乘以用户重要度，且候选确实具备可表达的事实或素材。若有效竞品样本数为 0 或 `Σ(content_importance)=0`，该维度为 `unscorable`，不能按 0 分处理。
10. **缺失值与归一化**：缺失不等于 0；利润和合规绝不插补。普通维度只有在观测权重达到门槛时才重分配权重。优先使用同站点、类目、时间窗的外部 P10/P90：

    ```text
    normalized = 100 × clip((transform(x)-transform(p10)) /
                            (transform(p90)-transform(p10)), 0, 1)
    ```

    反向指标用 `100-normalized`。当 `transform(p90)=transform(p10)` 时不得除零：该指标标记 `benchmark_no_dispersion` 并从评分权重中移除；若业务策略明确允许中性降级，可返回 50 分但必须降低证据置信度并记录该策略。无外部基准时，候选集合必须达到最小样本数，并标记该批分数不可跨批直接比较。竞争压力公式中的五个输入也必须先按同一规则转为 `[0,100]` 的 `normalized_*` 子分，不能把计数、评分和比例直接相加。
11. **机会分与决策**：所有维度和子指标分数必须先转为 `[0,100]`，方向统一为“越高越好”并执行 `clip(0,100)`。缺失维度满足覆盖门槛时使用 `effective_weight_i = configured_weight_i / Σobserved_configured_weight`，否则候选进入 `hold`。`opportunity_score = Σ(dimension_score × effective_weight)`。建议 `pass` 且分数 ≥75、`evidence_confidence ≥0.70` 为 `prioritize`；60～75 或高分低置信为 `validate`；低于 60 为 `deprioritize`。并列时依次比较保守情景贡献利润、证据置信度、合规风险、敏感性稳定度，最后按 `candidate_id` 升序保证稳定结果。
12. **置信度不是成功概率**：综合证据覆盖、新鲜度、样本量、来源可靠度、多来源一致性和插补惩罚。只有一个来源时不伪造一致性。
13. **敏感性分析**：逐一把维度权重上下浮动 20%，并对售价、广告、退货、需求执行输入给定的低/基准/高情景；输出分数区间、决策稳定度和 Top K 排名稳定度。未经用户提供分布不运行随机 Monte Carlo。
14. **可审计解释**：输出每项原始值、变换值、标准分、权重、基准、证据和门禁原因；解释由结构化结果模板生成，不让 LLM 重新判断或篡改分数。

### 5.4 输出

| 变量名 | 类型 | 说明 |
| --- | --- | --- |
| `evaluation_id` | `string` | 本次评估稳定 ID。 |
| `policy_version` | `string` | 实际使用的策略版本。 |
| `ranked_candidates` | `list<object>` | 仅硬门禁通过的正式排名。 |
| `held_candidates` | `list<object>` | 因证据、利润或合规未确认而待审核的候选。 |
| `rejected_candidates` | `list<object>` | 硬门禁失败候选及原因。 |
| `portfolio_summary` | `object` | 各决策数量、Top 候选、共同风险和数据覆盖。 |
| `data_quality_report` | `object` | 缺失率、过期率、插补率、来源冲突和隔离指标。 |

每个候选至少输出 `gate_results`、`decision`、`rank`、`opportunity_score`、`evidence_confidence`（范围 `[0,1]`）、`dimension_scores`、利润摘要、`score_min/max`、决策/排名稳定度、正负驱动项、缺失字段及证据引用。

### 5.5 业务结果与错误码

`INVALID_POLICY`、`DUPLICATE_CANDIDATE`、`UNIT_MISMATCH`、`FX_MISSING`、`BENCHMARK_INSUFFICIENT`、`COST_INSUFFICIENT`、`COMPLIANCE_UNKNOWN`、`LOW_EVIDENCE_COVERAGE`、`METRIC_OUT_OF_RANGE`、`SOURCE_UNAVAILABLE`、`ALL_CANDIDATES_GATED`。

## 6. 节点 6：竞品商品采集

**执行粒度**：单平台、单站点、单类目/研究主题的一次竞品集合构建  
**节点边界**：发现、采集、归一、去重和筛选可比较商品；不直接做策略判断，不把销量估算或排名快照当成长期事实。

### 6.1 输入

| 变量名 | 类型 | 必填 | 说明与约束 |
| --- | --- | --- | --- |
| `platform` | `string` | 是 | `amazon` 或 `tiktok_shop`。 |
| `marketplace` | `string` | 是 | 明确站点/国家，不允许只传平台名。 |
| `discovery_mode` | `string` | 是 | `keyword`、`category`、`seed_product` 或 `mixed`。 |
| `keywords` | `list<object>` | 条件必填 | 每项含查询词、语言和可选权重。 |
| `category_id` | `string` | 条件必填 | 类目模式下的平台有效类目 ID。 |
| `seed_products` | `list<object>` | 条件必填 | 种子商品 ID/URL，以及可选标准商品事实。 |
| `collection_scope` | `object` | 是 | 单次来源的最大候选数、页数上限、字段范围、评论/媒体采样范围；不重复承载最终目标竞品数。 |
| `filters` | `object` | 否 | 品牌排除、价格范围、履约方式、是否排除配件/翻新/不同比例套装等。 |
| `market_context` | `object` | 否 | 语言、币种、非个性化地域上下文和搜索排序。 |
| `credential_ref` | `string` | 否 | 授权凭证引用，不传明文 Token。 |
| `existing_snapshot` | `object` | 否 | 可复用历史快照，必须包含采集时间、来源和版本。 |

`keywords`、`category_id`、`seed_products` 至少满足一个。

### 6.2 业务配置

| 配置项 | 类型 | 建议默认值 | 说明 |
| --- | --- | --- | --- |
| `entity_level` | `string` | `parent_listing` | 可选 `marketplace_item`、`variant`、`offer`，决定父子体和多 Offer 合并粒度。 |
| `target_count` | `integer` | `30` | 最终目标竞品数的唯一配置源；“Top 30”是模板默认值，不是节点硬上限。实际采用值回传至 `collection_summary.requested_count`。 |
| `candidate_oversampling` | `float` | `3.0` | 先扩大候选池再筛同类性，避免过滤后样本不足。 |
| `include_sponsored` | `boolean` | `true` | 广告位与自然位必须分开标记。 |
| `freshness_policy` | `object` | 版本化配置 | 价格、库存、排名的 TTL 短于静态属性。 |
| `comparability_threshold` | `float` | `0.75` | 直接竞品最低同类性；需按类目校准。 |
| `uncertain_candidate_policy` | `string` | `review` | 低置信候选进入相邻竞品、排除或人工复核。 |
| `evidence_level` | `string` | `field` | 关键字段建议字段级证据。 |
| `adapter_version` | `string` | 固定稳定版本 | 页面/API 结构变化时可追溯并可停止错误适配器。 |

### 6.3 处理逻辑

1. **生成采集计划**：校验平台、站点和发现条件；规范化查询但保留原词。种子商品先解析商品类型、核心用途和关键规格，再生成同类搜索条件。混合模式为关键词、类目和种子分配配额，防止一个宽泛查询占满结果。
2. **合法、受控的数据访问**：只使用官方、授权或明确允许的来源，遵守访问控制和速率限制，不设计验证码/登录绕过。网页文字、评论等全部视为不可信数据，不作为节点指令执行。
3. **构造过采样候选池**：分别保留自然搜索、广告位、类目榜单和相似商品推荐等 `discovery_channel`；每次出现记录查询、页码、排名、站点和时间。排名仅代表该搜索上下文的时点快照。
4. **实体级去重**：先按平台、站点、商品/父体/变体/Offer ID 去重；跨查询命中的同一商品只保留一个主体，所有命中位置进入 `discovery_occurrences`。近重复仅按品牌型号、规格、包装量、标题指纹和主图感知哈希分组，证据不足不强行合并。
5. **同类性筛选**：不能只比较标题相似度。综合目标类目/商品类型、核心用途、功能、材质、规格、适用人群、商品角色、包装量、单位价格和视觉主体，输出：

   ```json
   {
     "score": 0.82,
     "tier": "direct|adjacent|excluded|uncertain",
     "reasons": ["same_product_type", "different_pack_size"],
     "missing_evidence": ["material"]
   }
   ```

   `direct` 用于价格和内容基准，`adjacent` 只用于定位和需求探索。不能为凑够 30 个而把不相干商品标成直接竞品。
6. **采集字段并统一口径**：采集标题、品牌、类目、价格及适用条件、评分/评论数、规格、变体、包装量、媒体、履约和公开经营信号。会员价、优惠券、订阅价和卖家折扣必须保留条件，不能只取最低数字。
7. **经营信号真实性分层**：销量、GMV 等若不是平台直接公开字段，只能以 `estimated` 输出，附算法、区间和置信度；无可靠来源则不输出。未知库存或销量不能写成 0。
8. **评论和媒体采样**：评论只保留研究所需内容、时间窗、语言和样本量，不采集评论者个人标识。图片/视频返回 URL、角色、哈希和元数据，不把二进制塞入工作流。
9. **字段级时效和冲突**：每个易变值包含 `observed_at`、`observed/derived/estimated`、证据 ID 和置信度。缓存超出 TTL 时只有显式允许才能降级使用，并标记 `stale`。不同日期的价格/排名不得拼成同一时点。
10. **质量门禁**：统计候选数、去重数、直接/相邻竞品数、关键字段覆盖率、新鲜率、同类性分布、查询覆盖和失败范围。直接竞品不足时返回 `partial` 和局限性，不降低阈值伪造完整结果。

### 6.4 输出

| 变量名 | 类型 | 说明 |
| --- | --- | --- |
| `competitor_set_id` | `string` | 由平台、站点、研究条件、时间及方法版本生成的集合 ID。 |
| `competitors` | `list<object>` | 去重后的竞品，包含商品事实、公开信号、发现位置、同类性、新鲜度和证据。 |
| `excluded_candidates` | `list<object>` | 被排除的候选及原因码。 |
| `collection_summary` | `object` | 请求、候选、去重、直接/相邻/排除数量和采集时间。 |
| `data_quality` | `object` | 关键字段覆盖、新鲜率、冲突数、置信度和限制。 |

每个 `competitors[]` 至少包含平台商品/父体/变体 ID、URL、品牌标题、类目、条件化价格、评分及评论数、属性、变体摘要、卖点、媒体、公开信号、`discovery_occurrences`、`comparability`、`freshness` 和证据 ID。

### 6.5 业务结果与错误码

`INVALID_DISCOVERY_INPUT`、`TARGET_AMBIGUOUS`、`AUTH_MISSING`、`SOURCE_NOT_ALLOWED`、`RATE_LIMITED`、`SOURCE_UNAVAILABLE`、`SOURCE_SCHEMA_CHANGED`、`PRODUCT_PARTIAL`、`INSUFFICIENT_COMPARABLES`、`CACHE_STALE`、`COLLECTION_TIMEOUT`。

输入契约整体无效、授权失败和来源禁止类错误进入异常分支；429、超时和 5xx 才有限重试；`INSUFFICIENT_COMPARABLES`、过期缓存降级、超时或个别商品失败可返回 `needs_review/partial`、已完成部分及未完成范围。

## 7. 节点 7：竞品对标分析


**执行粒度**：一个自有商品对一个可比较竞品集合  
**节点边界**：生成证据化 Benchmark、差距和行动机会；不重新采集竞品、不承诺点击率/转化率提升，也不复制竞品受保护的图片、视频或品牌表达。

### 7.1 输入

| 变量名 | 类型 | 必填 | 说明与约束 |
| --- | --- | --- | --- |
| `own_product` | `object` | 是 | 自有商品事实、Listing、变体、媒体和价格；未知字段保持未知。 |
| `competitors` | `list<object>` | 是 | 建议直接使用节点 6 的输出，必须带同类性、新鲜度和证据。 |
| `market_context` | `object` | 是 | 平台、站点、语言、币种和类目。 |
| `analysis_objective` | `string` | 是 | 如 `new_product_positioning`、`listing_conversion`、`content_gap`、`pricing`。 |
| `keyword_evidence` | `list<object>` | 否 | 关键词、来源、搜索量/趋势和时间；无来源时只能分析覆盖，不能声称热度。 |
| `review_evidence` | `list<object>` | 否 | 评论主题、样本量、时间窗和证据。 |
| `own_performance` | `object` | 否 | 自有曝光、CTR、CVR、退货等，必须定义统计窗口和口径。 |
| `business_constraints` | `object` | 否 | 商品不可改变的事实、成本、品牌定位、素材能力和禁止声明。 |

### 7.2 业务配置

| 配置项 | 类型 | 建议默认值 | 说明 |
| --- | --- | --- | --- |
| `peer_policy` | `object` | 直接竞品为统计基准 | 相邻竞品仅用于定位/趋势探索。 |
| `freshness_policy` | `object` | 版本化配置 | 价格、排名、内容和评论分别定义最大时效。 |
| `normalization_policy` | `object` | 当前稳定版本 | 币种、单位、包装量和变体层级统一规则。 |
| `benchmark_statistics` | `list<string>` | `median,p25,p75,top_quartile` | 避免只看最大值或简单平均。 |
| `feature_rubric_version` | `string` | 固定版本 | 文本、图片、视频、变体和评论特征定义。 |
| `missing_value_policy` | `string` | `skip_and_lower_confidence` | 未知值不按 0 处理。 |
| `priority_policy` | `object` | 分档规则 | 输出行动优先级，而非虚假精确 ROI。 |
| `compliance_guardrail` | `boolean` | `true` | 过滤无法证明、潜在侵权或违规建议。 |

### 7.3 处理逻辑

1. **重建可比 Cohort**：重新校验平台、站点、类目、时间和同类性，将商品分为 `direct_peers`、`adjacent_peers` 和 `excluded`。Amazon 与 TikTok Shop、不同站点和不同商品类型分别建基准，不能直接混算。
2. **统一单位和比较层级**：把价格转换成同币种、同包装量的单位价格；把父体、变体或 Offer 调整到同一比较层级。无法可靠换算的特征标记 `not_comparable`，禁止直接比较原始数字。
3. **构造带证据特征**：每个特征同时输出值、`observed/derived/inferred`、证据、置信度和是否可比。特征覆盖：
   - 商品/Offer：功能、材质、规格、包装量、变体、价格、履约和证明材料；
   - 搜索/文本：标题结构、关键词覆盖、卖点结构、属性完整度、重复与不可证实声明；
   - 图片/视频：数量、分辨率、主体占比、图片角色、OCR 信息、真实演示、使用场景；
   - 评论：主题频率、正负向、严重度、时间趋势和是否可由卖家控制；
   - 经营信号：评分、评论数、公开排名和互动数据，全部带观察时间。
4. **把主观判断改为 Rubric**：例如“图片高级”不能直接作为特征，应拆成清晰度、背景一致性、场景覆盖、信息层级、文字可读性等可复核指标；视觉结论引用具体 `asset_id`，视频引用时间片段。
5. **评论聚类质量控制**：模型可以归纳主题，但每个主题必须保留样本数、占比、严重度、时间窗口和代表性证据。单条评论、小样本或陈旧评论不能上升为普遍需求。
6. **稳健 Benchmark**：默认用直接竞品的中位数、P25/P75 和头部四分位。每个特征输出样本数和覆盖率，缺失值不参与分母；小样本只输出范围和低置信度，不输出貌似精确的百分位。
7. **按特征方向解释**：区分“越高越好”“越低越好”和“合理区间”。标题长度、价格等区间型指标不得按越高越好处理。可选综合分只称“启发式指数”，不能解释为转化率。
8. **差距分类**：将差距明确分成 `fact_gap`、`content_gap`、`proof_gap`、`offer_gap`、`product_gap`、`customer_need_gap` 和 `unknown_data_gap`。数值差距只在同口径数据上计算；定性差距使用等级和证据，不伪造小数精度。
9. **机会生成约束**：每条机会必须有明确差距、需求或竞品证据、自有商品可实施/可证明、无合规或知识产权冲突，并说明作用机制。不能因为竞品普遍使用某声明就建议直接复制。
10. **透明优先级**：分别输出 `impact_level`、`evidence_strength`、`feasibility`、`effort`、`risk`，再按规则生成：
    - `P0`：高影响、高证据、可实施且风险可控；
    - `P1`：高影响但需补证，或中影响高证据；
    - `P2`：探索实验、长期产品改进或继续观察。
11. **需要实验的建议**：输出实验假设、主指标、守护指标、最短数据窗口和停止条件；不能把相关性写成因果承诺。
12. **置信度和局限**：综合直接竞品样本、字段覆盖、新鲜度、同类性、多来源一致性和模型提取质量。结论必须明确局限，例如“图片覆盖差距证据较强，但缺少自有 CTR，无法判断实际点击率提升幅度”。

可选的行动优先级计算应保持可解释：

```text
priority_signal =
  gap_importance × gap_severity × evidence_strength × feasibility
```

四个乘数都必须先映射到 `[0,1]`：`gap_importance` 来自版本化差距类型策略，`gap_severity` 来自同口径差距 Rubric，`evidence_strength` 来自覆盖/样本/新鲜度，`feasibility` 来自能力与约束核验。展示用 `severity_score = 100 × gap_severity`，不得把 `[0,100]` 值直接代入乘法。计算结果只用于排序，最终仍输出各乘数和分档，不宣称预测收益。

### 7.4 输出

| 变量名 | 类型 | 说明 |
| --- | --- | --- |
| `analysis_summary` | `object` | 直接/相邻竞品数、目标、整体置信度、关键发现和局限。 |
| `benchmarks` | `list<object>` | 维度、特征、样本数、覆盖率、中位数/分位数、单位、置信度和证据。 |
| `dimension_results` | `list<object>` | 自有值、基准、`behind/parity/ahead/unknown`、差距严重度和证据。 |
| `gaps` | `list<object>` | 差距 ID、类型、描述、影响对象、严重度和证据。 |
| `opportunities` | `list<object>` | 建议动作、作用机制、P0/P1/P2、影响、证据、可行性、成本、风险和依赖。 |
| `data_quality` | `object` | 样本量、字段覆盖、新鲜度、模型抽取质量及不可比较项。 |

### 7.5 业务结果与错误码

`INVALID_ANALYSIS_INPUT`、`OWN_PRODUCT_INCOMPLETE`、`COMPETITOR_SET_EMPTY`、`INSUFFICIENT_DIRECT_PEERS`、`DATA_STALE`、`UNIT_NOT_COMPARABLE`、`CURRENCY_UNRESOLVED`、`EVIDENCE_COVERAGE_LOW`、`MODEL_EXTRACTION_FAILED`、`UNSUPPORTED_MARKETPLACE`。

结构整体不可解析和不支持站点进入异常分支。上游合法返回空竞品集合时，`COMPETITOR_SET_EMPTY` 是 `needs_review` 业务结果；直接竞品不足、数据过期或单个维度失败时继续可执行维度并返回 `partial`。模型失败可退回规则特征，不能用模型臆测值补齐。

## 8. 节点 8：成本利润与定价测算

**执行粒度**：商品/SKU × 平台履约情景 × 价格情景  
**节点边界**：建立可审计的单位经济模型、盈亏平衡点和可行价格带；不预测销量，不替代税务、海关或法律意见。没有价格弹性数据时不输出“唯一最优售价”。

### 8.1 输入

| 变量名 | 类型 | 必填 | 说明与约束 |
| --- | --- | --- | --- |
| `product_cost_profile` | `object` | 是 | 仅包含 SKU、包装尺寸/重量、原产地和数量等非金额商品事实；不承载采购或物流成本。 |
| `market_context` | `object` | 是 | 平台、站点、目的国、结算币种和计算时间。 |
| `fulfillment_scenarios` | `list<object>` | 是 | Amazon FBA/FBM、TikTok 平台履约/商家履约等情景及参数。 |
| `pricing_input` | `object` | 是 | 当前/候选价格或搜索区间，以及折扣、补贴、买家运费和含税口径；字段定义见下文。 |
| `cost_items` | `list<object>` | 是 | 采购、头程、清关、包装、仓储、广告、联盟、退货等金额/费率的唯一权威输入。 |
| `fee_policy_refs` | `list<object>` | 条件必填 | 平台佣金、交易、履约和仓储规则引用、版本及有效期。 |
| `exchange_rates` | `list<object>` | 条件必填 | 多币种时必须提供或由授权服务获取，包含汇率时间和来源。 |
| `tax_profile` | `object` | 条件必填 | 含税市场、VAT/GST/销售税或进口税参与时提供。 |
| `customs_profile` | `object` | 否 | HS 编码、原产地、目的地、税基和规则引用。 |
| `competitor_price_context` | `object` | 否 | 节点 7 的直接竞品单位价格带、样本量、同类性和新鲜度。 |
| `target_metrics` | `object` | 否 | 目标贡献率、完全成本利润率、ROI、最大广告率等。 |
| `uncertainty_ranges` | `list<object>` | 否 | 汇率、运费、广告、退货等驱动的低/基准/高值；每个驱动独立一项。 |
| `volume_assumptions` | `object` | 否 | 月销量、批量和仓储月数；完全成本分摊时必需。 |

`pricing_input` 必须显式区分：`gross_item_price`（折扣前商品价）、`seller_funded_discount`、`platform_funded_buyer_discount`、`seller_receivable_platform_subsidy`、`buyer_shipping_charge`、`buyer_tax_if_exclusive`、`tax_included` 和可选 `buyer_paid_amount_observed`。计算权威顺序是先由前述分项推导买家支付与卖家结算前收入，再用观察值做校验；观察值与推导值不一致时返回冲突，不能覆盖公式。只有明确结算给卖家的补贴才进入卖家收入，买家折扣与卖家应收补贴不得用同一个金额重复计入。

`cost_items[]` 必须声明 `cost_item_id`、`cost_code`、金额/费率、币种、`per_unit/per_order/per_shipment/per_period/percent_of_revenue` 计费基础、数量、卖方是否承担、时间、来源和置信度。对同一 `sku_id + scenario_id + cost_code + basis + effective_period` 只允许一个 canonical 成本项；如 Policy Store 与自定义输入同时命中，默认视为 `DOUBLE_COUNT_RISK`，除非显式 `override_of_cost_item_id` 且审计记录允许覆盖。未知成本不能用 0 代替。

| --- | --- | --- | --- |

| `tax_mode` | `string` | 必须显式选择 | 含税价拆税、税额另加或不计间接税。 |

| `currency_policy` | `object` | 明确来源和最大时效 | 结算汇率、计划汇率或现货汇率不能混用。 |
| `allocation_policy` | `object` | 按成本项配置 | 批次/周期费用按件数、重量、体积或销量分摊。 |

### 8.3 处理逻辑

1. **统一口径**：统一重量、尺寸、体积、包装量和货币；明确价格是否含税、折扣、补贴和运费由谁承担；标注每个成本的计费基础。以 `cost_items` 为所有金额/费率成本的唯一来源，检查广告费是否同时以固定金额和费率重复输入，以及退货损失是否重复包含退款本金。
2. **场景可计算性检查**：FBA/平台履约缺少包装尺寸或重量时，不猜测尺寸档，只让该情景失败；完全成本模式缺少销量/分摊数量时仍可输出贡献利润，但完全成本利润为未知。
3. **动态规则解析**：按计算时间匹配平台佣金、交易/支付费、履约费、仓储费、最低/封顶/阶梯费、退款后费用返还、补贴和卖家折扣。每个费用项输出 `rule_id/version/effective_from/formula/basis`。规则重叠或断档时停止该情景。
4. **履约情景分账**：
   - Amazon FBA：采购、头程、准备/入仓、尺寸档、计费重量、履约、仓储、退货分开列账；
   - Amazon FBM：仓库操作、包装、承运服务区、尾程、附加费、买家运费收入和退货分开；
   - TikTok Shop：平台佣金、交易费、联盟佣金、卖家折扣、平台补贴和履约/运费规则分开。

   同一费用不得同时出现在 Policy Store 和自定义成本中，节点执行 `double_count_check`。
5. **汇率、税费与关税**：保留原币、换算币、汇率、日期和来源；含税售价按卖家税务身份拆出代收/应付税额，代收税不算收入。关税需要明确 HS 编码、原产地、目的地和税基；不完整时输出未决项，不能给伪精确税额。
6. **建立单位经济账本**：对每个 SKU、履约情景和价格 `P` 逐项计算：

   ```text
   buyer_paid_amount =
       gross_item_price
     - seller_funded_discount
     - platform_funded_buyer_discount
     + buyer_shipping_charge
     + buyer_tax_if_exclusive
   
   卖家结算前收入 =
       buyer_paid_amount
     + seller_receivable_platform_subsidy
   
   净收入 =
       卖家结算前收入
     - 代收/应付间接税
     - 预期退款收入
   
   净落地商品成本 =
       采购 + 头程 + 关税/清关 + 包装/准备
     - 可恢复退货库存价值
   
   净平台与履约费 =
       平台佣金 + 交易费 + 履约费 + 仓储费
     - 可返还平台费用
   
   获客与促销成本 = 广告 + 联盟佣金 + 优惠券成本
   
   贡献利润 =
       净收入
     - 净落地商品成本
     - 净平台与履约费
     - 获客与促销成本
     - 退货处理损失
     - 其他变动成本
   
   完全分摊利润 = 贡献利润 - 每件分摊固定成本
   ```

   贡献/完全成本利润率的分母为净收入；分母非正时省略该利润率字段，并在情景 `issue_codes` 中返回 `NON_POSITIVE_MARGIN_DENOMINATOR`。ROI 同时输出明确分母定义。
7. **盈亏平衡求解**：至少求贡献盈亏平衡价、完全成本盈亏平衡价、目标利润率最低价、周期固定成本对应的盈亏平衡销量，以及可承受最大广告率。平台费用存在最低费、阶梯、舍入和尺寸档时，不使用简单线性公式：先按规则断点扫描，再在符号变化区间二分求根，对每个根重新跑完整费用规则。
8. **可行价格带**：

   ```text
   economic_floor = max(贡献盈亏平衡价, 目标利润率最低价, 促销后底价)
   allowed_price_domain = 用户搜索范围 ∩ 平台允许价格范围
   economic_band = allowed_price_domain 中满足经济底线的区间
   market_band = 同站点、同类、同包装量、新鲜直接竞品的观察单位价格区间
   benchmark_overlap = economic_band ∩ market_band
   ```

   `economic_band` 为空才输出 `no_feasible_price`，表示在用户/平台允许的价格域内没有满足经济约束的解。仅 `benchmark_overlap` 为空时输出 `no_benchmark_overlap` 和 `validate` 建议：观察到的竞品带不是消费者支付意愿硬上限，差异化、包装量或高端定位仍需价格弹性/支付意愿实验。只有输入策略给出硬性最高可接受价时，该上限才进入 `allowed_price_domain`。无竞品价格时只给经济底线；无价格弹性时给区间及待测试价点，不声称唯一最优价。
9. **敏感性分析**：使用输入的低/基准/高值，分别改变售价、汇率、头尾程、履约费、广告率、联盟佣金、退货率、恢复率、仓储月数和销量；输出利润、盈亏平衡价及是否跨过目标利润线。未提供范围时返回 `sensitivity_not_run`，不能自行编造波动或概率。
10. **置信度与审计**：由成本覆盖率、费用规则有效性、汇率新鲜度、税费口径、类目/尺寸档确定性、历史退货/广告假设以及竞品价格可比性共同决定。置信度代表输入/规则可靠度，不是未来盈利概率。保存输入哈希、公式版本、规则/汇率版本、中间值、舍入和人工覆盖原因。

### 8.5 业务结果与错误码

`REQUIRED_COST_MISSING`、`UNIT_INVALID`、`FEE_POLICY_NOT_FOUND`、`FEE_POLICY_AMBIGUOUS`、`FEE_POLICY_EXPIRED`、`SIZE_TIER_UNRESOLVED`、`FX_MISSING`、`FX_STALE`、`TAX_PROFILE_AMBIGUOUS`、`DOUBLE_COUNT_RISK`、`CALCULATION_NON_CONVERGENT`、`NO_BENCHMARK_OVERLAP`、`NO_FEASIBLE_PRICE`、`PARTIAL_SCENARIO`、`SOURCE_UNAVAILABLE`。

按情景隔离错误：FBA 失败时可继续 FBM/TikTok 情景，只要至少一个情景有效就返回 `partial`。输入错误、规则冲突和重复计费风险不重试；费率/汇率服务的超时、429、5xx 才有限重试。`NO_BENCHMARK_OVERLAP` 与 `NO_FEASIBLE_PRICE` 都是业务结果，不是系统异常。
