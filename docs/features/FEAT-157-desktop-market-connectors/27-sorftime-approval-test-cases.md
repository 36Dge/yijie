# FEAT-157 连接器审批测试用例

2026-11-23 · 待评审 · **全部 22 条用例均未执行**

验收对象为「请求批准」「帮我批准」「完全访问」、原生工具授权的保存与撤销，以及 Sorftime 的轮次授权续期。TC-06 验证真实冷启动后的第一笔调用，TC-14 验证轮次续期和单笔许可的不同寿命。P0 用例覆盖本次需求的主要验收条件，P1 用例覆盖兼容、显示与操作边界。

## 数据与计数

- 桌面场景使用独立测试数据、可用的 MiniMax-M3 和 Kimi K3.1 Pro，以及已启用并完成工具发现的 Sorftime 测试安装。每条用例和各独立分支从没有对应规则的状态开始，再建立该用例指定的授权。需要业务查询时只选择 Sorftime。
- 基准查询 **Q** 为 `product_search`，参数为 `{"amz_site":"US","search_name":"outdoor"}`。可在聊天中输入「只使用 Sorftime 的 product_search，查询美国 Amazon 上关键词 outdoor 的商品，调用一次」。执行时按实际工具名和参数核对。换站点使用 `GB`。同站点换工具使用 `category_name_search`，参数为 `{"amz_site":"US","category_name":"outdoor"}`。
- 表中的次数均指**该操作引起的 Sorftime 业务查询增量**。审批卡、模型请求、连接时的初始化与工具发现分别记录。每笔核对原生回执中的 `serviceId=sorftime`，将工具 Item、`callRef`、决定来源及 `admissionConsumed` 与业务接收记录关联。桌面实连可用 Sorftime 测试账号的请求明细核对次数。独立计数不可得时，该断言标为「待核验」。
- 受控时钟用例使用仓库已有的 Sorftime `product_search` schema 和进程内查询端，沿生产 Worker 的登记、决定与消费路径计数。Guardian 分支使用真实原生审核流程，可用回环审核模型稳定给出允许或拒绝。记录中分别注明「Sorftime 实连」「Sorftime 本地协议样本」或「仅界面／契约」。
