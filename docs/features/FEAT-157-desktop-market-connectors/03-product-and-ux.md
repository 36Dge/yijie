## 3. 信息结构与页面布局

### 3.1 导航与主页面

“连接器”取代原“资料库”菜单位置。页面标题“连接器”，说明“连接外部应用与服务，在对话中使用已启用的连接器。”导航图标、标题操作图标走 `YjIcon` registry；既有“插件”菜单仍表示 Skill 广场，不改为 MCP 入口。

主页面使用市场、已安装两个 tab。市场六组分类，每组标题显示真实数量，卡片默认三列；名称、应用图标、两行内描述、单一状态/操作标识构成卡片。卡片主体及其加号均打开同一个详情弹窗。实现宜用一个主 button 包含所有展示内容，避免“整卡 button 内嵌加号 button”。异常信息超过卡片容量时显示简短原因与“查看详情”，完整修复动作在弹窗内。

已安装为单列表，不出现“自定义/市场”二级分类。每行显示图标、名称、描述、状态、switch、卸载。市场使用加号表示未安装、空心连接状态表示已安装未启用、勾选表示已启用；所有图形都有对应可访问文本，不能只靠形状或颜色。

页面支持名称/描述搜索；无匹配显示“没有找到匹配的连接器”和“清空搜索”，不伪装成目录为空。搜索是本地展示筛选，不触发第三方请求。已安装计数与当前筛选无关。原始描述缺失时使用经核实的简短能力说明，不编造服务权限、工具数、收费或支持范围。

### 3.2 安装/配置弹窗

弹窗结构为易界 Logo 与应用图标、名称和描述、能力与数据访问说明、当前状态、必要配置/修复说明、底部操作。正文可滚动，关闭与底部主操作在最小窗口内可达。标题随阶段变化：安装、已安装但未启用、正在连接、配置连接器、连接未完成；不能连接中仍显示“已启用”。

PDF 的三段通用说明适配为事实性文案：

- “扩展对话能力”：仅描述已核实的服务能力，不承诺自动完成未提供的工具。
- “遵循当前权限设置”：调用继续遵循易界有效权限和审批策略；不承诺每次必弹审批，也不把 OAuth 同意等同所有业务操作批准。
- “随时管理连接”：可停用或卸载本机登记；若服务不支持撤销远端授权，要明确区分本机停用与服务端撤销。

## 4. 四个相互独立的产品状态

| 维度 | 含义 | 不意味着 |
|---|---|---|
| 已安装 | 当前作用域已登记该目录应用 | 已授权、已配置、已启用或已执行 |
| 授权/配置就绪 | 所需授权、凭据和运行依赖已满足当前可验证要求 | 自动开启服务，或审批过业务写操作 |
| 全局已启用 | 该作用域允许把此连接器用于后续普通对话选择 | 所有线程自动挂载所有服务、所有工具自动获批 |
| 本轮已选择 | 草稿对本次提交携带明确 connector refs | 变更全局启用、修改已提交历史或恢复失效授权 |

市场、已安装列表、聊天弹层读取同一权威状态。UI 不以先置 switch 为 true 的乐观副本宣告成功；可以显示“正在开启/关闭”，但必须以完成响应或重新读取为终态。全局启用与实际连接可用性分开展示，服务临时不可达时可显示“已启用 · 暂不可用”，不因一项短暂故障抹掉安装和用户选择意图。

本轮空选集明确表示不使用市场中的 51 个连接器工具，已有原生工具按原有规则保持。后续每轮默认空选，不自动继承上一轮或全部已启用服务。首期在单一本地 identity 下每个应用只允许一个账户连接；“更换账户”必须显式停用并重新授权。每次账户/授权实例替换产生新的 connection generation；旧草稿中的同名引用不能自动指向新的账户，须标记“连接已变更，请重新选择”，已提交历史不随新账户改写。

## 5. 安装、授权、启停和卸载

### 5.1 主流程

1. 用户从市场打开应用详情，查看能力/权限说明，点击“安装 XXX”。操作期间禁止对同一项重复安装。
2. 登记完成后，安装数增加，弹窗留在“XXX 已安装但未启用”，主按钮变为“启用 XXX”。安装不自动打开浏览器、不读取第三方业务数据、不运行 stdio 工具。
3. 启用根据目录能力进入 OAuth、配置凭据、本地依赖检查或真实无认证连接分支。UI 只渲染技术边界给出的所需配置，不执行材料中的 shell 命令。
4. OAuth 分支显示“请在浏览器中完成授权”，提供“重新打开授权页面”和“取消连接”。授权成功且运行能力验证满足要求后，权威状态转为已启用，弹窗关闭，市场勾选与已安装 switch 同步更新。
5. 用户从聊天入口选择已启用应用，输入具体任务，发送后进入既有 Codex 执行/审批/结果链路。选择连接器本身不进行第三方业务调用。

### 5.2 不同接入方式的交互

| 方式 | 启用操作 | 缺失/拒绝/取消后的状态 |
|---|---|---|
| 标准 OAuth | 点击启用才创建授权操作并打开系统浏览器；展示安全的服务名称/目标域，不显示 token、完整 callback 或动态参数 | 保留已安装且未启用；显示拒绝、取消、过期或可重试错误；用户可再次启用 |
| 凭据配置 | UI展示明确字段标签和来源说明；实际秘密输入通过经评审的原生/Connectors安全入口，Renderer不接收原文；保存后验证，不回显已存secret | 缺字段聚焦字段；失败保留非敏感输入，secret 生命周期按安全设计处理；可取消，服务不被启用 |
| 本地 stdio | 展示依赖与凭据是否就绪；正常启动受管进程，成功后才开启 | 缺依赖/凭据给出可执行恢复说明；不能以安装卡片成功代替进程/工具可用 |
| 易界尚未支持的网关/身份方案 | 已安装项显示“接入配置待完成”，说明缺少易界自己的接入条件 | 不借用其他应用网关身份、client_id 或回调；不能显示“已连接”；逐服务验收保持未通过 |
| 经验证无需额外授权 | 点击启用执行正常连接就绪检查 | 无凭据提示不代表免费或任意工具免审批；失败使用同一恢复路径 |

认证步骤仅服务于用户主动启用的连接器。`demo_fast + local` 进入易界本身仍为免登录；不能因为第三方需要登录就要求所有用户每次启动易界先完成浏览器认证。

### 5.3 关闭、取消、超时与迟到结果

连接中提供与 PDF 一致的“断开”含义，产品文案优先“取消连接”，明确只取消当前未完成操作。取消确认成功后关闭弹窗，toast “连接已取消，服务未启用”，保留安装。若已经接通的服务停用成功，则 toast “服务已停用”。避免在取消结果未知时显示“服务已禁用”。

关闭弹窗只关闭展示，不等同撤销已经进入第三方页面的授权；操作仍可从该项恢复查看。连接中关闭按钮有明确可访问说明；需要取消时使用“取消连接”。取消、停用、卸载、切换作用域都必须使旧授权操作失去完成权限。迟到 callback、重复 callback、旧窗口成功页只能触发权威状态复核，不能恢复取消后的启用状态。

发生超时或完成状态不确定时显示“正在确认连接状态”，先按 operation ID 查询/刷新；不得自动新建第二次授权、重复打开浏览器或将未知伪装成失败。用户显式重试仍复用既有状态/幂等语义；若旧操作已终止才可创建新的授权意图。

### 5.4 启停、卸载与并发

| 场景 | 产品行为 |
|---|---|
| 开启已配置但停用项 | 正常验证并开启；必要时重授权，不重复安装 |
| 关闭已启用项 | 行级 pending，禁止同一项重复反向切换；权威关闭后 switch 关闭、待发送引用失效；其他连接器不被一起关闭 |
| 正在连接时关闭 | 取消该授权操作，保留安装；取消结果未知则保留可恢复状态 |
| 点击卸载 | 展示名称、将删除本机登记/所管配置的影响；确认后停用并清理该项；取消不改变任何状态 |
| 当前草稿引用此项 | 卸载/停用前提示会使未发送的引用不可用；完成后在相关草稿标记不可用并提供移除，发送前不得静默忽略 |
| 有正在执行的调用 | 展示当前执行可能尚在完成；后续新派发被禁止。复用正常取消/中断承接，不强杀进程，不承诺已执行副作用被撤回 |
| 同时从管理页与聊天弹层操作 | 以同一 operation/revision 校验；冲突刷新权威状态并解释，不能最后一次 UI 覆盖服务器事实 |
| 卸载失败或清理待恢复 | 列表保留记录和明确状态；给出继续清理/重试，不假装卸载完成再偷偷恢复 |
| 重装 | 使用同一稳定目录 ID，重新建立安装意图；不会恢复被清除的秘密或自动开启；旧历史只读保留 |

卸载确认是产品内对本机配置影响的正常交互，不能替代第三方业务操作审批。是否撤销第三方 token、是否保留非敏感配置、清理范围与失败恢复由安全/技术设计冻结，并在弹窗如实展示。

## 6. Composer 入口、本轮选择与草稿

### 6.1 入口和弹层

入口位于输入框内部操作区的“关联店铺”右侧；工作空间、权限入口仍位于现有底座下方，不把连接器挪到设置栏、附件菜单或页面头部。新任务和普通会话均提供入口；补图位置是本次明确约束。

弹层标题“连接器”，列出当前已安装项，应用图标与名称、待配置/需重授权/不可用 badge、全局 switch、底部“管理连接器”。可搜索已安装应用；列表局部滚动，管理操作保持可达。空态为“还没有安装连接器”与“管理连接器”，不把市场 51 项全部当作已安装显示。Beta 标记仅在产品明确保留试用标识时显示，不能用它掩盖必须完成的接入。

行本体与 switch 是两个并列控件：

- 点击已启用且可用的行，切换本轮选中状态；弹层可保持开启以便继续选择，显示独立勾选标记。
- 点击待配置/停用项的行，进入该项配置/启用详情；不自动把不可用项放进可发送集合。
- switch 只改变全局启用。它的点击和键盘事件不得冒泡为本轮选择；开启成功也不自动选择，用户再点行表达本轮意图。
- “管理连接器”先保留当前草稿再打开管理页，并提供回到原新任务/会话的路径；回到输入框时还原用户文字、选择和合理的输入焦点。

### 6.2 输入区的已选标识

在输入框内容顶部、textarea 之前展示一组结构化 chip，包含连接器图标、名称、独立移除按钮。允许多个不同已启用连接器，按用户选择顺序显示并按稳定 ID 去重，最多 51 项。若工具数量或运行时预算无法承接完整选集，提交前明确说明并请用户减少选择，不静默裁剪工具或服务。长名称截断并提供完整 tooltip，多项换行，区域高度有 token 限制后局部滚动，不将发送按钮挤出视口。

原生 textarea 保留文本输入、中文输入法组合、Enter 发送/Shift+Enter 换行、粘贴、附件和选区行为。芯片不写入 `modelValue` 文本，也不以名称字符串解析服务身份。芯片移除只改变待发送选择，不全局停用。仅选连接器而没有文字或附件仍提示“请输入任务需求”，不发送无意图调用。

失效芯片保留名称并标记“已停用/需重新连接/不支持”，提供移除/配置动作；有失效选择时拦截提交并说明原因。不得悄悄删除选择后继续发送，造成用户以为仍在使用指定服务。提交中、生成中、history-only 和作用域切换时禁止增删本轮引用；恢复可用后再允许编辑。

### 6.3 草稿生命周期

| 边界 | 文字与本轮选择 | 已有附件 |
|---|---|---|
| 开关弹层或详情 | 原样保留；取消配置不改变原选择 | 原样保留 |
| 管理连接器页往返 | 在共享草稿状态中按当前 context/new/session 保留文字/refs；新任务还保存模型profile意图和工作空间ID，回页重新校验availability/revision，失效明确提示且不自动改选；已有会话模型/工作空间从native权威恢复，恢复原任务而非新建第二个任务 | 继续使用 native 草稿，不重新导入 |
| 同一页面切换会话 | 各会话隔离；新任务有独立槽位，不继承上一会话选择 | 现有目标切换规则保持 |
| 提交失败/未知结果 | 文字和 connector refs 保留，operation ID 与请求快照绑定；恢复使用原请求、原选集与原 connection generation，先确认接受状态再重试；账户连接已变更时必须重新选择而非改写原请求 | 保留原草稿引用 |
| `local_durable_accepted` | 清除刚提交目标的文字与选择；本轮 refs 进入历史；不清掉用户在其他会话编辑的草稿 | 沿用现有绑定/移除草稿引用流程 |
| 创建新会话 | 已提交 refs 属于首轮；后续每轮默认空选，空选不开放市场 51 工具 | 沿用已绑定内容 |
| 账号/tenant/context 变化 | 立即封闭旧请求并清除旧作用域内存视图；不跨账户显示名称或继承选择 | 沿用原 native scope 校验 |
| 正常退出/重启 | 本轮未发送文字/选择默认仍是内存草稿，不额外承诺跨重启恢复；已接受消息和 refs 必须可重开 | 现有持久化能力继续有效 |

将管理往返所需的草稿提升到共享 store 是候选最小方案，包含新任务模型与工作空间（当前 `ChatPage.vue:133` 的 selectedProjectId、`useChatModels.ts:5` 的 newProfile也会随页面卸载），避免只保留文字却改变实际执行目标。此方案不为本期新增文字草稿数据库 migration。若最终选择跨重启草稿恢复，必须先补对应私有 schema、保存/清除时点、作用域和回滚设计，不能隐含加入。

## 7. 模型、计划 input-only、历史和旧版本兼容

### 7.1 模型选择与普通任务

连接器选择与模型意图是两个独立字段，共同组成一次提交快照。选择模型不会自动清空 connector refs；发送前统一校验模型能力、连接器可用性、当前权限和 provider 协议支持。已有 `chat_model_submit_v1` 分支必须接受同样语义的新版本输入，不能仅普通 v2 路径支持连接器。

没有选择连接器时，普通文本/附件/模型提交沿用既有行为；不因本需求导致原来可用的无连接器任务全部被阻断。选择连接器后，若有效模型或运行环境不支持工具/本轮选择隔离，显示明确原因，保留草稿，提供“移除连接器”或选择受支持模型；禁止静默把 refs 变成自然语言标签、丢掉 refs、换模型或向本轮开放所有已启用服务。

### 7.2 计划草案与定时任务

现有计划草案必须保持 FEAT-155 的 input-only 约束。草案 Composer 不显示连接器入口和 chips，草案提交不携带 connector refs，不触发配置、OAuth、MCP discovery 或业务工具。不得为了 UI 一致而把全局启用服务注入计划草案线程。

普通新任务切换为计划草案时，沿用现有切换确认，只把用户文本作为草案输入；连接器引用和附件不偷偷转换成提示词或授权。原普通任务草稿按原目标保留；返回普通任务可恢复并重新校验其 refs。已有定时计划/手动立即执行/后台计划运行不继承聊天中的选择，本期不新增计划连接器绑定字段。若未来需要，应作为独立产品和契约变更。

### 7.3 历史与降级

已接受的用户消息应保存稳定 connector ID 和发送时安全名称快照，并展示为只读引用；无需保存秘密、完整授权 URL 或工具参数来解释选择。服务改名/停用/卸载后历史仍能显示“当时选择了什么”，但历史引用不能一键恢复旧授权或重新执行。

新历史格式需先有兼容 reader 和未知值安全呈现，再由 producer 发出。旧历史没有 refs 时按现有方式展示，不根据正文中出现应用名称去补造。未知 ID 可显示“连接器信息暂不可用”并保留安全名称快照；缺失 display 能力不构造假服务。版本完全不兼容时显示升级/只读提示，不能将错误载荷按附件解析并导致整段历史静默消失。

旧 Host/Runtime 或缺失能力时，目录可以在已允许的范围继续浏览，但本轮使用入口显示不可用原因；管理能力与执行能力分别判断。无 refs 的既有请求可走原路径，有 refs 的请求必须明确拒绝或由用户移除后重发。不得以“降级兼容”为名扩大权限、改用 shell 桥接、自动调用其他服务或重新派发历史。

## 8. 页面与操作状态矩阵

| 状态 | 用户看到的内容 | 主恢复动作 | 不允许的误导 |
|---|---|---|---|
| 目录读取中 | 骨架、正在读取连接器、aria-busy | 可离开页面 | 显示 51 个“已就绪”占位数据 |
| 目录就绪 | 六分类 51 项和准确安装/启用状态 | 安装、查看、管理 | 把清单可见称为真实服务通过 |
| 无安装项 | 已安装 tab/聊天弹层有明确空态 | 去市场/管理连接器 | 空白页或自动安装推荐项 |
| 搜索无结果 | 显示搜索条件与无匹配提示 | 清空搜索 | 说“没有连接器服务” |
| 首次读取失败 | 安全原因、重试入口 | 重新读取 | 用旧缓存冒充本次读取成功 |
| 刷新失败但有旧数据 | 保留上次成功展示，并标记状态待确认 | 重试；不允许依赖过期状态提交 | 更新“刚刚已验证”时间 |
| 无浏览权限 | 无权访问提示 | 重新读取权限/返回可访问页面 | 显示其他作用域的已安装名称 |

| 本地依赖/凭据缺失 | 缺少项和设置指引 | 配置/再检测 | 后台临时运行未经核定的下载命令 |
| 服务不可达/限流 | 对应项不可用原因和重试条件 | 明确重试，不无限自动循环 | 假造成功、费用或精确恢复时间 |
| 冲突或结果未知 | 当前状态待确认 | 查询同一 operation/刷新 | 重复安装、授权或卸载 |
| 本轮引用已失效 | 芯片警示、阻止本次提交、保留正文 | 移除或重新连接 | 无提示丢弃 refs 并发送 |
| 协议/格式不兼容 | 版本说明、能力安全关闭或历史只读 | 升级/移除 refs 后继续旧能力 | 将不认识的枚举当作已启用 |

错误文案不包含 token、cookie、完整回调、原始敏感响应或未脱敏堆栈。需要排查时显示安全错误码与可复制的脱敏关联 ID，不让用户靠猜测“重启全部服务”恢复。

## 9. 主题、尺寸、图标与键盘

规范来源为 `yijie-desktop/docs/design/docs/design/` 的 AI 开发规则、Chat 工作区、插件市场、设置权限、配色状态矩阵、主题与无障碍章节；活跃组件与 token 是实际实现入口。

- 亮色使用纯白结构背景与石墨文本；暗色使用既有石墨背景/卡片/弹层层级。青柠主操作使用 `--yj-color-brand-primary` 与石墨 `--yj-color-on-brand`；普通正文/图标使用 `--yj-color-text-primary`，次级说明使用 body/secondary。不得复制 PDF 的黑主按钮、补图的绿色正文或第三方整页配色。
- 已选 chip 使用中性表面和文本，选中标识可使用品牌 token；成功/警告/错误分别用 semantic token，不把所有状态染成品牌色。卡片无新增投影/位移；弹窗和弹层复用 `--yj-shadow-popover` / `--yj-shadow-modal`。
- 应用 logo 使用用户提供的本地资产和显式 ID 映射，以 `<img>`/受控资源展示，不作为任意 HTML/SVG 内容注入；普通按钮图标走 `YjIcon` registry。浅/深主题均给 logo 合适的中性底板，不修改品牌标识颜色。加载失败时使用本地图标 fallback 和应用名称，不加载未知远程 URL。
- 复用 `naive-theme.ts` 中的 Button、Switch、Popover 主题覆盖。新增弹窗、列表、chip 尺寸只定义所需局部 token，不散落 HEX、任意阴影、像素与 z-index。
- 最小窗口必须实测 `1180×760`，侧栏展开/收起、首页/会话、亮/暗各覆盖；使用当前 UI 缩放，验证长名称、多 chips、51 项滚动时模型/发送/关闭/管理操作可达，无横向溢出。
- 输入区空间不足时连接器入口可收为图标按钮，保留完整 aria-label/title；不得先挤掉模型选择或发送。弹层按入口上下空间选方向，必要时覆盖部分输入区利用视口，header/footer 固定、列表滚动。
- tab 使用真实 tablist/tabpanel，方向键、Home/End、aria-selected 与焦点一致。卡片用 button 语义；仅图标操作均有名称和 tooltip。卸载在 hover 与 focus-within 下均显示，Tab 可到达。
- 弹层入口支持 Enter/Space/ArrowDown 打开、Esc 关闭并还焦；行与 switch 分开聚焦，switch 的名称明确“启用/停用 XXX”，本轮选择名称明确“本轮使用 XXX”。不要给包含 switch 的外层按钮嵌套控件。
- modal 使用 Naive 的焦点管理，打开聚焦标题/首个有效操作，关闭回原触发点；失败保留上下文并聚焦错误/相关字段。pending 使用 aria-busy/status，错误用 alert；不会随每次轮询重复朗读整页。
- chips 有“移除 XXX”可访问按钮和可见焦点；不全局拦截 textarea Backspace/方向键破坏中文输入法。减少动态效果时关闭非必要旋转/过渡，状态仍以文字可辨。

| AC-010 | 逐服务记录授权/配置、真实连接、工具发现、按允许范围的真实调用与结果；未验证项如实未通过，不以安装卡片或两个样例代表 51 个全部成功 |

验证只采用正常、非破坏性操作和用户允许的真实服务范围。不得频繁强杀、篡改或伪装二进制、破坏权限、注入攻击资源，亦不得用 synthetic 状态冒充真实接入。不可安全执行的项目登记“未执行、原因、影响”。第三方账户、真实敏感数据、费用与外部写操作的授权边界由需求包单独记录，UI 设计不授予这些权限。

候选取舍：保留原生 textarea 并增加独立芯片，比新建富文本编辑器更契合现有输入行为；共享内存草稿解决管理往返，比本期增加新草稿数据库更小；独立全局启用与本轮选择确保用户意图可见，也给既有 Codex 线程隔离、审批与历史链路留下明确边界。最终技术能力不足时须显式提示和补齐契约，不能通过隐藏选择、注入名称文本或开放所有服务实现表面上的交互完成。
