## 主流程、交互与状态

1. canonical local demo_fast 免登录进入 Chat
2. 新任务默认请求批准，用户在入口选模式
3. 首次完全访问先确认，取消保持原设置
4. 提交任务时传递真实 Runtime 权限；排队/运行/待审批禁止切换
5. 人工请求以卡片展示操作与范围，批准本次/拒绝回传 Codex
6. 当前轮结束后允许修改；模式仅影响该任务，重启后恢复

- idle: 展示当前模式；允许打开选择菜单。
- loading: 权限读取/保存与任务提交期间禁用重复动作；运行中禁止切换。
- success: 持久写入成功后更新模式标签；审批决策成功后更新卡片。
- empty: 新任务默认请求批准；无待审批不显示审批卡片。
- error: 读取、保存或决策失败保留最后确认状态并显示可重试错误。
- retry: 重读当前任务状态；过期或已解决请求不再次执行。
- cancel: Esc/外部点击收起菜单；完全访问取消不修改；拒绝使用原生拒绝语义。

完全访问首次确认采用每个本机用户一次的持久标记；每个任务的权限独立保存。历史任务无新权限记录时 UI 以请求批准作为下一轮默认，只有显式提交新轮才应用。等待审批也属于 busy；审批失败不乐观显示成功。选择失败保留旧值；取消选择无副作用。

## 工程事实与技术决定

- Desktop 真实入口为 src/components/chat/ChatComposer.vue 与 src/pages/chat/ChatPage.vue，需求前仅有只读说明。Native application/worker/database 管理 durable outbox、scope 与 Host 连接。
- Host internal/codex/session_protocol.go 现有线程默认 read-only/never；原生 thread/turn 请求提供 approvalPolicy、approvalsReviewer 和 sandbox/sandboxPolicy，thread/approveGuardianDeniedAction 已存在。
- 首选直接传原生配置与关联原生请求，不复制风险模型、不新增 Runtime 补丁。人工审批只承接待执行回调；自动审批使用 Runtime 原生审核结果与手动批准接口。
- Runtime 字段以保留的 FEAT-136 实际 schema 为准；仓库根 generated schema 部分来自已终止 candidate，不能拿旧 v6 provenance 要求反向扩造 Runtime。
- contract-impact=semantic：新任务默认行为由固定只读变为可在工作区执行的请求批准；旧 wire 省略新字段保留旧语义。HTTP 权威源先行；私有 IPC 同源 schema 与 SQLCipher 增量表同步。
- 只对 exact local/demo_fast 启用新权限；保留 native scope/owner 校验与 Host bearer。商家业务审批和 public/production 不在本次范围。
- 现有 Desktop docs/design 颜色收敛文档修改与 proposals 删除属于用户已有工作，保持不动；其余四仓初查无修改。全部仓库当前为 chore/retirement-baseline-20260905。
