# FEAT-127 - 对话图片与文件上传及七天本地上下文

## 1. 问题与价值

当前 Chat 只接受纯文本。用户无法把商品图、报告或结构化资料与问题作为同一条消息发送，也无法在重开会话后看到这些附件。FEAT-127 把 Message 明确为多模态容器，让本地 Desktop 能安全导入、解析、索引并在七天内把附件作为 AI 上下文。

## 2. 目标用户与场景

- 用户：使用 macOS Desktop 本地 Chat 的已授权卖家。
- 主场景：通过输入框底部左侧的单一加号选择图片或文件，或拖入输入框；确认附件就绪后与文本一起发送。
- 后续场景：重开会话时，已发送附件元数据跟随消息加载；七天后保留消息记录与元数据，但正文、二进制和索引不可再用于 AI 上下文。

## 3. 范围

- 一个统一加号入口，位置与 `references/plus-entry.png` 一致：输入面板底部操作区最左侧、权限入口之前。
- 图片和文档的选择、拖拽、校验、上传状态、移除与失败恢复。
- Message 的 `text/file/image` 内容块、发送与历史加载。
- Desktop SQLCipher 中的附件二进制、解析结果、分块索引、消息绑定和七天过期状态。
- 文件解析后以有界相关片段进入 AI；图片通过既有 Runtime image UserInput 进入模型。
- Agent Host 新增并行 v2 turn input，不改变现有 v1 纯文本接口。
- 本地验证与交付包；不依赖云服务器、云数据库或对象存储。

## 4. 非目标

- AI 生成图片或文件的消息流展示、预览、下载和操作。
- 云同步、多设备共享、对象存储、服务端文件解析或向量数据库。
- 压缩包、可执行文件、宏文档、SVG、目录上传或远程 URL 抓取。
- OCR、图片编辑、病毒查杀服务和生产级 DLP。
- 合并、tag、发布、签名、公证或生产部署。

## 5. 成功标准

- 文本、附件或二者组合都能形成一条持久消息，并由本地 AI 实际消费对应上下文。
- 单文件超过 10 MiB、压缩包、目录、伪装 MIME 和不支持格式在 native 边界被拒绝。
- 应用重开后附件元数据与消息一致；七天到期后内容物理清除且 UI 显示“已过期”。
- 拖拽与加号走同一 native 校验和持久化路径。
- 亮色、暗色和 1180x760 最小窗口无重叠，可键盘操作，图标按钮有可访问名称。
