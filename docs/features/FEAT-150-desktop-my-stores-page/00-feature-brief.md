# FEAT-150 — Desktop 我的店铺展示页 Demo Brief

> Profile: `demo_fast` · Exposure: `local` · Created: `2026-08-26`

## 1. 用户问题与结果

- 目标用户：希望快速浏览经营概况、发现下一项运营任务的跨境电商卖家与运营人员。
- 当前问题：左侧导航中的“我的店铺”仍是禁用项，参考稿要求的经营快报、精选场景和岗位推荐均没有真实页面承载。
- 用户完成后能看到或使用的真实结果：从左侧导航进入 `/store` 后，用户看到明确标注为演示内容的经营概况，可按经营目标或岗位即时筛选场景卡片；所有内容均可在本地 Desktop 正常入口中使用，不依赖任何店铺连接。
- In scope：启用“我的店铺”导航；新增受 `store.read` 保护的 `/store` 路由；实现三个参考模块、全部标签和合成内容；覆盖亮色/暗色、1180×760、键盘与可访问语义。
- Out of scope：真实店铺/API/Agent Host/Runtime/数据库/持久化接入；多端同步；立即授权/需授权；查看全部；搜索；分页；场景执行、保存或预览；任何付费、生产或外部写操作。

## 2. 完整主流程

1. `exposure=local`：通过 canonical demo_fast 启动器零登录交互直达业务主页面（ADR-0018）；不适用请说明。
2. 固定本地身份具有 `store.read`，用户在现有 App Shell 中点击“我的店铺”，路由进入 `/store`，侧栏条目保持 selected。
3. 首屏默认展示“近 7 天销售战报”、精选场景“全部”和角色推荐“全部”，并在页面级明确标注“演示数据，不代表真实店铺”。
4. 用户可切换经营快报的三个标签，五张指标卡即时替换为相应的销售、广告或 FBA 库存口径。
5. 用户可切换精选场景的九个经营目标，场景网格显示对应合成内容；无结果时显示清晰空态并保留标签。
6. 用户可切换角色推荐的六个岗位筛选，卡片网格即时显示适合该岗位的合成场景。
7. 页面没有授权、搜索、查看全部、分页、保存或执行入口，不产生任何业务副作用。

## 3. 交互与 UI

- 视觉方向、布局和关键控件：采用易界经营分析 Pattern 和现有 App Shell；页面头部给出标题、价值说明和演示数据提示；经营快报使用三段标签与五列自适应指标卡；两个场景模块使用胶囊标签、标准密度卡片网格、短文案和清晰分类标签。所有颜色、字号、间距、圆角、阴影和动效只使用现有 design token，图标只通过 `YjIcon` registry。
- 主次操作：唯一页面内交互是三组筛选标签；它们只改变当前本地展示内容，没有高影响操作。参考稿中的授权、搜索、查看全部和分页均不渲染。页面没有预览、保存或提交语义。
- Idle：页面未进入时由左侧已启用的“我的店铺”链接提供清晰入口，不预取数据。
- Loading：不适用。页面只同步读取打包内的只读 TypeScript 常量，没有网络、文件、计时器或长任务，因此不制造虚假 loading。
- Success：三个模块按固定顺序完整展示；切换标签后标题、说明、指标或卡片列表与选中状态同步更新。
- Empty：领域筛选函数对合法但无内容的映射返回空列表，页面显示“该筛选暂无演示场景”，并保留所有筛选入口供用户恢复。
- Error：无 `store.read` 的深链由既有服务端权威投影对应的 Router guard 在页面实例化前拦截；非法/未知筛选键不会进入模型，组件只接受封闭 key 并安全保持当前合法选择。
- Retry：不适用远程重试。权限恢复沿用既有设置/权限刷新链路；空筛选可以直接选择任一其他标签恢复。
- Cancel：不适用。页面没有提交、授权、保存、异步任务或外部副作用，不提供伪取消控件。

## 5. 工程事实与边界

- 受影响仓库：`yijie` 只保存 FEAT-150 四文件治理包；`yijie-desktop` 保存页面、纯领域模型、复用组件、route/navigation 与测试。`repos.yaml` 未变化，其他兄弟仓不受影响。
- 真实入口/启动方式：在 `yijie-desktop` 运行 `pnpm tauri:dev`（或等价别名 `pnpm tauri:demo-fast`），通过真实 Tauri WebView 与现有 local demo_fast 启动链进入应用后选择 `/store`；`pnpm dev` 仅用于快速视觉诊断，不可替代 D4。
- local direct-entry、固定 scope 与 public/production 鉴权边界：沿用 ADR-0018；local demo_fast 固定 scope 已包含 `store.read`。本需求不修改 capability、身份、租户、授权或 public/production 边界；Router 继续使用现有权限投影保护 `/store`。
- `contract-impact`：`none`。新增行为仅存在于 Desktop 进程内的静态 TypeScript 展示模型、Vue 组件和 Router；Desktop↔API/Agent Host/Runtime wire、Tauri command、本地持久化、durable event、replay 和跨版本边界均无可观察变化。
- 权威契约源与 source-first 顺序：不适用公共契约修改；先固定本 FEAT 的本地模型与交互规则，再实现组件/页面，最后接入 route/navigation 并验证既有 `store.read` 权限语义。
- 数据、密钥、付费调用和外部写操作边界：全部指标、趋势、标签和场景文案由 Codex 合成并在 UI 明示为演示内容；不读取真实店铺、PII、token、cookie、Keychain 或环境 secret；付费、破坏性和生产写入额度均为 0。
- 已有工作区改动：`yijie` 和 `yijie-desktop` 当前都位于 `feat/feat-131-desktop-codex-parity-baseline`，并有属于用户/前序工作的 FEAT-131 未提交文件；FEAT-150 不 reset、checkout、覆盖、批量格式化或修改这些既有文件。必要的重叠仅限未脏的 route/navigation/frontend 测试文件，并在最终 diff 中逐项区分。
- 参考稿冲突：PDF 文本目录写“放差评”，全部对应页面截图和标签均写“防差评”。按用户要求同时参考截图与具体需求，采用业务语义明确且由多张截图一致支持的“防差评”，并把文本目录视为笔误。

## 6. 推荐方案与停止条件

- Codex 推荐方案及主要取舍：建立一个纯领域模型文件保存合成快报和场景映射；建立可复用的 `YjTabs`、`YjMetricCard` 与场景卡组件；页面只组合三段内容。该方案让筛选行为可单测、UI 可复用、无 API 假象，同时保持参考稿的信息架构和易界自身视觉语言。
- 30 分钟无新证据时的诊断动作：停止猜测式 CSS/Router 补丁，读取失败测试、浏览器/Tauri 控制台、路由状态与计算样式，定位完整调用链或布局约束。
- 90 分钟同一核心阻塞时的简化/替代方案：保留全部 Must AC，优先减少非关键装饰、复杂动效或额外卡片数量；用现有 `YjPage/YjSection` 与原生 CSS grid 完成稳定布局。
- 超过 16 小时时的缩减范围：停止扩展非 Must 的卡片文案、装饰和额外自动化；不得删除三个模块、全部筛选、权限边界、主题、1180×760 或键盘验收。
