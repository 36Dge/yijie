## 谁负责出图

易界用户直接在对话里要求生成图片时，由当前对话模型理解要求，调用易界随产品提供的内置生图工具，由火山方舟 Seedream 生成图片。用户继续在当前对话中查看和打开结果。**文字点名使用专家和界面选中专家具有相同优先级。选择期间，每一轮都优先使用该专家提供的同领域工具，直到移除或切换专家。** FEAT-168 将这项规则应用于生图，LinkFox 人台换模特图专家是已有的实际入口。

| 当次用户意图或选择 | 唯一允许的新建生图路径 |
|---|---|
| 没有选中专家，或选中的专家配置中确实没有生图工具 | 易界内置工具 → Seedream 5.0 Pro。相同规则适用于产品中本已获准执行此类任务的入口。 |
| 已选专家在其实际配置中提供了本任务的生图工具 | 优先使用该专家的生图工具；后续无需再次点名。 |
| 在界面选择 LinkFox 人台换模特图专家，或在消息中明确要求“用人台换模特图专家来做” | 使用这位专家当前配置的生图工具，沿用其连接资格、参数、素材授权及审批。Seedream 的参数约定仅适用于内置工具。 |
| 当前没有专家绑定，用户只说“把人台换成真人”，仅启用了 LinkFox 连接器，或仅讨论这位专家 | 这些行为不建立专家绑定。若意图是生成图片，走内置工具；若只是询问专家能力，只回答问题。 |
| 已选 LinkFox 专家，连接、资格或授权缺失 | 提示完成该专家所需操作或重新选择。禁止自动改用 Seedream；反向亦然。仅有历史使用记录不能代替当前有效选择。 |
| 只要求看图、分析、预览、保存或重开历史图片 | 消费已有内容，生图调用次数为零。 |

界面选择沿用已有专家胶囊、精确 ID 和版本、会话绑定修订号及本轮冻结快照。纯文本须明确要求使用该专家；引用、否定、询问能力和隐式技能匹配均不能构成授权。唯一解析后按现有流程准备资源并冻结本轮选择；无法唯一解析时，引导用户在已有选择器中选定。准备中、切换取消、状态未明或提交冲突均保留草稿、附件和已有操作；不提前发起任一路生图。切换只影响后续尚未提交的任务。点名和界面选择均建立可见的会话专家胶囊。正常重开或继续发送时，以仍然有效的绑定为准；移除后回到默认，切换后按新专家配置。绑定可以持续多轮，各轮的外部调用授权独立。

选中专家仅决定路由。LinkFox 的真实连接、当前轮服务选择、素材外发许可和原有逐次审批仍须齐备。有本地图片但缺该专家要求的授权直链时，沿用专家提示。任务创建回执表示已受理，查询原 taskId 成功且返回图片链接才算专家出图。本地 Artifact 预览、保存和重开要求只适用于内置路径。

## 内置工具与对话交付

`当前对话模型 → yijie-codex 原生图像工具 → 易界的方舟适配 → 现有图片产物与对话卡片`

1. 以固定 fork 的 `image_gen.imagegen` 扩展、工具注册、调用标识和原生开始/结束事件为基础。内置工具对话模型与后端出图模型分离。保留现有对话模型的 Responses 工具调用循环；对于生图，仅由适配层向方舟图片 API 发起一次请求。主模型无需迁移到方舟。[原生扩展](../../../../yijie-codex/codex-rs/ext/image-generation/src/extension.rs) · [方舟 Responses API](https://console.volcengine.com/ark/region:cn-beijing/docs/create-model-responses-api) · [方舟工具调用](https://console.volcengine.com/ark/region:cn-beijing/docs/responses-api-tool-calling)
2. 现有 fork 的生图扩展绑定 OpenAI 鉴权、命名空间、固定图像模型与返回格式。候选设计仅适配正式日常配置下的工具可见性、方舟调用和结果交付，保留原生调度与取消。当前日常客户端与旧实验 dynamic-tool 配置互斥，不能靠打开旧开关上线。具体接缝、资格验证与切换顺序见[工程设计](01-delivery-log.md)。
3. 首版内置入口承接文生图及本轮单张 PNG/JPEG 人物参考图。由 Host 依据受信会话与本轮提交选择用户已允许交给方舟的附件。只给文件路径、指向上轮图片或一次给多张时，要求用户在本轮提供一张合规图片，出站请求数为零。普通请求只返回一张结果；LinkFox 专家继续按已配置的图片角色和数量执行。图层拆分、新画布、额外模型选择器和图像供应商自动切换均在本次范围外。
4. 用户等待期间沿用现有对话活动状态。方舟非流式调用按一次完整结果处理，适配层取回图片后检查格式与内容，写入加密暂存区。Native 取得并持久提交图片后，卡片才可预览或保存；ACK 延迟时仅补确认。历史中仍处保留期的已提交原图从本机读取，已过期或未完成交付则显示相应状态。重新加载预览、重复通知、重开及读取失败均不产生新计费请求。

## 方舟请求

北京区 `POST https://ark.cn-beijing.volces.com/api/v3/images/generations`，使用独立方舟 Bearer API key。普通文生图的默认请求体示例：

```json
{
  "model": "doubao-seedream-5-0-pro-260628",
  "prompt": "一盏白色台灯放在浅灰色桌面上，正面商品照。",
  "size": "1.5K",
  "watermark": false
}
```

- 分辨率用 API 枚举 `1.5K`（大写 K）。水印用 JSON 布尔值 `false`。仅在参考图任务中增加业务输入 `image`。其余可选项省略，使用服务默认值。
- 用户已移除图片 API 流式约束，当前请求省略 `stream`，按默认非流式 JSON 处理。方舟默认返回有效期 24 小时的图片 URL。由受管适配层及时取回结果并交付现有产物链，对话历史使用本地产物引用。对话本身的事件更新可照常进行。[图片生成 API](https://console.volcengine.com/ark/region:cn-beijing/docs/image-generation-api) · [型号能力表](https://console.volcengine.com/ark/region:cn-beijing/docs/image-generation-tutorial) · [图片流式响应参考](https://console.volcengine.com/ark/region:cn-beijing/docs/image-generation-streaming-responses)
- 只在确需配置方舟 key 时，以本机掩码弹窗接收；已配置则复用。凭据仅交受管持有方。取消、失焦退出或配置失败均不提交生图；再次配置由用户发起。启动易界、普通聊天和使用 LinkFox 均无需输入方舟 key。输入 key 只完成配置，真实联调还需要独立的调用授权。

## 交付边界

产品目标是日常易界的正常对话。当前 Demo 验证只使用正式代码路径和本需求独立的本机数据目录、公开或合成素材。日常入口实际绑定用户原数据，只有单独获准才能激活；旧需求的批准不延用。后续切换应先验证两条选路、内置工具的真实出图与原卡片交付，再撤销旧 MiniMax 生图入口；回退只暂停新内置生成，当前受支持格式内、已持久提交且在保留期内的图片仍可读。8 项验收口径见[验收矩阵](02-verification.md)。本次交付为独立的本机候选，日常激活、Git 提交和发布均未执行。
