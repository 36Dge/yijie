- 新草稿和已有会话分别使用草稿专家选择、已有绑定及预期修订。专家解析或切换尚未完成时不发送；用户明确点名只允许通过同一选择和绑定流程，不可用模型给出的名字充当身份。[现有提交与恢复条件](../../../../yijie-desktop/src/pages/chat/ChatPage.vue) · [已有专家选择器](../../../../yijie-desktop/src/composables/useChatExpertPicker.ts)
- 验收时将本轮专家快照、执行准入和实际出站记录依次对齐。LinkFox 的通用 MCP 代理按当前服务身份与已发现的实际生图创建操作判断，历史名 `aigc/imageGenAsync` 仅供核对；普通会话只获得了服务可见性时不能执行该创建操作。重开旧任务后，用户明确请求查询仍以原 taskId 和现有授权为准。[Host 会话提交](../../../../yijie-agent-host/internal/session/market_submit.go) · [Connector gateway 执行准入](../../../../yijie-connectors/worker/src/gateway.rs) · [专家规则](../../../../yijie-skills/plugins/yijie-desktop-skills/experts/linkfox-expert-aigc-imagegen-mannequin-to-model/skills/mannequin-to-model/ROLE.md)
- Host spool 仅用于受控暂存。Native 校验并提交之后才向 Host 确认；恢复、补 ACK 和用户重新出图分别计数。历史过期或丢失情形优先用已存在的自然记录或正常 reader 状态验证，禁止改时间、权限或数据库制造故障。[产物提交和 ACK](../../../../yijie-desktop/src-tauri/src/chat/artifact.rs) · [历史产物保留边界](../FEAT-165-native-artifact-files-and-preview/00-feature-brief.md)

## 起草时的执行与证据边界

- 验收前先核对契约、固定 Runtime、原生工具注册与出站形状。`pnpm client:dev` 和已有易界入口使用日常真实 Homes、数据及服务。用于验证的隔离候选必须记录同源代码、锁文件/构建身份、支持的正常入口、独立数据和受控测试身份；只有证明其等价性，才可计其资格证据。日常真实环境、真实账号和付费操作须另获明确授权，获得之前不执行。
- 获准后，以同一版本组合、同一次 fresh run 串联 AC-001 至 AC-008、已有桌面交互、Seedream 实际结果、正常重开及代表性失败/重试；逐项记录场景、入口、预期、实际结果、可核查证据和实际调用数。本地记录器仅证明请求形状、路由和失败处理。按同一用户结果解释本地记录、UI 与服务回执，不能将不同候选的零散通过合并成 D4。
- LinkFox 分开记录“本地专家选择/准入/拒绝”与“真实账户发现/审批/远端任务及结果”。无真实账号、授权或预算时，后一项保持 **NOT RUN**，明确 AC-002 未验证的范围，不将本地检查或历史资料折算成真实出图 PASS。Seedream 未有获准实调和可读原图时同理；未覆盖的 Must AC 不评 PASS，D4 保持未通过。证据只留脱敏关联标识、状态、次数与必要的非敏感 UI 截图。
- 取消仅通过 UI 或原生中断，重开使用应用正常退出。故障注入式强杀、篡改可执行文件、破坏权限、攻击性输入或归档不列入验收。上述异常制造场景未执行，正常错误响应、取消和重放也须在获准实施后验证。
- 当前本地 D4 按 Owner 接受范围收口。DP 公开验收不适用。
