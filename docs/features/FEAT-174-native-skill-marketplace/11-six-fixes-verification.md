# 六项修复：最终验收与自审

2026-11-14。六项问题及完整窗口验证发现的接入遗漏已修复。结论为 **local 候选验收通过**，不等于生产发布或真实供应商模型质量验收。最高 `contract-impact=breaking`；先更新源契约和生成物，再实现配套 Host / Native。付费及外部业务调用为 0。

## 验收中补齐的遗漏

完整窗口发现：仅把拒绝变为 failed 仍不够，Native 原有续聊路径要求已经绑定 Host。为此新增按需 schema46 初次 Host 意图，复用现有消息/outbox 事务、身份绑定函数和 turn 确认流程。本地模型 revision 保留为 1，首次 Host 创建映射为 0；接收回执后只绑定新轮次。前序包含未知、待处理、普通错误或原生绑定时不允许此入口；不会把旧请求重发或改成成功。

容量自审发现通用聊天响应的 1 MiB 限制会先于条目数触发。技能目录使用同源生成的独立 256 MiB 上限，覆盖该目录全部字段上限和 JSON 转义的最坏序列化规模；其他聊天/操作响应仍使用原上限。验证使用约 2 MiB 的普通说明文字、1024 行目录，没有资源耗尽或攻击 fixture。

自审还补齐了“只有 prepared 旧源、尚未取得 NativeBefore 快照”的回滚：不把默认 false 当作历史停用意图；回滚与恢复均通过。`Import/Mutate` 等待同一写锁后重新检查模式/readiness，防止在维护完成后沿用排队前的准入判断。

最终 OpenAPI lint 发现六处操作缺少 summary，已补齐并重新生成全部消费锁。此项仅增加接口说明；最后两轮窗口验收与最终版本的 Go/Rust DTO、JSON Schema 和执行源码相同，差异仅为源文档摘要引起的锁摘要，详见机器校验记录。

## 原生复用与兼容边界

`yijie-codex` 源码、25 项补丁、canonical schemas 和固定二进制均未修改。安装、卸载、刷新、启停、库存读取、发现、技能解析/正文读取和配置优先级继续由原生负责；Host 只维护应用操作归属、事务进度、旧回执投影与容量准入，不增加第二套安装器、技能解析器、规则求值器或缓存扫描器。

实际核对源码后确认：该固定 Runtime 的 `skills.config` 仅消费 User 和 SessionFlags 层。项目层同名配置不会参与原生技能启停求值。本轮保留这个原生边界；S5 验证的是实际 CWD 和原生发现/已有策略，未在 Host 发明项目层规则支持。最初按项目层 opt-out 编写的检查没有通过，调查及更正证据保留，未改成虚假通过。

- 技能私有状态 schema2：新 reader 读取 1/2，旧 schema1 writer 拒绝 2；兼容回滚使用本轮 reader。
- Host 会话 schema14：仅首次保存拒绝证明时增加外层，保留原 domain/model envelope（实机为 13）及既有回执；旧 writer 不能忽略拒绝 ID 约束。
- Native schema46：仅新的未绑定会话显式提交需要升级；追加初次 Host 意图表，正常删除沿父记录级联，旧 reader 拒绝新格式。实机升级后正常冷启动、历史读取、技能选择和续聊通过。
- 已完成的 schema1 兼容周期可按记录读入。无法证明归属的旧维护残留继续保留并阻断自动处理；旧未知聊天结果也不因 404 或忙碌错误被推定未派发。未自动处理无法证明的旧意图。
