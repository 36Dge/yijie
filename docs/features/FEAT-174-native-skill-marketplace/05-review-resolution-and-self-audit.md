## 2. 自审中额外发现并已修正文档的点

- **库存扫描边界**：原生临时安装／备份目录可能被朴素扫描误当插件。N2现明确复用原生布局／manifest身份核验并排除临时目录。
- **旧writer实际阻断**：只隔离新库，旧Host仍可能打开旧根。现明确公共v3路由标记在native副作用前发布；旧reader在恢复前拒绝，新reader承接旧codec。真正旧二进制降级不在本期支持范围，不能假称只改回版本号即可回退。
- **刷新完成定义**：调用底层刷新函数不足以保证技能缓存／线程已采用新来源。N3现必须沿现有管理器缓存失效／变更回调，并以原生配置及强制技能快照确认，不能只看cacheVersion。
- **不同来源的卸载**：当前内置项保留目录／来源／卡片；个人与下架项才移除可见条目，避免通用删除规则破坏内置加号重装。
- **旧会话边界**：原生冷恢复可能保留旧初始目录。现区分新旧会话证据，不由Host补目录、不改rollout、不自动付费压缩；提供重新选择／新建任务入口。

## 3. 原生复用自审

已经存在且必须保留的机制：本地市场登记、PluginStore安装／卸载／原子替换、原生刷新器、原生配置编辑与规则优先级、技能解析／加载／去重／预算。N1仅控制来源与触发，N2仅投影原生事实，N3仅桥接既有刷新。

允许留在Host的部分是用户文件导入、来源快照、产品身份、发布／操作意图与旧业务数据适配。来源快照和目录代际不是安装缓存；journal中的前态不是实时安装权威。自审未保留另一个安装器、更新算法、正文解析器、文本匹配器或工具执行平台的设计。

单文件／ZIP归一化不强行套用原生外部代理目录迁移或tar.gz接口；理由和源码在03。工具依赖只引用现有MCP／连接器事实，不因导入获得新授权。
