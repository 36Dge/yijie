# FEAT-174 技能模块调整方案

日期：2026-11-13（Asia/Shanghai）。状态：方案草案，待评审，未实施。负责人／评审人：段成威。交付范围：先完成本机 demo_fast 验证；面向用户的 App 分发仍需原发布流程。

推荐采用 **应用内置本地 Marketplace＋用户导入本地 Marketplace＋Codex 原生 Plugin/Skills 管理**。一个技能对应一个仅承载技能资源的原生插件，页面仍叫“技能”，用户不需要理解插件、Runtime 或本地路径。

本次文档变更 contract-impact 为 none；拟实施变更按 breaking 评审，涉及安装权威迁移、原生技能名称变化和旧封闭契约的兼容问题，见[契约与迁移](04-contract-and-migration.md)。方案落盘不代表 D0 批准，不继承其他任务的实施或付费额度。

## 1. 已确认的产品规则

| 用户要求 | 明确行为 |
|---|---|
| 技能随易界 App 打包 | 首批 38 个普通技能的完整内容与本地目录进入 App Resources；独立于用户是否已安装技能 |
| 安装 App 后直接展示 | 新用户第一次进入技能页即可看到全部内置卡片；全部未添加，显示加号 |
| 加号无需服务端下载 | 从随 App 分发的本地源安装，成功后默认启用；不下载市场或技能资源 |
| ZIP 或 skill.md 上传 | 文案使用“导入技能”，文件仅复制到本机；一次导入一个技能，成功即安装并默认启用，没有第二次“安装”操作 |
| 尽可能复用 yijie-codex | 原生承担目录解释、安装缓存、安装／卸载、启停配置、技能解析、发现、显式／隐式调用、正文按需读取、去重及上下文预算 |

“默认未添加”适用于新用户和升级新增的内置技能。已有安装／停用选择保持，不批量卸载或重新启用。现有首次启动自动安装 7 项的逻辑退役。

## 2. 当前流程与调整点

当前链路：yijie-skills 自定义 bundle／ZIP → Desktop 清单展示 → Host 解包、安装回执和停用标记 → 原生 skills/extraRoots/set、skills/config/write、skills/list → 聊天原生 Skill 输入 → Runtime 加载正文。

已经复用的是原生发现与运行机制；原生 Marketplace/Plugin 安装管理尚未接入，用户导入尚未实现。38 个技能有 25 个声明工具依赖，安装成功不代表工具可用。当前专家组合包中的 38 个普通技能与旧包归档逐项相同，不将专家资源计入技能页。

| 层 | 保留／新增 | 退役／避免重复 |
|---|---|---|
| yijie-skills | 内容、版本、许可、图标映射；生成原生 marketplace.json 和逐技能 plugin.json | 普通技能不再以自定义 bundle 清单作为安装权威 |
| Desktop | 现有卡片、五类布局与搜索；新增“我的技能”“导入技能”和原生选文件 | 去掉 7 项自动安装；前端不扫描目录、解压或拼接正文 |
| Agent Host | 来源准入、导入、产品 ID 映射、操作去重／恢复、原生接口适配 | 普通技能不再自建最终安装缓存、安装回执和启停标记 |
| yijie-codex | 原生本地插件目录、安装器、配置与 Skills 引擎 | 不重写安装器、匹配器、正文注入器或 Agent 执行循环 |

专家资源包、会话绑定与准备流程保持现有职责。实现须拆开普通技能与专家资源分支，不能删除共享服务而破坏专家，也不能让旧普通技能对账重新注册已迁移目录。

## 3. 三条用户流程

### 首次展示

App 提供 `yijie-builtin` 本地 Marketplace，包含全部内置技能的说明和源文件。Host 读取原生目录与安装状态，Desktop 映射到中文卡片。目录存在不触发 plugin/install，也不将整个源目录注册成 Skills 根。

全新用户：38 项可见、0 项已添加、0 项启用。重新扫描、页面进入、窗口恢复与重启均不得自动安装。Runtime 暂不可用时，可用核验后的随包展示索引显示卡片，但状态为“待同步”、操作禁用，不把未知状态写成未安装或已安装。

### 加号添加内置技能

1. 点击卡片加号，显示局部“正在添加”，同一条目操作互斥。
2. Host 根据稳定技能 ID 找到本地条目，不接受前端任意路径、URL 或远程 marketplace 名称。
3. 调用原生 plugin/install，由原生安装器从本地源复制到易界专属 CODEX_HOME 的插件缓存，并默认启用。
4. 回读原生安装状态、skills/list 与配置刷新结果，确认后显示开启的开关；未确认时保持同步中或可恢复错误。
5. 停用只改变原生启用配置，再启用不用重装。卸载调用原生 plugin/uninstall，内置源与卡片保留并恢复加号。

添加、启停和卸载不自动发送聊天请求，不执行技能脚本或连接器业务操作。停用影响后续轮次的可选目录与新注入，已进入会话历史的正文不删除。

### 导入用户技能

右上角“导入技能”选择 `.zip` 或大小写不敏感的 `SKILL.md`，按“读取文件 → 校验 → 添加 → 已添加并启用”一次完成。这里的上传是本地导入，不上传易界服务端。

首期 ZIP 支持根目录一个 SKILL.md，或唯一外层文件夹下一个 SKILL.md；保留 references、scripts、assets、templates 等相对结构。正常目录项、macOS 的 .DS_Store／__MACOSX 在归一化阶段处理。零个／多个技能入口明确报格式错误，不猜测或静默丢弃。

单文件入口名规范化为 SKILL.md，正文保持不变。按原生格式要求包含有效 YAML frontmatter 和非空 description；name 缺省由原生规则给出。不自动把文章改写成技能，不调用模型补描述。需要配套文件时使用 ZIP；单文件仅携带该文件，未提供附件的引用不能被视为已满足。

Host 生成受控的技能专用 plugin.json，将内容放入用户本地 Marketplace，再调用同一个原生安装入口。完整插件、嵌套插件清单、hooks、Apps 或 MCP server 配置不作为可执行插件导入；本需求接受技能包。普通脚本保留，安装时不执行。

推荐默认：首次导入成功开启；同一用户重复导入相同内容按摘要去重，返回已有条目并保留当前启停；同名不同内容作为新条目，显示名称加序号，不静默覆盖内置或个人技能。

个人技能卸载先确认原生卸载成功，再移除“我的技能”条目及本应用持有的导入源副本。用户最初选择的文件、运行产生的文档和原生 plugin data 不删除。再次使用需重新导入。

## 4. 页面与状态

保留 `/plugins?tab=skills`、三列卡片、彩色图标、五类内置分类、亮暗主题和键盘焦点。在技能页内增加“内置技能／我的技能”切换；搜索作用于当前分区。个人技能采用现有图标回退，不要求上传图标或新增生图服务。

普通卡片保持名称、简介、操作区，不恢复版本、许可、风险等常驻底栏；来源由分区表达。工具缺失等真实异常独立展示，按需链接已有连接器入口。正常卡片由加号表达未添加、开关表达启停。

| 状态 | 可观察行为 |
|---|---|
| idle | 未添加为加号，已添加为开关；导入按钮可用 |
| loading | 区分读取、校验、添加、同步，不虚构百分比，同条目互斥 |
| success | 原生回读确认后提示“已添加并启用”；导入后定位个人技能 |
| empty | 我的技能为空显示导入入口；搜索无结果可清除搜索 |
| error | 区分格式、超限、权限、Runtime 不可用、安装失败、状态未确认；已有安装不消失 |
| retry | 同一操作 ID 先查询实际状态，已成功不再安装；格式有问题则重选文件 |
| cancel | 选文件取消无变化；提交前可清理暂存；原生安装已发出时先核对结果，再完成或补偿卸载，不假报未安装 |
| permission denied | 可读时保留目录；禁止导入／管理，沿用本机身份和 Host 鉴权 |

导入完成、已启用、Runtime 可发现、工具就绪分别记录。缺少工具可以保持“已安装且启用”，但明确缺项，不把添加成功等同于业务可执行。

## 5. 推荐架构及三个必要适配

一技能一插件使单个加号、开关和卸载直接对应原生生命周期；不把 38 项装成一个插件后再自建子安装状态。内置市场 `yijie-builtin`、个人市场 `yijie-user` 均为方案命名。

1. **本地目录来源策略。** 当前开启 plugins 后，即使 remote_plugin=false 也会同步官方市场。推荐一个默认保持上游行为的最小 Runtime 配置扩展，限制市场来源和后台同步，安装／执行算法不改。这是待评审的拟议补丁，不靠隐藏 UI、清缓存、伪造 git 或制造网络错误实现离线承诺。
2. **技能身份迁移。** 插件技能名为 `plugin:skill`，当前短名称约束不能直接沿用。稳定产品 ID 保持，Host 从原生投影解析实际名称／路径，聊天继续传 `{id,version}` 和 UserInput::Skill，不新增 Host 文本匹配器。
3. **工具依赖边界。** 复用原生 MCP 发现、权限、调用；依赖声明不赋予连接器授权。25 项工具型技能逐项映射到已有真实能力，未接通则报缺失；首期不自动安装第三方 server，也不新增供应商、库存等连接器。

另有一处薄适配：原生内部已有 installed_version，但当前 app-server 未返回；直接增加可选 installedVersion 投影，避免把可提供版本当成已安装版本。它与来源策略是本方案两处最小 Runtime 增量，安装器与版本管理算法继续复用。源码证据见[原生能力审计](03-native-reuse-audit.md)，详细装配及兼容见[工程方案](04-contract-and-migration.md)。

## 6. 选项与取舍

| 方案 | 收益 | 代价／判断 |
|---|---|---|
| A 自有安装器增加导入 | 改动较小，原生 Skills 加载保持 | 继续维护安装回执与同步，未解决更多复用的目标，不推荐为目标架构 |
| B 原生本地 Marketplace／Plugin 统一承载 | 两种来源共用原生目录、缓存、安装卸载、启停和运行 | 需要最小来源策略扩展、契约与迁移；推荐 |
| C 个人写原生 Skills 目录，内置走旧安装器 | 导入直接 | 双路径长期存在，状态与恢复不同，不推荐 |

B 的网络副作用、身份变化、旧安装迁移须同时实现验证，不能仅开插件开关。若最小扩展未获准，A 仅作为待选择缩减路径，不自动切换或实施。
