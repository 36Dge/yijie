## 2. 检查层次与可用命令

- Runtime：沿 yijie-codex canonical 补丁构建／schema 比较入口，筛选本地 PluginStore、MarketplacePolicy、配置与生命周期的普通用例。保持真实可执行文件、正常 EOF 清理；历史攻击／故障注入用例先排除。
- Contracts：在实际改动后运行对应生成／一致性／兼容验证；核对冒号名称、个人来源、导入操作与旧响应 reader，而非只检查新增字段。
- Host：现有 operation journal、RPC 参数、正常导入、查询对账、选择身份与专家隔离的定向检查；不复制一套 mock 安装器来证明原生安装已接通。
- Desktop：受影响页面／store／API／聊天选择和原生文件导入的定向检查，遵守 scripts/test-safety-exclusions.json，并补审未列入但不合用户规则的用例。
- 产品：正常 pnpm client:dev 或既有 start-ui 入口的真实服务组合；需要重启时先正常退出。浏览器组件测试不替代原生窗口和真实 Runtime。

本方案没有新增可执行测试文件。实施命令在相应源码改动后绑定确切范围，不能现在编造未来测试函数名并写 PASS。
