# FEAT-171 首期平台与资源预算

2026-11-09，D0设计基线。本文冻结支持政策、准入限额和未来验收门槛；**预算值不是性能实测结果，Codex文件体积不是易界包体证明**。未构建、安装或启动任何产品候选。

## 1. 首期平台与安装口径

首期为 **macOS 14.0及以上、Apple Silicon arm64原生运行**，不要求Rosetta。最低8 GiB物理内存，推荐16 GiB；新装前至少12 GiB可用磁盘，升级前至少16 GiB可用磁盘，不含既有用户原件占用。最低配置下执行同一支持范围；通过串行重任务和有界解析控制资源，不静默缩减格式。

这是本轮明确的产品支持政策，不是已完成系统资格验证：

- `yijie-desktop/src-tauri/tauri.conf.json` 当前没有显式 `bundle.macOS.minimumSystemVersion`。
- `scripts/install-development-entry.py:30` 的开发启动器最低系统是13.0；本次只读 `otool -l` 观察现有开发可执行文件 `minos 11.0`。二者都不能证明macOS14最低机型已验证。
- 后续标准构建必须统一应用包、launcher、Host、Runtime及文档依赖的目标系统/架构；在macOS14最小支持环境与当前稳定系统分别正常验证。上游二进制minos低于14不构成冲突，只要其真实支持范围覆盖14；不手改既有Mach-O或签名程序的版本字段。Intel、Windows、Linux本期不发布支持声明。
- 依赖表中的LibreOffice26.8.2官方macOS系统门槛不高于此政策；出处和可分发条件见[06](06-dependency-baseline.md)。Apple Quartz/CoreGraphics为目标OS系统框架，允许复用，不是要求用户安装第三方转换软件。

完整安装候选包含文档环境、指南、模板与字体。用户不需要Python、Node、Office、Homebrew、源码、编译链、Docker或Codex缓存。模型网络及账号沿现有产品条件；本地文件解析、预览和已安装引擎执行不额外下载。开发启动器成功不能代替清洁用户安装候选验收。

## 3. 安装、磁盘与内存预算

所有GiB/MiB均按2的幂计；空间预检以所选包清单的实际字节和下列上限计算，不能只看安装文件下载成功。

| 项目 | D0冻结门槛 | 执行规则 |
|---|---|---|
| 文档依赖归档 | ≤1 GiB压缩；≤2 GiB展开 | 完整离线包；超限停止候选晋升并回到体积优化/设计评审 |
| 完整应用候选 | ≤3 GiB压缩；单一安装代≤6 GiB落盘 | 包括本功能与既有应用/Runtime；不是仅计算Python目录 |
| 更新保留 | 最多当前代+上一兼容代；暂存新代独立 | 不覆盖正在使用的依赖，不删用户原件以凑空间；正常切换后按引用数清理无引用旧代 |
| 可用磁盘 | 新装≥12 GiB；升级≥16 GiB | 包含安装暂存和运行余量，不包含用户已有文件；实际包清单计算要求更高时取较高值 |
| 每文档作业临时空间 | 目标≤256 MiB，准入/写入总预算512 MiB | 含中间Office/PDF/解析文件；增长到预算前拒绝下一步骤，正常收尾，不截断成伪有效文件 |
| 文档作业全局临时空间 | ≤2 GiB | 按job拥有权记账；原件、spool和QA分别记账，不重复计算为可用空间 |
| QA页面缓存 | 单作业≤128 MiB；全局≤512 MiB；TTL24小时 | 逐页生成/读取，不一次加载全页；已检查页可释放图片缓存，保留覆盖记录及原件digest，不清除正式产物 |
| 文档子进程内存 | 最低配置下进程树RSS峰值验收≤2 GiB；目标≤1.5 GiB | 这是未来性能验收门槛；超限不能用强杀制造“受控”；运行时停止新重任务并正常收尾 |
| 单页解码 | ≤4,000,000像素，RGBA约16MB | 沿现有Quartz限额；逐页/分块，不因缩放倍数无界分配 |

正式聊天原件的7天保留及用户明确另存文件生命周期按主设计执行，不被24小时QA缓存清理影响。Host spool仍沿现有24小时、256MiB/session、1GiB/global及进程密钥生命周期；staged不保证重启恢复。保留到期、缓存清理、用户另存不能混成一个删除动作。

## 4. 格式准入与质量支持集

层级必须分开：上传/解析范围、生成质量范围、Host交付最大值不是同一个“文件大小”。

| 层级 | 冻结范围 | 对超出范围的行为 |
|---|---|---|
| 单个上传附件 | ≤10 MiB，每消息≤10件 | 保持现有准入；拒绝时不读取部分内容冒充完整 |
| 正常生成且承诺完整质量检查 | 每正式文件≤10 MiB；每轮≤12正式产物 | 生成前说明范围，必要时请求用户选择拆分；不能自动拆成超过12项 |
| Office/PDF/HTML预览源 | ≤10 MiB | 超出本期完整预览基线时说明；已合法提交原件仍可保存 |
| TXT/Markdown/CSV/JSON完整文本源 | ≤1 MiB | 原件可保留/另存；超出时明确“未完整解析/预览”，不宣称已全量问答 |
| Host产物传输/保存上限 | >0且≤64 MiB/件 | 只是现有容器上限，不表示10—64MiB文件已通过生成/预览资格 |
| 同轮九格式典型请求 | 9×10 MiB=90 MiB正式原件 | 小于256MiB会话spool预算；QA页图不登记正式产物，不能挤占12项名额 |

准入同时保持已有结构预算：OOXML最多512 entries、总解压32MiB、单entry8MiB及压缩比上限；PDF最多256页/4096 objects/1024 streams及既有扩展流预算；JSON深度32、节点20,000。限额是并且关系，文件不到10MiB也可能因结构超过范围而拒绝。不得为通过首期验收放宽现有保护。

### 生成与完整视觉检查的有界范围

- DOCX/PPTX/PDF：每件最多50页/幻灯片；全部页进入覆盖清单。PDF阅读器现有256页上限可以继续供已接纳输入阅读，但不能把256页输入阅读当作50页以上生成QA已资格化。
- XLSX：最多10工作表；每表最多2,000行、50列；全工作簿非空单元格≤12,000，所有使用矩形面积总和也≤12,000。公式≤2,000、图表≤20。不能仅按非空格计算而忽略跨度极大的稀疏区域。
- XLSX视觉QA以每块最多50行×12列拆分，不放大成一张不可读的全表截图；按实际字体/长文本继续分块后**总块数≤32**，每个使用区域和图表都有覆盖项。超过任一上限时，在生成计划阶段说明超出完整QA支持集，允许用户缩减或明确分拆；不能静默跳过中间单元格后仍报告全部检查完成。
- 文本/Markdown单行≤8,192 bytes；单次投影≤256KiB、最多2,000行。CSV最多10,000行、50列、每cell≤4,096 bytes且总源≤1MiB；按200行/50列窗口读取，须在实现时补齐游标，当前200行截断实现不能冒充10,000行已支持。
- JSON在1MiB/深度32/20,000节点内完整解析，数值词法需保留；单次UI响应有界，不通过JS Number默默改变大整数。HTML≤10MiB含内嵌资源，不另取外链填补页面。

生成基线内的文件必须满足格式/内容/视觉要求；超过范围不是自动放宽质量检查的授权。用户明确要求更大文件时，先解释范围和可选择的拆分，不能把“局部检查”标为全部通过。后续扩大支持集必须有对应资源证据与契约/兼容审查。

## 5. 并发、时限与正常取消

- 应用内同时仅1个重文档作业（Office转换、公式重算、页面栅格化）执行；待执行队列最多8项，同一会话最多1项在途。只做资源信号量与准入，不另建Agent调度/执行循环。多代理仍通过原生执行机制申请此资源。
- 用户预览同时最多2个读取操作，沿已有受控读租约；重生成不得阻塞已提交原件的轻量阅读。一次只保留当前页必要解码数据。
- 环境预检目标：冷启动≤15秒、同版本热检查≤2秒；参考标准文档首屏目标≤3秒（Office首次转换另计）。本轮没有耗时benchmark，此为未来最低配置验收门槛。
- 正常转换/重算单步骤软截止180秒；一次本地文档作业总软截止900秒，不包括模型推理网络时延。到软截止不再派发下一重步骤，明确超时，走转换器支持的正常停止/退出及原生取消。
- 正常停止请求后30秒仍未退出，显示STOP_PENDING并保留资源拥有权；不释放并发槽启动另一个冲突作业，不用SIGKILL、超时kill或替换程序强制结束。不能安全退出时停止该步骤并向用户报告。
- 对读取/解析设置可取消的原生边界；预算上限由事前准入与逐步有界分配保证，不能把进程被OS终止当作预算执行成功。未知结果先查询已提交事实，不自动重投生成/另存。
