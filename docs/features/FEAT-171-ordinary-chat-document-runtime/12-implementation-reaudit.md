## 复审结论

上一轮代表性 Kimi 任务通过，不能推出全部普通输入和恢复路径正确。本轮发现以下实际遗漏，已作源码修正。生成/读取依旧复用受管 CPython、LibreOffice、Quartz，以及 yijie-codex 原生执行、审批、Code Mode 和 view_image；未增加第二执行器或权限入口。

| 问题 | 根因与影响 | 本轮修正与验证 |
|---|---|---|
| 文本格式表格丢失 | TXT、Markdown、HTML 快速模板读取了 `rows` 却没有写入输出，仍返回成功 | 三类模板输出实际表格；Markdown 处理分隔符/换行，HTML 转义单元格；九格式样本增加内容断言 |
| 合法跨表公式被拒绝 | 直接比较公式字符串，Calc 合法去掉工作表引号也被当作改变公式 | 按公式 token 比较，仅规范化范围引用引号/大小写，保留文本常量及有意义的空白；真实跨表 SUM 等8条公式验证 |
| 空文本公式结果被误判 | openpyxl 将显式空字符串缓存读为 None；Native 阅读器也把空 `<v/>` 当成无缓存 | 同时核对 OOXML 的 `t=str` 与显式缓存；IF 的合法空结果被接受并显示为空，真正缺缓存仍提示未计算 |
| 失败占用最终文件名 | create 直接写最终路径，再作结构/大小检查；空 CSV 失败后遗留目标文件 | 创建和重算在同目录私有临时路径完成校验，随后原子、不覆盖发布；空 CSV 失败后同名正常重试通过 |
| 版式失败后不能重试 | 固定缓存目录存在即拒绝，未区分执行中、正常结束失败与有效缓存 | 每次尝试使用唯一目录及 schema 2 完成标记；正常结束后可再尝试，成功投影复用，日志保留；真实51页 Word 两次均完成转换并正确报告超页数，产生两个独立已完成尝试 |
| 字体不可用连带关闭表格 | 已解析 XLSX 后以 `?` 传播字体装配错误，整份预览失败；部分字体可能已写入 presentation | 字体先完整读取再装配；缺少专用环境时保留只读表格并显示降级提示，不改生成环境选择；真实表格及环境未配置状态验证 |
| 缓存重用配额/期限错误 | 重用输入仍重复累加文件大小，收据只首次创建，重用未刷新24小时派生期限；直接写稳定路径也可能留下不完整副本 | 仅计新增字节与收据增量；输入副本先同步后不覆盖原子创建，收据原子更新，期限不超过主存储原有效期；配额边界、续期上限和内容一致检查通过 |
| 转换所有权判断不足 | 拿到 helper 锁不代表旧独立 converter 已退出；Popen 未创建子进程却可能遗留 pending 标记 | 新重任务先核对旧 job 所有权；不明状态停止准入；启动失败且确认无子进程时才标记已结束。未制造孤儿进程或替换转换器做测试 |
| 原生退出与输出排空混淆 | `has_exited` 同时要求 reader 完成；直接子进程已退出、输出未结束时，停止逻辑仍可能发送进程组信号 | 继续持有 reader，但已知直接子进程退出后不发信号；正常退出、协作停止、父进程退出后后代正常输出3项检查通过 |

另外修正 XLSX 快速模板列宽设置迭代空集合的遗漏；九份指南明确各格式模板字段，PPTX 快速模板是标题/正文，更丰富的表格和图表由同包 python-pptx 创建，避免把通用字段说明理解为全部格式同一布局能力。
