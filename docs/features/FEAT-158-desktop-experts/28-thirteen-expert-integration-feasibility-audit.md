## 1. 结论与推荐决定

**可以继续沿易界现有专家架构接入，但不能将这 13 个 WorkBuddy 包整体复制后视为可用。** 其中 11 位可以在现有受管资源、单专家会话、普通工具与已选连接器架构内制定适配路径；WindAlice 和美团需要先完成独立连接器协议、认证和生命周期方案，当前不具备直接接入条件。11 位也不代表已经通过运行或在线资格：计算错误、素材来源、实际执行依赖和产物交付仍须逐项解决。

- **代码与资源接入**：真实安装、角色／知识、辅助程序、连接器路由和本地控制链已实现。

### 3.4 真实文件与 App 内预览是两项能力

现有 Native Artifact 接受 PNG/JPEG/WebP、受限 MP4、TXT/CSV/JSON/PDF/XLSX 和专用结构化 report JSON。**不接受任意 HTML/SVG；PDF/XLSX 只保存，没有内联预览；MP4 要求恰好一条 `vide` 轨，常见有声视频的音频轨会被拒绝。** 代码详见附录架构第 7 节，特别是 `artifact.rs:2969–2988` 与 `artifact_video_native.rs:1584–1690`。

工作区生成文件不会自动注册 Host Artifact；目前实际生产者只有图片 provider，另有明确标记的 synthetic 测试 producer。聊天 Markdown 链接是惰性文本，也不是一键打开本地文件。因此：

1. 本地专家可沿现有工具权限，将真实文件保存到用户选定工作区，给出绝对路径、文件摘要和独立核验结果，并用允许的系统应用实际打开／播放。这是可验收的文件交付，但必须明确当前从 Finder／系统应用打开的操作路径。
2. 在 App 内点击打开、HTML 交互预览、工作区产物登记、有声 MP4 预览属于**未实现的产品能力**。如要求纳入该组，需先评审路径归属、来源、类型、大小、生命周期、用户手势与安全协议，源契约先行，不能删检查或借 synthetic 回执伪造真实产物。
3. 跨专家复用现有 report-viz／research 代码时，应在本包显式收录已审版本和许可，或定义正式共享依赖。专家不全局投影，不能直接引用另一位专家的安装路径并假设始终存在。
