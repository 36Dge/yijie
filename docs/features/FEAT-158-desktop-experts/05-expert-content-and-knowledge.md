## 1. 首期专家定位

推荐产品名保留 **资深电商运营操盘手**，副标题固定为 **京东专向**。列表卡片、详情和专家聊天入口均展示平台边界，不能仅在长说明末尾说明。`jd-ops-expert` 可作为候选稳定技术标识；“京小二”是参考包的展示名，不自动取代用户提供的产品名，也不表示其品牌或头像已获发布授权。

推荐简介：“围绕京东开店、上架、推广、履约与复盘，结合本地参考资料整理操作清单，并说明依据、适用条件和待核实事项。”避免宣称“掌握全部 2026 最新规则”“保证出单”“所有参数可直接照抄”。

首期价值是让用户选择一个持续具有明确领域、处理流程和关联技能的专家，减少每次重复描述背景。其范围为京东单平台运营咨询与文档整理，不包含自动登录店铺、修改商品、投广告、报名活动或执行退款。原文的“只做京东”可以迁移为角色边界；其他平台的问题应说明范围并给出正常切换入口，只有易界已安装且支持的专家才可作为可点击推荐，不能把参考中的“盘盘、券姐”等名字当作已接入能力。

快捷问题的产品文案以[03 产品与交互](03-product-and-ux.md)为唯一口径。它们只预填输入框，由用户编辑和发送；普通召唤不因存在 `defaultInitPrompt` 自动产生模型调用或外部操作。

## 5. 按需本地 reference 策略

推荐首期将经审校的内容作为既有受管 Skills 包的本地参考资源，候选用途 `expert_resources` 不进入全局 Runtime skills 投影。角色简述和 `SKILL.md` 保持简短，说明平台范围、定位步骤、引用方式与未知事项处理。专家会话只携带所选专家的必要角色/技能关联；知识全文不进入系统提示词，不在每一轮重复附加，也不注册一套新的知识搜索服务。

Host 将固定完整 baseline 与短角色内容组合为 `baseInstructions`，复用同一 thread 的正常 unsubscribe/resume 路径，让专家上下文与模型、权限、MCP 配置一起生效。只改角色片段替代完整 baseline、另起专家 Runtime 进程、把所有专家 Skill 常驻注入普通会话，都不属于推荐方案。此处是工程设计，实际切换时序和 Runtime 合格性仍待后续验证，不能写成已经支持。

下面是 `yijie-skills` 中的候选源码目录，不是归档内部路径。沿用打包器时以 `jd-ops-kb` 为归档根，包内入口必须是根部 `SKILL.md`，不把嵌套入口当现有格式支持：

```text
skills/jd-ops-kb/
  SKILL.md
  references/
    index.md
    m01-foundations.md
    ...
    m14-creators-cps.md
    source-notes.md
```

内容文件由 `yijie-skills` 维护；首期不修改 `yijie-knowledge` 使其承担一套新的本地 RAG。未来若需远程知识时效更新、检索服务或 embedding，作为单独能力复用 `yijie-knowledge` 并重新做契约/数据评估，不把它夹带进专家接入。

读取步骤要求：

1. 根据用户问题选择模块和规范化场景，先读短索引。
2. 按当前受管包根路径解析 reference，使用正常 Runtime 文件工具读取所需片段；不得依赖开发者本机或 WorkBuddy 的绝对路径。当前权限/沙箱配置是否可读该受管路径必须完成实际资格验证；未证实前不能声称接通，更不能为读知识扩大权限。
3. 同时检查条目的来源、适用范围和内容状态。对冲突、缺失、过期风险或待核实政策只作说明，不生成确定的后台参数。
4. 回答给出结论、适用条件、可执行的正常操作建议和真实片段引用；引用表示“本地资料依据”，不是“已获得京东官方认证”。
5. 片段不足时明确缺什么；不为填满模板编造场景、规则或店铺数据。资料加载失败时使用正常错误提示和重试入口，不能用模型记忆伪装读取成功。

移除当前专家后，当前会话按主设计在允许的时机恢复完整 baseline；后续普通新会话也不继续绑定其角色和 Skill。已有聊天引用保留其当时内容版本与路径身份；资源不再可用时如实显示不可用，不自动换到另一版本制造同一来源的假象。专家的单会话选择、受管包安装状态与全局技能开关是不同概念，不用全局启停技能来冒充移除专家。具体切换、安装保留和历史策略沿用主设计与既有持久化机制。

## 7. 原设计的内容准入范围（历史保留，非当前完成门槛）

本轮不执行全网政策核验，不清洗重写全部原稿，不发布第一版专家。工程接入与内容准入分别记录：加载成功不能证明知识正确，发现知识问题也不要求为了需求草案重做整个京东知识工程。

首个可咨询内容版本的最低要求：

1. 保留来源指纹和原文定位；导出的候选包不修改用户提供的源文件。
2. 14 个模块都有可检索索引与真实片段路径；缺项明确标记，不谎称“14 模块全部内容已完整恢复”。
3. 排除第 4.3 节列出的不当操作建议及同类内容；整理后的角色不因资料声称“合规”就执行它。
4. 修复可确定的算术与提取错误，不能确定的原文标为缺失；为冲突项保留适用范围和“待核实”记录。
5. 涉及时效、处罚、费用、申诉期限和硬性门槛的具体条款，未完成逐条官方核验前不得作为确定现行政策；可降为待核实说明，不阻止普通 SOP、问题梳理和文档整理能力交付。
6. 用少量已审校、非敏感、非攻击性的样例验证引用与角色行为；真实模型与任何付费调用按本需求后续授权执行，不继承其他 Feature 额度。
7. 公开发布前补足资料/头像/第三方文本的来源与许可确认。仅用户提供文件和本机可读不等于取得对外分发权。
