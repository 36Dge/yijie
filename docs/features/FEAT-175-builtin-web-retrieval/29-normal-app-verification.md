## 下一批真实产品样本（待新费用授权）

采用两模型各四个新聊天，共 8 个任务，逐一执行；普通问答、限定站点的资料研究、链接资料采集、指定 URL 读取各一个。只发自然语言需求，保留原生工具发现与调度，不在用户消息中指定内部工具名。

| 场景 | 两模型使用的任务文本 | 预期首个业务检索 |
| --- | --- | --- |
| 普通问答 | 请核对 Python 官方网站，截至今天最新稳定版 Python 的版本号是什么？用 100 字以内回答并附官方链接。 | 原生 `web_search` |
| 研究 | 请研究 Python 3.14 相比 3.13 的三项主要变化，只采集 python.org 和 docs.python.org 的资料；每项给出正文证据片段和来源链接，300 字以内。 | Pro |
| 资料采集 | 请采集三条 asyncio 入门资料，只列标题、网址和一句摘要，供我之后挑选阅读。 | Basic |
| 指定网页 | 请读取 https://docs.python.org/3/library/asyncio.html ，从正文概括 asyncio 的定位和两个高层 API 入口，150 字以内并附链接。 | Fetch |

分别记录首个业务检索与完整任务成功；`tool_search`／Code Mode 发现或编排动作不算业务选路。完整成功须有实际工具结果、可追溯来源和有用最终答复，不能只凭工具被调用。该小样本只用于产品闭环，不替代正式 Q2/Q3 的覆盖和统计结论。

建议一次性、24 小时内使用的 **20 元软停发额度**。8 个用户任务是执行范围上限；普通 App 的自动续轮、子线程及标题请求均计入实际用量，不把任务数写成模型 HTTP 数。固定 Runtime 持久保存原生 `TokenCount` 与 `WebSearchCall`；两模型的原有本机记录也已有 `total_token_usage`、`last_token_usage`。复用这些原生元数据及服务端操作记录，按新样本和新增文件／偏移观察，不创建新计量框架。按线程累计增量计费，避免重复 token 事件重复收费；费用缺失、累计值重置、无法归属或流未完成时停止后续任务，不按零费用处理。

普通 App 不能对每个模型 HTTP 做本批次派发前硬限制，也不能凭 token 事件宣称掌握全部底层 HTTP。**本次产品样本不承诺 48 次模型 HTTP 上限**，历史 Q2 的授权／门禁不改写。24 个原生搜索、12 个 REST 操作是观察停发阈值，不能阻止已在途工作。两模型原有请求／流重试设置均为 0；Runtime 和产品工具调度保持原状。不使用会移除原生搜索或绑定旧授权的历史计量模式。
