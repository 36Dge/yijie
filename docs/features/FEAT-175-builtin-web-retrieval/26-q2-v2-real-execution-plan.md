# FEAT-175 真实 Q2-v2 下一步执行方案

2026-11-15。**本轮仅审计与设计：不改产品／QA 执行代码，不读取供应商凭据，不执行新的付费调用。** 以下正数预算全部是提案，当前新增付费授权为 0。已有一次性 20 元授权已消费，不能复用。

建议顺序：先完成零费用真实传输接线与准入修补，再申请一次新的分段授权，先运行 4 个门槛样本，通过后在同一批次扩至 12 个首次动作样本。此次称 **Q2-v2A 首次动作与停止资格**；完整回答／真实来源和工具结果回灌另列 Q2-v2B，不能把 A 的采样中断算成整项 Q2 通过。

本方案 `contract-impact=none`：提出不可发布 QA 驱动的后续变化；实施时重新核对分类。FEAT-175 产品整体 breaking 治理、B01/B02/B03、S2—S5 与生产门禁不变。

## 1. 当前完成与新发现

已完成：v2 的 12 个首次动作本机样本、12 个完整流程本机样本、配额拒绝场景、14 项评分及 8 项诊断测试；首次动作、原生终态、完整任务成功已分开。Kimi／MiniMax 本机协议使用固定 Runtime 和原有工具组织；这不证明 MiniMax 的真实供应商资格或真实选路准确率。[上一批记录](25-q2-v2-sampling-and-diagnostics.md)

首轮真实 v1 仍为 5 个 Kimi 模型 HTTP、3 次 hosted、2.487164 元保守费用记录，第二个任务失败、其余 10 项缺失；供应商 REST 为 0，账单未核对。旧记录不重写。[真实结果](24-q2-first-live-result.md)

本次补充审计发现一个 **live 前阻塞项**：`check_task` 对已经见过的 thread／turn 检查采样关闭，但未知身份会回落到 active_task。纯本机状态验证中，关闭边界序号为 3，随后首次出现的线程身份仍取得准入序号 5。没有启动 HTTP 服务、Runtime 或供应商请求，不能将此描述为实际发生的付费越界；但它证明当前准入逻辑不能直接开放 live。[源码](../../../../yijie-agent-host/scripts/feat175_q2_v2_meter.py:128)／[审计记录](references/q2-v2-live-readiness-audit.json)

上一批子／根绑定用例覆盖的是关闭前已经登记的身份，不包含“关闭后首次出现身份”这一分支。已执行的本机 PASS 保留其原范围，live readiness 仍为阻塞。

## 2. 必须先补齐的 QA 接线

| 缺口 | 最小实现方式与原生复用 | 进入真实执行前的验收 |
| --- | --- | --- |
| 根任务关闭与未知迟到子线程 | 以根任务／原生代际关闭整个准入；根／子身份从 `turn/started`、`thread/read` 和现有 `nativeApprovalOwnerForTurn` 确认后登记。未知身份不归给最近活跃任务；归属不明只允许有界等待，未确认不派发 | 已知根／子、关闭后首次出现的子身份、下一任务已开启时旧子身份，都不能越过原任务边界或占用新任务额度 |
| 原生子任务停止屏障 | 复用原生生命周期与 `turn/interrupt`，跟踪整个根任务的已知和迟到子轮次；关闭后新身份直接拒绝，退出前确认已拥有轮次都终止。不能只依赖一次 `unfinished()` 快照 | 补固定 Runtime 的正常根／子回环，证明无新准入、无遗留活动轮次；无法确认则 STOP_PENDING，不强杀 |
| 真实 provider 传输 | 复用 v1 的固定两站 `/v1/responses`、原文转发、Responses 观察和断开后继续收集；新增独立受控 live 装配。v2 当前预生成完整响应、预填 EOF 的逻辑仅留在本机路径 | 正常逐段 SSE、正常取消后终态到达、完整 usage／EOF、未知结果分类均有本机证据；请求体和模型／工具参数不变 |
| 取消后的证据与计费 | 记录请求准入、采样确认、收到的 SSE Item 与终态序号。分开“原生可见采样前缀”和“供应商完整计费清单”；停发后才收到的 hosted 也计费并保留 | 不为对账删 Item、制造 native Item 或强填 complete；影响首次先后判断的缺失仍是 INCONCLUSIVE，不能借采样取消掩盖额外 hosted |
| 真实身份／计数／授权 | 替换当前仅用于本机的 `synthetic` 与固定 0 统计，改由实际派发记录产生 `recorded-native`、usage 和费用。新的一次性授权绑定 profile、模式、任务顺序、源锁、价格与额度 | 未授权在读取 Key／启动前拒绝；旧 v1 grant、错 scope、过期、重复使用全部拒绝；Key 只由计量进程读取，不进入 Runtime／日志 |
| 分段计划与逐任务审核 | 在 QA 驱动增加冻结序列和阶段闸门，复用现有离线评分器逐任务检查；无需改 Codex 的工具组织或推理调度 | 参数、原生归属、关闭与计费证据在下一任务准入前核验；不能执行完全部样本后才发现首项关键错误 |
| 真实时间边界 | 将当前 60 秒本机观察循环与真实观察／当前响应收尾期限分开；复用 native interrupt 和正常退出 | 通过正常延迟响应及正常取消验证，不把短 QA 超时判为模型不会选工具 |

绑定解析应沿现有异步方式进行：stdio 通知 reader 内不能同步发 `thread/read` 等待同一连接，否则会造成死锁。[原生复用位置](../../../../yijie-agent-host/internal/codex/native_tools.go:139)

执行准入必须确认被调用的原生活动 turn 和当前任务授权；用于观察已结束 Item 的 `requireActive=false` 归属查询不能单独充当执行许可。无检索结论需要整个根／子任务的自然终态与完整响应证据，不能只见到根 turn completed 就忽略仍在运行的子任务。

真实 SSE 有一项必须澄清的差异：当前本机代码在向 Runtime 写入之前已经看完完整响应，并直接标记 `stream_complete=true`；真实原生中断可能关闭客户端，而供应商终态尚未到达。因此不能机械搬用当前“provider 全集＝native completed 全集”作为采样通过条件。应保留两套清单及它们的映射：已观察到的 native Item 必须有真实对应；未投递／迟到的 provider Item 保留并计费；无法判断是否存在更早未观察检索时仍为 INCONCLUSIVE，不能据代理收到数据的时间推断供应商实际执行时间。[本机实现](../../../../yijie-agent-host/scripts/feat175_q2_v2_meter.py:311)

候选 QA 时间参数：首次动作观察 180 秒；原生采样确认／中断返回 10 秒；单模型 HTTP 从派发起绝对上限 240 秒，闲置读取上限 120 秒；采样关闭后最多继续收集 60 秒且不超过该 HTTP 绝对上限；正常 native 退出最多 40 秒。这些参数须先通过零费用验证并冻结，不修改模型 max_output_tokens、reasoning、原生 rollout／Goal 预算或产品审批窗口。到期但缺 usage／EOF 时记 unknown，不能按零费用结束。

维持一次一个根任务、现有最多一个模型 HTTP 在途的 QA 计量边界，并单独验证其与原生根／子回环兼容；它不关闭原生 MCP 并行。若这项约束妨碍合法原生流程，先回到零费用计量设计，不通过禁用子代理或静默改并行配置制造通过。

## 3. 执行阶段与预算提案

| 阶段 | 范围与顺序 | 费用与准入建议 | 退出条件 |
| --- | --- | --- | --- |
| A0：接线和本机资格 | 完成上表，保留 v1／当前 v2 全部证据，形成新的 live 候选源锁 | 新真实调用 0、费用 0 | 新增迟到身份场景、正常 SSE 收尾、根／子退出、授权和分段账本均通过；再提交具体授权材料 |
| A1：4 个门槛样本 | MiniMax Q2-02 → Kimi Q2-02 → MiniMax Q2-06 → Kimi Q2-06；原提示不变 | 累计软停发阈值 6 元；模型 HTTP ≤16，每模型 ≤8、每任务 ≤4；hosted 观察阈值 8；本机 MCP 每任务 ≤4；供应商 REST 0 | 两模型各有原生搜索与 Fetch 首次动作证据，参数／关闭／usage／归属均合格；无未解决关键错误 |
| A2：扩至完整 12 项首次动作 | 仅 A1 合格后，按 Q2-01、03、04、05 逐类交替两模型；每个模型／case 只执行一次 | 整批累计软阈值提升到 20 元；模型 HTTP 合计 ≤48、每模型 ≤24、每任务 ≤4；hosted 观察阈值 24；本机 MCP 每任务 ≤4；供应商 REST 0 | 每模型固定 6 项均可判定，六类路线及参数达到下节标准；预算、尾流和退出证据完整 |

6 元和 20 元是同一批次的累计软阈值，**不是 6＋20＝26 元**。如果用户一次批准 A1＋A2，A1 的固定审阅闸门通过后可在同一受控进程／账本内继续；阶段切换不重置次数、费用或授权有效期。若只批准 A1，A2 保持关闭。

金额依据是已冻结的 2026-11-15 价格快照和首轮实际 usage；上次 5 个 Kimi 请求的保守记录约为 2.49 元，仅用于规模规划，不是每次请求的费用上界，也不能套用为 MiniMax 的实测成本。正式发起前重新核验官方公开定价并冻结；新授权建议有效期最多 24 小时、单批次一次使用，明确接受在途超额。当前没有新的正数授权。[价格快照](../../../../yijie-agent-host/internal/codex/testdata/feat175-q2/pricing-snapshot.json)

模型 HTTP 包括原生发现后的 continuation、子线程、压缩或其他实际辅助模型请求，不存在“探针免费、不计次数”的例外。无权限或未定价的模型／工具不派发。费用按实际 terminal usage 与 hosted 记录保守核算，缓存折扣未证实则不扣；未知派发不退回次数，不把未知金额计为 0。

工具来源冻结不要求每个请求的工具表字节都相同：Codex 原生按需发现／加载导致的正常声明变化必须能追溯到冻结目录和 Runtime；只有未经登记的名称、schema、策略或实现变化才是漂移。实际 provider 声明及原生搜索模式也要记录，不能只凭静态 profile 推断联网模式；不为验收静默切换配置。

软阈值只能停止新准入，不能保证最终账单不超过 6／20 元；hosted 观察阈值也不是供应商单次 HTTP 内部工作的硬上限。若只接受硬人民币上限，保持 live 关闭，另行提供不改变本次原始请求／模型配置的硬约束资格。

## 4. 停发条件与恢复规则

**正常单任务采样结束：** 首个符合 canonical 结构的检索 Item 出现后，原子关闭整个根任务的新准入，调用原生中断并继续收集已发响应；无检索样本必须自然完成。`sampling_boundary_closed` 属于预期停止，不等于任务成功，也不等于供应商限流。

**立即停止整批新准入并正常收尾：**

- 费用、模型 HTTP、hosted 或本机 MCP 达到批准上限，或出现任何真实供应商 REST 尝试。
- 采样确认之后出现新的准入；根／子归属不明、晚到请求混入下一任务、源锁／profile／工具声明漂移。
- 模型／计费层级不符，终态 usage／EOF 缺失、无法对账、发生未知费用；不追加探针来猜测费用。
- 真实流／模型协议不兼容、非预期审批／权限请求、中断／正常退出无法确认，或出现批准范围外的出站行为。

**停止升级／后续评测并审阅：** 首次工具或关键过滤参数不匹配、无法解释的 hosted 先于预期 MCP、无法判定首次先后等关键路由问题。A1 出现任一此类问题不进入 A2；A2 出现则不继续余项。保留该样本和所有未执行的 MISSING，不补跑替换失败。query 相关性未复核保持 REVIEW_REQUIRED，明确记录审阅者，不冒充独立人工批准。

采样引起的正常 MCP 取消与真实上游错误分开记录；出现供应商工具不可用、模型响应错误或供应商限流时，不能仅因 `first_route` 匹配就升级阶段。真实出站后的供应商错误也不能改记成本机准入拒绝。

退出后该一次性运行已经结束；不能换输出目录、换 grant ID 或用剩余额度自动重启。若需要改描述／配置／预期，先保留失败，建立新候选并重新审阅资格；不得强制 tool_choice、删 web_search、改输出上限、改工具名绕过原生保护或事后降低原样本标准。

## 6. 对 FEAT-175 整体的推进关系

A 通过之后仍须单列 **Q2-v2B**：验证真实模型的工具结果回灌与完整回答，使用有来源资格的实际检索内容。当前 REST=0、采样后中断的预算不能用于证明这件事，也不自动批准新增 REST 或辅助样本。优先复用已有 Connector backend／原生 MCP 回灌机制，先审阅其受控 QA 接法、凭据／内容来源与独立预算，再决定是否执行；不另造搜索后端，不把合成正文伪装成真实网页。

本方案不改写17号原整体 Q2 门槛：首次动作子门槛通过，不代表“每模型真实 native 与 MCP 完整链均成功”。Q2-v2B／真实内容证据具备后才能按原门槛复审整体 Q2。

普通问答默认原生、专家继承／明确禁用的产品接线、云端托管 Key、无需连接器安装授权的开箱能力，仍分别受 B01／B02 和 S2／S3 的产品实现／分发验收约束。A 的技术 profile 结果不能替代新用户 App 到服务端的完整链，Q3／Q4 和正式生产门禁保持未通过。

本轮输出为此方案与[接线审计](references/q2-v2-live-readiness-audit.json)，没有修改上述接线缺口，也没有开放 live。
