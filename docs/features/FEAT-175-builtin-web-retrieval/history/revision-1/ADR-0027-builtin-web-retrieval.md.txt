# ADR-0027：应用内置网页检索、原生工具复用与服务端持钥

## 状态

Proposed，2026-11-15。关联 [FEAT-175](../features/FEAT-175-builtin-web-retrieval/00-feature-brief.md)。用户明确产品目标、服务端托管 Kimi Key 和普通只读按原生权限自动执行；完整架构仍为候选，尚未授权产品实施、付费验证或发布。

## 背景

kimi-web 当前作为市场连接器，依赖安装／选集和逐次 Broker 审批；正文模式 prepare+60s 减去执行预留造成约 23 秒批准窗口。任意专家非空角色还会关闭 hosted web_search。用户要求将网页检索作为默认应用能力并修正这两类行为。

固定 Codex 已有标准 MCP、工具发现、Code Mode、per-tool approval、审批前等待和 elicitation 暂停计时。Host 已有应用内置媒体 MCP 的配置装配模式；Connectors 已有 Kimi REST adapter。主要缺口是产品归属、Host／UI 接线和真实公开凭据供应，而非缺少 Agent 调度内核。

## 候选决定

1. 应用自动装配 yijie_web 标准 MCP，普通／专家聊天默认可用；不伪造市场安装、授权或 selection lease。
2. 普通问答默认 hosted；三独立工具用于研究、采集、URL 读取。保留稳定工具名，更新冲突描述，真实路由按冻结 eval 验收。
3. 专家继承普通有效网页能力；明确受限任务和原生禁用配置仍生效。图片／视频及其他平台审批规则不变。
4. 内置只读工具使用原生 auto 和真实注解，不要求额外 Broker 批准。确认场景复用原生请求与暂停计时，Host 仅投影。
5. 公开用户通过易界产品服务获取能力，Kimi Key 只在 Connectors 服务端。API 拥有资格、必要用量和审计；不在客户端存共享 Key，不在服务端另运行 Agent。
6. Runtime 核心变更目标为零；确有缺口时先提供可证伪证据和最小增量评审，不在 Host 重造已有能力。

## 既有 ADR 的关系

此提案仅将 kimi-web 从市场服务归属迁为应用内置能力，不取消 ADR-0021 对其他市场连接器的当前选集／审批／凭据边界。复用 ADR-0025 的应用内置 MCP 思路，但本期公开目标不能沿用其“仅本机运营预置 Key”的资格。ADR-0018 local direct-entry 不适用于公网服务身份。

## 约束与取舍

Hosted 预检索可能早于模型选择 MCP，不能承诺所有自然语言任务绝对排他。保留实际重复率和费用证据；严格排他需明确任务范围或另审 Runtime 能力。默认可用不表示无限免费，额度政策与公开身份上线条件必须落实。

整体按 breaking source-first；保留旧历史 reader，正常结束旧 turn 后切换新请求。不得自动重放、降库、覆盖运行产物或借迁移改写其他服务的授权。公开发布以完整新用户真实链路验收为准。
