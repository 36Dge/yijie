# FEAT-175 修订 2：跨进程与交付边界

版本说明：本文记录修订2的审计／背景；当时未定的实现细节已由修订3的15／16／17明确，当前复审结论见 [18](18-revision-3-full-review.md)。第一／二版快照均保留；运行资格仍未执行。

2026-11-15，Proposed。补足第二次审计发现，属于当前设计规范；第一版快照仅作历史。用户已确认的服务端托管、原生只读自动执行、免连接器前置不变。这里没有实施授权，也没有新建实际认证或工具协议。

## 1. 身份链必须闭合

Native AuthService 继续拥有主产品 access/refresh token、静默续期及退出动作。renderer、Runtime 和普通 worker 不获得主 refresh token。现有本机 MCP bearer 只证明本机进程调用资格，不能拿来认证公网服务。

推荐在既有产品认证／授权体系中提供**仅检索权限的委派凭据**：限定 audience、主体、租户、允许的三项操作、到期时间及授权版本；不重新设计登录或密码体系。Native 通过正常产品认证取得／续期，使用 owner-only 私有装配通道交给 Host，Host 只在已验证的当前调用中提供给 worker。完整产品 token 不放入 Runtime env 或通用 market 控制正文。

委派／更新／撤销载荷仍须由Contracts源先行。修订3已在15号明确采用API发行的不透明300秒grant、原Verifier验证主会话和typed私有通道；尚未创建实际协议。API按可信主体／服务资格决定费用，thread/turn仅作关联。

退出、换租户、授权版本变化会撤销旧 generation 的新调用资格；旧活动调用按取消与已发送结果处理。凭据到期不自动改用另一账户或开发者 Key；允许 Native 正常静默刷新，但不得无限重试业务 POST。原生审批等候期间不提前预占供应商执行期限，执行前重新核验凭据。

## 2. 本机调用归属与取消

每个内置 MCP 调用须由 Host 验证真实 thread/turn 的当前绑定、用户 scope、进程 generation 和有效权限。复用现有原生通知、会话索引与必要的短期 owner 状态；不让模型提交的 tool arguments 充当这些身份，也不建立另一套 Agent 调度器。

当前自定义 MCP 的 metadata 不保证通用 native call_id。采用 MCP 实际请求上下文＋本机会话 generation 标识一次 handler 调用，分配一次 operation ID；记录它与当前 thread/turn 的关系。不得按工具名／参数摘要合并用户有意发起的两次调用，也不能把 cell_id 当业务幂等键。

取消分三层：

1. Runtime 原生停止／终态撤销本地活动 turn 的准入；Host 通过 worker 私有控制通道取消关联的 I/O owner。这个通道是薄的生命周期适配，不发送虚构 MCP 终态。
2. worker 尽力取消正在进行的产品 API 请求；API／Connectors 在真正派发前检查已知取消状态。跨代理 HTTP 断开不视为已经可靠送达取消，必要的按 operation ID 取消接口必须纳入源契约。
3. 已在供应商发送线性化点之后的调用只能有界收尾、返回已知结果或 unknown，不能承诺远端停止计费。迟到结果保留原 operation 归属，不进入新 turn。

“发送前取消为零请求”只指取消已被该执行 owner 观察并在发送线性化点之前生效，不是用户点击停止与异地服务器之间的零延迟保证。原生审批尚未允许时拒绝则必须零上游。

G2V 必须用固定 Runtime 的正常停止检查实际 MCP cancellation 和 Host 撤销路径。当前源码不能证明外层 future 被丢弃就一定发出 rmcp CancelledNotification；不通过假定它成立来宣称无需适配。如果正规生命周期仍有原生能力缺口，再审最小 Runtime 扩展，绝不强杀。

## 3. 云端复用的正确边界

共享的是参数映射、URL 约束、供应商 HTTP 构造与错误分类、结果归一化及封包预算。**不能将现有 Backend 实例直接全局共享给所有用户。** 它携带 permit、serial Mutex、cancelled 与旧 lease 语义。

新服务端每个 operation 有独立的取消、期限、一次派发状态和结果；共享 credential 只作为受管只读秘密引用。并发／额度属于 API 或 Connectors 服务端明确的准入限制，达到上限就返回 busy，不在旧 global serial.lock 后堆积无限队列。用户 A 的取消不能撤销用户 B 的 Backend 或凭据。

保持真实 readOnlyHint=true。Codex 可能并行调用这些工具，即使 supports_parallel_tool_calls=false 也不能据此保证串行；不得谎报写操作来改变原生调度。必须验证同用户并行、不同账户并行和一个调用取消而另一个正常结束。

## 4. 幂等、状态与费用

幂等承诺限定为**同业务 operation ID 的最多一次派发**，不是供应商 exactly-once，也不保证任意重新进入的模型调用自动恢复同一 operation。

API 作为派发与费用事实权威，按主体／租户＋operation ID 原子查重，绑定规范化参数摘要；同 ID 不同参数返回冲突。修订3明确为：API先持久化ready／额度预占，再发一次内部执行请求；Connectors在供应商HTTP前取得并持久化唯一claim许可。这个claim是保守派发授权点，不证明供应商已经收到请求。禁止服务重启后对已claim或发送结果未知的操作再次派发；API→Connectors、反向代理和供应商层都不能无条件重试有费用的 POST。

候选操作状态至少区分：未派发拒绝、已准入未claim、已获派发许可且可能发出、已完成、claim前取消、结果未知。取消只在与claim原子竞争胜出时保证零请求；已完成结果不能被迟到取消改成未执行。状态与 native Item 终态分别归属，不互相伪造。

必须在公开／内部源契约中包含：执行、只读查询原 operation、尽力取消，以及受控的身份委派。记录中已足够确定失败且未派发时才能释放预占；发送未知不能自动记免费。实际供应商费用和本地预占分开。

本期不建立搜索结果缓存或跨任务证据库。若没有保留原正文，重复查询已完成 operation 只能返回完成事实及 result_unavailable，不能编造原结果或自动再次 Fetch。正常 UI 查看仍用已保存 native Item。用户明确重新发起才产生新 operation 和可能的新费用。

本机重启后不能用新 UUID 自动重放旧未完成调用；沿已有 unknown／恢复边界先报告或查询旧事实。修订3候选为30天operation元记录及UUIDv7新准入时窗，详见15号；过期旧operation不得静默当作新调用。服务端只存最小状态／摘要，不因此持久化完整 query、URL 或网页正文。

## 5. 专家角色政策与用户意图

删除“任意专家 role 非空就禁用 hosted”的 blanket 规则仍是明确目标。但受管资源里存在真的 agent 级离线限制，例如 data-analyst-pro ROLE.md；分镜专家的“脚本不联网”只是脚本实现说明。两者必须人工分类，不自动关键词匹配。

修订3已选择默认inherit，data-analyst-pro现有三个版本保留disabled，绑定精确版本／角色摘要；仅脚本自身限制不影响整个专家。当前角色不改；未来可联网版本另行审阅发布。当前规范见16号，不再将这一选择悬置。

角色原文／许可／数据外传限制不静默覆盖。采用16号的精确政策候选，完整方案接受后才能实施；不扩大为修改所有角色。旧绑定与历史保留，未来资源升级走原生Skills／受管资产机制，不伪造摘要或删除内容。

## 6. 开箱可用的前置必须准确

无需“搜索服务的安装／授权／Key／会话勾选”不等于无需正常 App 身份，也不意味着本需求已经托管了 Kimi／MiniMax 主模型推理。

当前 ModelAvailable 仍依赖相应模型配置。公开验收必须先证明基础 App 给目标账户提供可用主模型服务，再证明它不需要额外搜索配置。本 FEAT-175 不默默新增模型推理网关，也不能把直接调用 REST 的成功当成完整聊天可用。

若基础产品模型服务仍依赖开发者本机 Key，则完整新用户交付被 B01 阻断；不能以要求普通用户再填搜索 Key 或拷贝开发者秘密弥补。真实验收明确列出身份、模型、搜索、受支持制品四项前置及各自来源。

受支持制品还须具有公开分发资格，不能把当前只获 local-use 资格的资源自动视为可向所有用户再分发。本需求不默默扩大现有专家／Skills 的分发许可范围；目标 App 的签名、资源渠道与允许的专家集合需有既有或新取得的明确资格。

## 7. 共享 worker 与时限

共享进程须有明确的启用特性集合：market、builtin_web 各自有独立 capability、准入和关闭动作；关闭市场不停止仍在使用的内置能力，退出 App 才走共同正常 owner 收尾。旧 startup decoder 不理解新模式时失败关闭，不能通过伪造 MarketEnabled 或自动安装旧服务运行。

原生 required=false 不能替代 Host 的组件 readiness 设计：合法的内置服务不可用应显示 builtin unavailable，不凭空令主模型服务不可用；同时不得为了降级而绕过 manifest／来源或原市场安全门禁。builtin-only 与共享场景分别验证实际启动／状态，不能只检查配置字面值。

只有 builtin_web 时不加载旧市场凭据、FD3 模型 Key、OAuth 流程或额外远程目录。可复用 owner／transport，但必须有 builtin-only、market-only、both 三种普通生命周期测试。

云端构建使用选定 server OS／arch 的正规可复现产物。桌面 worker 的 host-target build 不是云端资格；提取共享模块时剥离不需要的本机存储／凭据／控制依赖。部署目标和依赖闭合在 G2V 明确，不覆盖现有二进制。

初始 60／45／35 秒上限保持为候选，但须从真实调用时钟核验。委派凭据读取／刷新、Host 准入及网络传递均有界；真正发送前检查父调用剩余时间是否足以容纳 Pro 完整 35 秒和投递余量，不足则返回未派发，不悄悄降成短预算 Pro。不能用 prepare 时刻提前起算，也不以延长所有时间掩盖阻塞。

最终序列化 MCP 预算必须包含新的 operation／来源元信息以及 text＋structuredContent；不能先得到恰好 65536 字节结果再附加元信息。继续只裁文本、不截 URL，并保留来源和截断状态。

## 8. 路由与阶段门槛

在大规模云端与客户端实施前，先用源契约候选及正规固定 Runtime 验证两模型的 hosted 与 MCP 实际工具表、只读执行、确认、取消和结果回灌。自然语言路由可行性需要独立获批的真实模型小规模探测；未获额度保持 NOT RUN，不能把 mock 路由当作供应商行为。

最终 96 个基础任务保持原计划，但首次有意义的检索提议／参数必须单独评分；先选错再纠正不能改写首次结果。每模型及每类分别报告，额外 hosted 与额外 REST 分开统计，明确预期合法 Pro→Fetch 序列。95%／5% 是候选实验验收阈值，不是总体统计保证，也不是任意输入的确定性承诺。

若共存方案的 hosted 预检索显著违反目标，必须在继续大规模实施前重新审阅任务范围／最小原生扩展选择。不能到最后才发现路由不可达，也不能新增隐藏的 Host 分类模型。
