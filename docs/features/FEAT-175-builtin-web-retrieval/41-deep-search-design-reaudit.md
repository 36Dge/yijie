# 网页深度搜索四项方案复审定稿

2026-11-19。评审对象是本次提出的执行回执、重复搜索收束、桌面合并和并发／校验四项设计。本文给出实施建议与验收条件，当前状态为设计评审。审计采用现有源码、两轮真实记录及离线时序推演，新增线上模型和搜索供应商调用均为 0。

## 四项决策

| 原建议 | 复审决定 | 促成修订的事实 |
|---|---|---|
| 以原搜索操作统一回执 | 保留，补上稳定的操作归属和只读取数协议 | 网关逐个调用生成 UUID，复用映射在进程内。API 现有 GET 只返回状态，POST 在找不到操作时有权创建操作。网关还会把某些已经派发的业务错误降为普通错误码。 |
| 重复搜索时纠偏并收尾 | 修改触发条件，分别控制单项检索与整轮结束 | Runtime 的现有回答收尾会撤下整轮工具。北京时间 08:54:20 已收到第二次复用回执，第一条有 8 个来源的新查询到 08:55:13 才返回，之后还有一次查到 6 条。非空缓存还可能被代码用来首次读取某条正文。 |

## 1. 执行身份、结果与读取

一次模型调用保留一个原生调用 ID，多个调用可以指向同一个原始 `operation_id`。每个调用均保有独立的等待、取消和最终回执，包括同一 `Promise.all` 中的每个子调用。用内置网关产生的受信回执向下游传递三项独立事实。

| 事实 | 典型值 | 权威来源 |
|---|---|---|
| 本调用与原操作的关系 | 首次申请、等待已有操作、读取已完成结果 | 已验证的 Host 轮次和内置网关／API 返回的原操作引用 |
| 派发情况 | 确认未派发、已取得派发许可但发送结果不明、已观察到发送或供应商响应 | API 的原子 claim 与执行器的传输阶段。仅取得 claim 时采取保守处理。 |
| 业务结果与可用性 | 有结果、完整空结果、部分结果、失败或未知，以及正文是否可读 | 原操作的业务结算和有界结果缓存 |

本次 10 次和 19 次对外请求均有对应 HTTP 响应。现有 `web_http_send` 日志写在调用 HTTP 客户端之前，它单独只能证明开始尝试发送。新回执由执行器沿私有结果／结算通道报告传输阶段，API 记录最近可证事实。只有 claim 或传输返回不明时，桌面显示待确认，业务层保留原引用。日志用于事后核对。

**服务端负责同一次搜索至多派发一次。** Host 在现有私有准入通道验证真实根轮次、调用方轮次和能力绑定，在本机会话存储为这个范围保留一个可恢复的不透明引用。调用方从已校验的准入回执取得它。它只划分幂等范围，取数资格始终由产品身份决定。产品 API 继续自行校验租户、用户、网页权限、绑定和授权版本，并自行计算工具及完整参数的规范摘要。对象字段序不影响相等性，数组顺序、关键词、显式数量、站点和日期条件均参与比较。范围和授权版本取首次准入快照。

API 在现有操作存储中为绑定、授权快照、轮次范围和参数摘要建立事务性唯一关联。第一次准入分配原操作，后续相同请求取得原引用。网关可在本机按完整参数加速匹配，跨层关联统一使用原操作引用。受信回执同时绑定本次调用与原操作，以便分别核对归属。在途合并继续使用现有网关等待机制，供应商发送继续使用现有原子 claim。同主体的凭据正常续期保持引用，撤权、绑定更换或不同用户轮次按新权限处理。Host 恢复时先证明原轮次和绑定仍然有效。用户在新一轮明确刷新可以产生新操作。

**增加独立的只读结果操作。** 它复用现有结果缓存，每次读取重新验证当前资格、绑定和操作归属。运行中的原操作返回待完成，已完成且正文可用的原操作返回原结果。正文可能因保留期、容量逐出或进程重启而不可用，统一展示“原搜索已执行，结果详情不可用”，有精确原因时再细分。找不到可读结果的路径具有零创建、零供应商派发语义。历史页使用已保存的展示投影。

**重试以派发事实为准。** 离线把真实的 `invalid_response` 回执交给现有网关后，同参再次进入该层会被选为新操作。这是可复现的网关风险，MiniMax 实跑对此参数只请求过一次。改造后，已派发、可能已派发或结算未知，都保留原操作引用。只有明确未派发、仍有授权、原因可恢复且预算允许的工作才有重新准入资格。显式取消、撤权和无效参数分别按其原因结束。一个等待者取消只结束其等待，最后一个等待者退出、整轮中断或撤权再按既有权限和派发状态处理底层操作。

现有通用失败保护会参考工作目录、输入文件和权限是否变化。对协商支持新回执的内置深度搜索，重发决策由上述业务事实决定，通用权限控制继续生效。决定资格的是原操作的派发状态和当前服务容量。[资格检查](../../../../yijie-agent-host/internal/session/builtin_web.go) · [操作准入与 claim](../../../../yijie-api/internal/modules/webretrieval/infrastructure/postgres/repository.go) · [现有只读状态接口](../../../../yijie-api/internal/modules/webretrieval/interfaces/http/handler.go) · [网关复用记录](../../../../yijie-connectors/worker/src/builtin_web_gateway/search_reuse.rs)

## 2. Runtime 的有限纠偏

在真实内层工具结果返回时收集可信的操作引用和结果事实，在每次模型采样步骤结束时汇总。普通 MCP、通过工具发现后的调用以及 Code Mode 内层调用共用这条规则。一个并行批次只算一次模型决策。即使脚本只打印标题，Runtime 仍能读取原生回执。模型生成的 JavaScript 文本和用户可见标题都不承担执行身份识别。

1. 首次完整空结果应明确给出实际筛选条件和“这些条件下没有匹配结果”。只有成功、0 条、无截断且无丢弃才属于此类。部分结果、全体资料校验失败、忙和正文不可读都采用各自状态。
2. 首次在后续步骤重复索取已知空结果时，返回原引用及一条简短的纠偏信息，允许换关键词、在用户允许的范围内调整条件、读取已有来源或组织回答。非空结果继续支持现有脚本按来源读取正文。首次读某个来源或片段属于有效工作。自定义脚本的产出无法判定时，记为进展未知，应用原任务预算。
3. 对已终态的精确参数保留整轮记录。若一次模型决策全部命中已知完整空结果或可证明相同的已交付标准摘要，且没有其他有效工作，最多由这组重复结果触发一次纠偏续步。这个续步仍可实际执行新参数、读取不同材料和完成其他已授权事项。若模型再次只提出已耗尽查询，Runtime 逐项归还回执，并终止由这些查询引起的采样续步。在途或已提出的独立工作继续。如果整轮只剩重复查询，进入有界作答，确实缺证据时给出部分结果与缺口。连续交替索取多个旧结果也共用一次纠偏机会。
4. 只有整轮已进入交付阶段才复用现有的有界无工具收尾。多事项任务先处理仍可执行的其他工作。已耗尽查询的记录跨越旁路搜索、进度消息和活动分组。用户指定站点和日期时，改词仍须遵守原限制。针对不同措辞查相近主题的情况，先利用已有来源，确有预约办法、票价或日期等证据缺口时继续。主题相似性只辅助选路，完整参数仍决定复用身份。

对受信标准摘要，可比较已交付的操作引用、材料版本及来源选择，忽略耗时、调用 ID 等展示变化。无法识别的新正文读取保留既有原始回执访问能力。工具名层面的屏蔽无法区分一组灵隐寺参数与一组天气参数，具体限制要落实到参数解析后的调用入口。原生 hosted `webSearch` 单独计数。上述规则约束易界可控的工具执行及后续采样，模型仍可能提出重复请求。[现有 Runtime 收尾](../../../../yijie-codex/.yijie/patches/chat-models/0013-answer-completion.patch) · [内置工具回执与 Code Mode](../../../../yijie-codex/.yijie/patches/chat-models/0026-deep-search-model-view.patch)

## 3. 桌面展示与重开

沿用 Host 的白名单投影和现有任务活动组件。给操作引用和派发关系预留固定回执空间，使它们能独立于正文裁剪保存。Native 对同一调用 ID 的开始、完成和重复事件执行幂等更新，Vue 在整个轮次先按原操作引用聚合，再生成各活动分组。卡片留在首次搜索的位置，后来的复用按不同逻辑调用 ID 更新计数，消息顺序和用户展开状态都得以保留。一项操作跨两个分组时，后组只在审计明细保留调用发生的位置。准备中的调用可以显示等待，确认派发后才增加实际搜索数。

Kimi 的同一查询应出现一张“0 条结果 · 已复用 10 次”的卡，审计明细保留 11 条调用。全部 Pro 应显示 10 项实际搜索。MiniMax 按原记录显示 19 项派发，其中 1 项结果无效，另列 5 项繁忙未派发。不同过滤条件即使显示词相同也分别保留。新记录重开后恢复同一聚合。旧记录缺少可靠引用时沿用已有状态和耗时。查看历史不触发搜索。[Host 展示投影](../../../../yijie-agent-host/internal/session/native_deep_web_search.go) · [桌面活动组](../../../../yijie-desktop/src/components/chat/ChatActivityGroup.vue)

## 4. 排队和返回数据质量

保留两个对外执行位和一处有界、可取消的网关队列。先合并同参，再为新操作排队，避免缓存读取占用供应商执行位。队列受容量、公平性、用户预算和端到端截止时间共同约束。MCP 工具总时限为 60 秒，Host 准入回执和 API 执行预算当前各有 45 秒边界，正文请求要求至少 35 秒的供应商预算。入队时记录总截止时间，获槽时复核授权、剩余时长和传输／结算余量，后续各层取更早的截止时间。容量不足或无法留足执行预算时返回明确的“未派发”。取得派发许可后沿用原操作查询进度和结果。

重新计算实际批次后，5 个繁忙返回均在约 5.03 秒。原批次中随后观察到其他调用完成的时间约为批首后 6.66、6.54、6.65 秒，以及最后一批的 5.48 和 7.00 秒。这支持对短时峰值做预算内等待。候选上限 8 秒可用于受控时序比较，最终参数须通过时限关系和实际观测。原来未派发的五项缺少服务时间样本，新调度下的实际成功率留待验证。[现有预算关系](../../../../yijie-contracts/scripts/builtin-web-source.mjs) · [网关容量等待](../../../../yijie-connectors/worker/src/builtin_web_gateway.rs)

供应商 HTTP、原数据解析、规范化、公共契约校验和结果结算分别记录阶段。适配器逐行使用出口的权威约束，可安全规范化的国际化网址先序列化再校验，保留其资源含义和原有 URL 安全检查。有效行保序返回，明确丢弃数和部分结果。非空上游数据全部无效时返回业务错误。诊断保留操作引用、阶段和脱敏字段路径，默认不保存网页正文。离线已证实普通中文路径样例在两处校验上有差异。线上那笔 HTTP 200 后的 `invalid_response` 没有保留可定位的具体字段。[适配器](../../../../yijie-connectors/worker/src/kimi_web_content.rs) · [最终校验](../../../../yijie-connectors/worker/src/builtin_web_executor.rs) · [执行结算](../../../../yijie-connectors/internal/webexecutor/http.go)

## 实施顺序和放行条件

本次文档审计为 `contract-impact = none`。拟议实施按 `breaking` 做跨版本评审。现有私有准入回执和 Native 展示对象均采用闭合 schema，直接发出新字段可能使旧读端拒绝整条记录。先在 Contracts 定义版本化请求、执行事实、只读结果和历史投影，验证 API 和全部读端可接收，再让能力协商成功的新轮次发出新格式。Runtime 原生协议变化遵守其 canonical schema 流程。优先落地防重、只读取数和可诊断结算，再启用桌面聚合与有限纠偏。队列参数独立灰度。新策略按轮次冻结。回退展示或调度时排空在途轮次，服务端继续保护原操作引用和未决状态，历史继续可读。

| 验收 | 通过条件 |
|---|---|
| 固定日志与真实桌面 | 保留既有三主题用例的 9 个请求、3 次派发和 15 条可读来源。杭州零结果组的 11 个逻辑回执一一对应，供应商发送 1 次，跨两个分组只出现 1 张卡、复用 10 次。重复通知、乱序到达、接近回执字节上限和重开均保持计数。 |
| 可交互的模型续步 | 脚本化模型在收到明确空回执后仍重复，纯重复最多触发一次纠偏续步，有明确终态。同一步混合空结果、天气补查和新来源正文读取时，后两项仍完成。覆盖直接调用和 Code Mode，调用与回执逐一配对。 |
| 重试与恢复 | 用原录制的无效回执和可恢复的原操作状态验证同参新增出站为 0。在途等待者分别取消、重连、结果逐出、撤权、未知结算均按各自事实返回。完整参数变化与用户在新轮次主动刷新可重新准入。 |
| 排队与校验 | 以正常受控服务时长覆盖四路提交、两路执行、在预算内释放、超过预算和正常取消。检查峰值、等待时间、实际发送、可用结果分别计数。中英文 URL、有效与无效来源混合、真实空结果分别走正确分支。 |
| 自然模型与交付质量 | 在任务级授权预算内，以同一版本、同一明确行程日期和可比设置，分别运行 Kimi 和 MiniMax 的独立任务。保留一次真实发起到最终回答的证据。评价实际发送、纯重复续步、排队、桌面行数，以及预约、票价、天气等所需信息的来源或明确缺口。若仍出现同一空结果驱动的长串独立续步、过早结束漏掉关键主题，或已派发的同参错误再次出站，该项验收失败。单次自然表现只作为样本。 |

设计验收的硬保证是同轮同参不因复用再次出站、同一操作只占一张主卡、纯无进展续步有上界。模型自然提问次数、有效材料覆盖与交付时长用真实任务衡量。
