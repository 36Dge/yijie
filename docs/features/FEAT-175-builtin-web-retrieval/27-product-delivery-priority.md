# FEAT-175 产品交付优先：主线程决定与执行记录

2026-11-15，用户在本主线程「审计易界联网搜索机制」明确授权调整推进顺序与修改产品代码。本页同步主需求记录，不向其他聊天发送任务。

最新执行要求：收缩 A0，只保留凭据、费用、准入和正常停止护栏；停止扩建通用 QA，以用户能够使用的产品能力为交付单位。优先修正真实会话的专家联网规则，再完成服务端托管检索→Host→App 的最小闭环。每次产品变更只做相应定向验证，复用已通过的证据。

此前的“暂不修改产品代码”已由这次明确授权取代。付费调用与公开分发仍需各自的明确授权；此前真实验证的一次性预算已消费，不能自动续用。Runtime 核心与现有制品不修改，不发布、不迁移日常数据、不自动提交或推送。

## 交付顺序

1. **专家联网规则。** 将已有同源政策接到真实 `contextForExpert`／恢复入口；普通已验证专家继承用户的原生搜索模式，明确离线的三个已审版本保持禁用；未资格化受限版本不自动放开，正常移除后恢复普通配置。
2. **服务端检索执行。** 复用现有 Kimi adapter、认证／权限、操作记录和正常取消机制，供应商 Key 留在服务端。保留有界费用、准入与幂等／未知结果护栏，不另造搜索引擎或 Agent 调度器。
3. **Host 与 App 接线。** 内置工具自动配置，不要求安装／选择旧 kimi-web；复用原生 MCP、tool_search、Code Mode、auto/prompt 与现有结果展示。只开放已就绪且有权限的服务能力。
4. **定向闭环。** 用实际产品路径和普通本机上游完成对应验证；真实模型／搜索调用与公开分发单独授权，不将合成内容或本机通过描述为公开可用。

S1 已有源契约、最小 Host 候选和 Q1 原生协议证据；正式整体 S1／Q2 与发布门禁未通过的部分继续如实记录。用户已明确允许产品最小闭环先行，不再把通用 QA 扩展作为这些产品源码改动的前置。保留原 A0 草稿和运行证据，但不继续投入其通用能力。

## 当前产品变更

专家规则修复已进入 Host 产品源码：真实资源解析成功后安装 `WithExpertWebPolicy`；原生配置仅对明确 disabled 政策或未验证的内部角色上下文保留禁用，不再把所有正常已选择专家一律禁用。没有强制设置 live，也不覆盖用户已有 cached／disabled 选择。

这项修改 `contract-impact=semantic`，执行已生成的 builtin-web-retrieval/1 专家政策，不增加外部字段。FEAT-175 整体仍为 breaking；服务端与跨进程接线继续 source-first，正式发布资格不因本页改变。

## 2026-11-16 产品实施结果

本轮已完成以下**本机候选源码**，没有继续扩建 A0 通用 QA，也没有切换日常 App、部署服务、提交或推送。

| 交付单位 | 实际变化 |
| --- | --- |
| 专家联网规则 | 真实专家选择／恢复入口加载同源政策；普通已验证专家保留用户原生搜索配置，三种已审离线版本禁用。新内置检索执行入口再次核验当前专家；旧 `kimi-web` 待审批调用也受离线政策约束，已完成的历史审批回执不改写。 |
| 服务端 | API 新增委托、执行、状态、取消和撤销入口；复用 OIDC、成员关系与 RBAC 的 `web.retrieve`。Goose 00005 保存绑定、授权摘要、操作与审计事件；原子 claim、租户每日有限调用额度、同用户并发 2、操作 ID 防重复。供应商 Key 只进入服务端执行器的受管私有启动管道。 |
| 执行器 | 新增 Connectors `cmd/web-executor`，API／执行器使用受管 mTLS。每次执行复用已有 Rust Kimi REST adapter 和一次 HTTP 许可，正常 EOF 取消，不增加供应商 SDK 重试或另写搜索客户端。 |
| Host／共享 worker | 新内置工具复用现有 worker、owner 控制管道、官方 rmcp、原生 MCP／tool_search／Code Mode。Native 安装委托后自动提供三工具；Host 的私有只读准入回调核验当前根轮次、原生子线程归属、专家政策和停止记录；工具执行不依赖市场选集。 |
| App | 标准产品会话自动取得、续期及撤销 web 专用委托，经原 Native 管道交给 Host；搜索 Key 不进入 App。只读调用使用原生 `auto`，结果复用现有网页资料组件。服务无资格／不可用时不阻塞普通原生搜索。 |

产品实现复用的原生能力仍是固定 Runtime 的工具组织、调度、权限和事件。新增回调仅判断是否允许本次服务请求，没有新增 Agent 调度器、内容搜索引擎或用户审批系统。子线程归属以当前根轮次的原生 `subAgentActivity/started` 或原生 spawn Item 为证据；不会把无法证明的旧子线程归到当前活跃轮次。跨轮次复用的旧子线程不自动取得新检索权限。

定向验证已覆盖：专家入口政策；两模型原生搜索选择／离线／移除的既有本机证据；实际固定 Runtime＋新 canonical 共享 worker 在两模型下无选集发现工具及 Host 准入链路（5 次本机模型 HTTP、2 次本机准入，供应商 REST 为 0）；实际原生子线程归属；新建隔离 PostgreSQL 的授权／执行／重放／额度／取消／两种撤销入口；本机 mTLS；现有 Kimi adapter 的服务端复用；Native 类型与秘密格式化；网页结果展示。源契约定向测试、三个 OpenAPI、同源消费检查、Go vet、Rust 编译与前端定向检查已通过。具体边界和制品见 [product result](references/product-integration-result.json)。

复审修正了三个实际接线问题：当前 Runtime 的子线程事实是 `subAgentActivity/started`，不能只识别旧 collab Item；旧连接器待审批调用必须执行离线专家政策；服务端尚未派发时的不可用错误应显示服务不可用，不能伪装成用户主动取消。未知发送结果仍保留 `may_have_dispatched`，不自动付费重发。唯一同操作重试限于明确未派发的产品 401，并等待 Native 的新委托。

## 激活边界与下一交付单位

目前**不是所有安装用户已开箱可用，也不是正式 S1／Q2／发布验收完成**。API 检索默认关闭；Native 的自动委托入口使用标准产品身份。现有 `local + demo_fast` 固定本地身份尚未获得公开服务的检索资格，本轮没有把它当作公网账号。日常客户端仍运行原有制品。

下一交付单位是把该候选放入正常 App 入口，并打通实际运行环境的服务身份／资格：部署方配置服务端 Kimi Key、API／执行器证书、可达入口、有限额度，并将 `web.retrieve` 配到普通用户的默认产品角色；用户不需要逐人安装或授权搜索连接器。API 配置入口为 `YIJIE_API_BUILTIN_WEB_ENABLED`、`YIJIE_API_WEB_DAILY_TENANT_CALLS`、`YIJIE_API_WEB_EXECUTOR_ORIGIN`、`YIJIE_API_WEB_INTERNAL_ADDRESS` 及 `YIJIE_API_WEB_{CERT,KEY,CA}_FILE`；执行器入口为 `YIJIE_WEB_EXECUTOR_ADDRESS`、`YIJIE_WEB_API_ORIGIN`、`YIJIE_WEB_SERVICE_{CERT,KEY,CA}_FILE`、`YIJIE_WEB_WORKER_MANIFEST`、`YIJIE_WEB_KIMI_KEY_FILE`。这些由部署维护，不进入用户设置页。

公开激活前仍需完成主身份／默认资格实证、同一批 Host／worker／App 制品接入、旧 `kimi-web` 新请求选集迁移及冻结历史兼容、元数据保留清理／多实例取消资格、不可变 Contracts 引用和发布检查。仅把 `web.retrieve` 加入目录不代表已经给用户默认资格；关闭 feature 是本候选的回退方式，保留已写入的操作计量，不执行破坏性降级。

真实 Q2-v2 仍未执行。本轮真实模型及付费搜索调用均为 **0**；之前已消费的一次性预算不复用。后续真实验证仍按用户已限定的“两模型及原生搜索，Basic／Pro／Fetch REST 为 0”另行确认一次性额度。上述未完成项不能由本机 mock／协议通过替代，也不作为继续扩建通用 QA 的理由。
