## 产品变更

**Demo 身份。** `local + demo_fast` 走固定 `127.0.0.1:18890` 的专用服务入口，复用原 Native 私有凭据文件格式与严格读取器，以 token 和 run epoch 认证，再从服务端查询固定主体的有效成员关系和 RBAC。公共 `api-server` 继续走 OIDC，不能使用本地凭据登录。Native 自动获取、续期、撤销 web 委托；Host／共享 worker 只有在同源 `local_demo` 配置下才能使用这个精确 loopback 地址。

**默认角色。** API Goose 00006 为已有 `task.create` 角色一次性增加 `web.retrieve`，并推进受影响租户的授权 revision。新默认 owner/member 角色包含该权限；原 v1 七项能力投影保持兼容。以后明确撤销权限不会被启动或重复 migration 补回。Demo 主体只在首次创建本地角色时初始化其默认授权。

**旧选集。** 新工具选择列表不再展示旧 `kimi-web`，启动也不再安装或自动启用它。Native 在新请求冻结前剔除该引用，真实 provider preflight 使用归一化后的选集。SQLite 0048 只记录这些新请求的原始选集；请求 HMAC 仍绑定原始输入，重试使用该原始记录校验。既有快照、回执、历史展示和已冻结 outbox 不改写，重放不依赖当前安装状态。

## 正常启动与停止

`development-client.py` 的现有服务启动／停止路径加入内置网页服务；固定 Swift 入口使用同一组合路径。`builtin-web-session.py prepare` 是明确的初次部署／迁移步骤，普通 `ensure` 仅检查 schema、按源码更新受管开发产物并启动，不能隐式迁移。

复用原本机 `yijie-postgres` / `yijie_api`，不建立第二套业务存储。网页 API／执行器为受管本机服务，复用原执行器、共享 worker 和 Go mTLS 客户端；Kimi Key 文件由服务端读取，Native 只得到短期委托。内部证书和 Native 私有凭据位于 Infra 已忽略的 generated 目录，路径不导出给 Vite。

正常退出先撤销 Native 委托，再正常停止网页 API／执行器与原专用工作流服务；保留共享 PostgreSQL 和所有 volume。退出仍未完成时保留进程与记录，不强杀。正常入口的 `build` 动作复用原源码核验、分组件构建和产物校验，只省略最终打开 App，避免验证期间恢复队列／计划任务并触发模型费用。
