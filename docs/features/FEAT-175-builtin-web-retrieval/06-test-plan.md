## 路由稳定性的冻结规则

计划 24 个基础输入：无需联网、普通时效问答、研究、仅列表、正文采集、明确 URL 读取六类，每类四个自然表达，包含中文／英文、用户明确过滤及 URL 仅为示例的反例。两模型每例重复两次，基础 96 个任务；另做普通／专家同提示对照。真实执行前冻结输入、期望及计分，不在看到失败后删样本或加点名工具提示。

| 指标 | 候选门槛及解释 |
| --- | --- |
| 首次主要路径正确率 | 每模型 48 个基础任务分别 ≥95%，另报告六类各 8 个结果；首次有意义的外部检索动作和参数符合冻结预期。tool_search 的本地目录查询不计外部检索；先选错后补对仍记首次错误 |
| 关键明确任务 | 明确 URL、站点／日期限制、纯链接列表的固定用例全部符合其工具／参数要求 |
| 无需联网 | 固定无需联网任务不得产生搜索／抓取；URL 仅为示例不触发 Fetch |
| 同需额外 hosted 检索 | 分母为每模型研究／列表／正文／URL 四类的 32 个任务；分子为其中出现非预期 hosted 的任务数，重复次数和费用另报。候选门槛 ≤5%，含服务端预检索，不排除失败任务 |
| 额外 REST 与恢复 | 分别记录首次错误、无效参数零发送、额外 Basic／Pro／Fetch、合法预期 Pro→Fetch 及后续恢复；不能只看到最终有 Pro 就计首选正确 |
| 证据与重复调用 | 不伪造 URL／正文；未改变条件或未获用户明确重试时，不重复失败操作；额外收费调用完整计入 |
| 调用成本／延迟 | 记录模型 HTTP、REST 次数／usage、确认等待、MCP active time／provider 时间；不将 API 次数当总 Token 费用 |

门槛为候选产品验收，不是已有实测结果或统计学普遍保证。若原生 hosted 预检索导致门槛不可达，应重新审阅 05 的任务范围方案，不通过增加 Host 隐藏分类回合、删工具响应或伪造成功修补指标。基础规模需结合真实预算批准；未获额度不能把缩小冒烟写成完整路由评测。

路由判定、HTTP 执行成功、正文交付、答案来源支持分别记录；正确工具遇真实服务失败可“路由正确／执行失败”，不能把两者混为全通过。首次错误经用户纠正后成功只计恢复证据。按实际模型 HTTP 与 hosted／REST 次数计预算，96 个任务不是 96 个 HTTP 的上限。

## 三项最终验收

1. Core vertical：真实新用户 App→正常身份→固定 Runtime→应用 MCP→云端 API／Connectors→Moonshot→结果→模型回答；原生普通问答另有独立请求证据。
2. Accessibility/visual：在真实 App 检查上述主要状态、亮暗最小窗口及键盘，不把组件测试当实机已过。
3. Teardown：正常退出、有限 HTTP owner 收尾、无工具补发、重开历史可读；服务端 unknown 可查事实而不自动再次执行。

仅运行相关、正常、非破坏性验证。跳过用户禁止的强杀、可执行文件替换、权限破坏、恶意资源／危险归档／攻击注入；记录未覆盖范围，不伪造全量安全或生产验收。不得为构造错误状态操作真实生产账户。
