## 首次动作与完整任务分开

| 维度 | 判断依据 | 不可误读为 |
| --- | --- | --- |
| `first_route_verdict` | 原生 `item/started` 的首次 webSearch／MCP 动作、参数、顺序与归属；复用 v1 canonical 校验及评分 | 模型意图解释、完整答案成功或稳定性达标 |
| `task_execution` | 原生 turn 的 completed／interrupted／failed | completed 就说明答案正确 |
| `full_task_success` | 完整执行与绑定原始证据摘要的答案／来源审阅 | 采样中断、合成材料、仅首次选择正确就是成功 |
| hosted 统计 | 每次原生搜索、首次之后的次数、首次 MCP 返回前的次数分别记录 | 普通问答的额外 hosted 不需要统计 |
| 样本来源 | `sample_kind` 与 `scorer_calls_provider` 分开 | 离线评分意味着原始样本没有真实调用 |

首次选路模式在观察到真实原生 Item 后关闭该任务的新准入，再调用既有 `turn/interrupt`。当前在途响应和终态继续保留，不截掉不利证据。MCP 不返回合成网页正文，等待原生中断返回后取消；模型不会因收到假正文而继续补查。自然完成抢先发生时记 `natural_completion_race`，仍不判完整任务成功。

关闭准入的边界是本机计量器的确认序号，不承诺“首个 Item 出现的同一瞬间停止所有供应商工作”。确认之前已准入的响应保留并结算；本批全部是本机模型，未因此建立真实费用控制资格。

“无需检索”只能在自然完成且证据完整后确认。首次工具选错后的纠正仍单列，不能覆盖首次错误；同一个原生 MCP Item 的参数若在后续事件中改变，不允许用新参数覆盖第一次观察。归属仍由原生祖先关系解析，不从 Code Mode 字符串或模型参数推测调用。

完整流程模式保留正常 continuation，用于观察额外 hosted、工具执行与 turn 终态。合成模型完成全部步骤只构成本机协议通过，`full_task_success` 保持 `NOT_EVALUATED_SYNTHETIC`；真实样本 failed 仍为 FAILED。

## 拒绝诊断

新计量器记录串行 journal 序号、闭合原因码、准入面（model／mcp／control）、任务／模型、原生 thread／turn、当时计数和首要拒绝引用，不记录 query、工具参数、凭据或任意异常正文。

模型总量／每模型／每任务上限分别为 `model_total_limit`、`model_model_limit`、`model_task_limit`，MCP 上限为 `mcp_task_limit`。采样关闭导致的后续请求记 `sampling_boundary_closed`，它是预期采样停止，不伪装成供应商限流，也不污染下一任务的全局失败状态。旧任务的晚到请求仍归入旧任务，不能占用新任务额度。

并发拒绝按实际进入 journal 的顺序记录；后续 `run_stopped` 指向首要拒绝，不改写第一原因。该序号证明的是观察到的准入顺序，不宣称能重建未观察到的网络发送先后。

## 实际本机验证

结果与源码摘要见[机器检查](references/q2-v2-checks.json)、[保留核验](references/q2-v2-preservation.json)。

| 验证 | 结果与边界 |
| --- | --- |
| 首次动作采样 | 12 个样本、16 个本机模型请求；4 个自然完成、8 个原生中断；合成正文交付 0，边界后新准入 0 |
| 完整流程／重复 hosted | 12 个样本、24 个本机模型请求，全部原生 completed；两模型普通检索各出现 2 个合成 hosted Item，额外次数正确记录；真实完整任务资格不授予 |
| MCP 配额拒绝 | 第五个不同的正常只读请求被拒；明确 `mcp_task_limit`、任务／轮次与计数 4，Runtime／meter 正常退出；正常并发单元用例另验证后续拒绝的原因关联 |
| 离线评分／诊断 | 14 项评分、8 项计量与正常并发测试通过；包含首次错误后纠正、参数改变、采样归属、无检索未完成、子／根任务共用边界、live 入口拒绝 |
| Go 检查 | 固定 Runtime 的三个本机场景均使用 race；纯 profile／对账 2 个顶层检查与 5 个子项通过；Go vet、语法与格式检查通过 |
| 旧真实失败只读重评 | Python 任务为首次选路 MATCH、完整任务 FAILED；两次 hosted 在首次 MCP 返回之前、首次之后额外 hosted 共 2 次；其余 10 项仍缺失 |

配额场景的内部 Go 驱动按预期非零结束；外层只授予“配额拒绝诊断通过”，不把它写成完整流程成功。对应日志和首要／后续拒绝序号保留在[配额证据](references/q2-v2-quota.json)。

第一次配额试验用了并发相同请求，实际被原生 `YIJIE_OPERATION_PENDING` 提前拦截，未达到 MCP 配额。该次记录保留为配额未验证，之后改用五个不同的正常 RFC 读取请求；没有关闭或绕过原生防重复保护。复审同时收紧了场景验收：配额场景未观察到指定拒绝时不得因为普通流程完成而返回成功。

## 完整复审结论

| 检查点 | 处理与证据 |
| --- | --- |
| 采样中断被误算任务成功 | 单独输出首次路由、原生执行终态、完整任务成功；中断／合成结果不授予完整成功 |
| 合成正文造成后续补查 | 首次模式不发送正文，等待原生中断返回后取消；本机 8 个工具样本验证 |
| 普通问答 hosted 重复被漏记 | 独立统计所有 hosted 和首次后的次数，普通问答也覆盖 |
| completion 修改首次参数 | 拒绝同 Item 参数变化；不把参数正文输出到异常日志 |
| 拒绝原因被泛化／并发覆盖 | 闭合原因、计数、绑定和串行序号；首要原因保留，后续引用 |
| 子任务／晚到请求混入下一任务 | 复用原生 ancestry；根／子共用计数与采样边界，旧请求保留旧任务归属；有离线绑定与计数用例 |
| 历史付费证据或授权被重置 | 只读重评另存输出；原 v1 源与 75 个原真实运行／授权文件逐字节核验 |
| 本机脚本越界为付费执行 | CLI 只有 local，拒绝 live 和凭据参数；没有新供应商出站路径 |

本轮未新增子代理工作流的端到端运行验收，不能把离线归属／共用计数检查表述成完整子代理中断资格。完整 Q2 自然选路、真实回答与来源质量、供应商费用、Q3/Q4、B01 与产品分发仍未通过；本机脚本生成的正确选择不代表真实模型准确率。后续真实 v2 还需受控 provider 执行接线及新的明确授权，本次不自动开启。

没有运行包含历史危险 fixture 的全量测试；没有强杀、可执行文件伪装／替换、权限破坏或攻击注入。所有本机 Runtime 均正常结束，日常 App、数据库、发布状态和各仓 HEAD 保持。
