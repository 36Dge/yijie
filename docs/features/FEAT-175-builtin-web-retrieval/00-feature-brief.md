## 用户已明确的结果

- 普通问答默认使用当前模型供应商的原生 `web_search`。
- 研究、资料采集和已知网页读取按需使用 Pro／Basic／Fetch。
- 修正“存在任意专家就关闭原生搜索”的逻辑；专家身份不再作为禁用搜索的条件。
- Kimi 网页工具成为应用内置能力，不要求用户安装、授权连接器、配置搜索 Key 或在会话中勾选。
- 本轮用户进一步明确：**供应商 Key 由易界服务端托管；普通只读检索按 Codex 原生权限自动执行。**
- 最大限度复用 Codex 原生工具发现、组织、执行、审批、超时和结果继续生成；当前实施包括S1／Q1与Q2接线；随后一次性获准的真实Q2已停批，真实供应商REST仍为0。

## 推荐架构

采用**应用自动装配的标准 MCP 服务 `yijie_web`**。它与普通聊天的原生hosted搜索共同可用；默认专家继承普通规则，data-analyst-pro现有三个明确受限版本按精确身份保留网页禁用。REST和Kimi Key留在服务端；Native保有主产品会话，worker仅使用API发行的最长300秒不透明网页委派。

保留三个稳定工具名 `kimi_web_search_pro`、`kimi_web_search`、`kimi_web_fetch`，将 title 与描述分别收敛为“研究网页”“采集来源”“读取网页”。这样能复用既有检索执行约束、结果类型、历史 reader 和 REST adapter，不为改名新增 Runtime 补丁。

默认 `approval_mode=auto`，保留真实 `readOnlyHint=true` 等注解，由 Codex 原生策略决定是否询问；不通过 Host 伪造批准、不全局强制 approve。内置工具不再创建市场 selection lease、`decide_call` 或 `prepare+60s` 截止。

完整设计见 [05 技术方案](05-technical-design.md)，逐项原生复用证据见 [11 源码审计](11-native-reuse-audit.md)。

## 交付范围与分发边界

完整目标包含“其他用户安装 App 后默认可用”。因此候选 Profile 为 `production_hardened + public`：共享运营凭据、多个用户的服务资格与费用边界必须由服务端承担。此 Profile 是方案范围，不代表用户已批准上线、费用或生产操作。

本机直连和预置 Key 可以用于明确授权的开发验证，**不能作为完整目标的交付替代**。不将共享 Key 打包进 App、写入普通用户 Keychain 或借用户的 MiniMax Key 调用 Kimi。正常易界产品身份可复用，不增加搜索服务独立 OAuth；现有 public 身份上线条件尚未完成，需要作为公开交付依赖记录。

## 关键取舍

1. 以标准 MCP 扩展代替重做 Codex 搜索内核；服务端只做工具执行，不运行另一个规划 Agent。
2. 复用原生审批与有效执行时间。已有 Runtime 支持审批前等待及 elicitation 暂停计时；23 秒问题来自易界 Broker 额外期限。
3. 不用隐式自动勾选旧连接器冒充内置能力，也不整体关闭所有聊天的 hosted 搜索。
4. 自然语言选择是模型行为。Kimi 可能在模型决定 MCP 工具前执行 hosted 搜索；现有原生协议没有已验证的“免费语义分类后再决定 hosted 工具表”入口。默认并存方案以实际路由指标验收，不能承诺任意研究问题零额外原生搜索。若要求绝对排他，需另审明确任务范围或 Runtime 增量，不擅自增加 Host 分类器。
