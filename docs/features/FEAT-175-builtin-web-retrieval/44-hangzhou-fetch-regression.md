# 杭州天气重复取页的复审、修复与回归

2026-11-24。原请求于北京时间 11 月 23 日 23:59 发起，跨午夜后中断。同一段进度出现四次，中国天气网杭州页有四个分别完成的服务端操作。回归保留原始记录，使用单独的 PostgreSQL、临时 Host 与 Runtime Home、同一份录制网页正文。

## 复审后补上的条件

1. **一次读取由接收端计数。** 四条模型调用拥有不同的调用 ID。数据库按授权绑定、授权版本、调用方与根轮次范围、工具和有效参数确定同一原操作。并行等待、操作复用和 HTTP 实际读取分别计数。Fetch 走独立的版本化请求和结果校验，先前的 Pro 端点继续使用其原有定义。
2. **比较模型实际收到的材料。** 第一次集成回放发现 Code Mode 只对 Pro 应用了结果序列化，Fetch 的网关复用已经命中，模型侧仍收到不同的包装。修复覆盖了 Code Mode 取值、直接调用和 Runtime 收尾判断。脚本可以读取原始结构的细节。只有已交给模型的相同材料才能用于判断重复。原生检索新条目及空状态查询单独识别，打开新网页和页内查找仍算独立工作。
3. **撤下工具后需要适合作答的上下文。** 两次真实 Kimi 补答都在工具集已为空时返回了原来的进度句。对照请求使用同一网页后生成了逐日预报，同时揭示了回放日与原请求日相差一天的问题。正式回归随原问题提供真实的原请求当地时间，Kimi 的实际结果逐日与原网页核对。
4. **最终作答仍属于原轮。** 仅在已证实重复 Fetch、原生收尾条件满足时，Runtime 为这次模型请求保留原用户输入、有效来源及其他工作的结果，合并同一原操作的重复工具回执，移除重复进度和当前步骤的旧推理。最后放回同一份真实用户输入。正文保持工具结果身份，提交、执行历史、权限和原生终态各自保留。已到达模型的七天预报可以与录制正文逐字核对。长网页中部的气象术语说明会受正常的上下文截断预算影响。
5. **历史读法与真实执行次数独立。** 阅读视图按同一用户输入段内的完整进度正文折叠。流式前缀首次出现差异时立即显示完整的新消息，最终答案独立呈现。展开可定位重复进度的原位置。旧天气记录中的四笔真实派发仍然是四笔。

## 可复跑入口

从[原方案](43-fetch-repeat-and-turn-completion.md)的四个验收环节取证。录制网页接口只监听本机并只接受记录中的杭州网址。真实模型验证只允许在只作答请求中联系 Kimi，该请求不声明任一工具。共享的额度目录在每次发送前以独占文件占用一个名额，跨进程重试共用同一额度。

- [回归协调器](references/check-hangzhou-fetch.py)读取显式配置的隔离库，启动、正常关闭本机网页与模型回放服务，核对接收端读数、Host 终态、Native 实时视图、SQLCipher 重开和组件中可见的正文数。
- [模型步骤回放](references/replay-hangzhou-fetch.py)从指定原始 JSONL 读取工具调用、托管搜索和公开进度。未指定真实模型凭据时，终态由本地脚本提供，只能验证协议。真实模型验收需要核对供应商 HTTP 完成回执与桌面最终正文摘要。

## 实测结果

| 检查 | 实测 |
|---|---|
| 将原记录四次请求单独送入 API | 四个不同调用 ID 共用一个原操作，录制网页的 HTTP 接收端收到 **1** 次。另一轮四个并发请求使用同一 URL 的不同片段，也只读取 **1** 次，并与上轮使用不同的原操作。 |
| 完整回归 | 第一次取页得到七天正文，第二次同参调用触发纠偏，第三次同参调用后进入只作答。该轮服务端账本恰有 **1** 个已完成操作、**1** 个派发凭证，网页接收端读数也是 **1**。 |
| 真正的最终回答 | 第五个模型步骤的工具集为空，只有这一最终步骤由真实 Kimi 执行。Kimi 返回 HTTP 200，原生轮次终态为 `completed`。第一轮通过核对的公开最终正文为 522 个字符，供应商输出和桌面最终文本的 SHA-256 均为 `8de473c9bce4f88ec7fceea73edf866130ed826777bea575d842045e05e54904`。 |
| 内容核对 | 11 月 23 至 29 日七行天气和有记录的气温逐日匹配。23 日如实标出网页仅提供 10℃，24 日为晴、14℃／4℃，25 日为多云转小雨、13℃／6℃。答案引用原中国天气网杭州页。 |
| 实时、重开与浏览器 | 新轮原始事件有三条同文进度。对真实 Host 通知进行 Native 投影、写入隔离 SQLCipher 并正常重开后，Vue 实时视图与重开视图均只有 **1** 条可见同文进度和 **1** 份最终回答。Chromium 在 1180×760 的亮、暗两种主题下也分别测得 **1／1**。原中断轮在两种主题下为 **1／0**，其原始四笔派发保留。 |

在授权的最多 8 次 Kimi 模型请求中共用了 **5 次**。两次验证了单纯禁用工具时的重复进度和有界失败，一次对照验证了收尾请求的组成，最后两次分别使用修复候选和日常构建实际选用的网页 worker 生成了通过核对的真实最终回答。前四个模型步骤由公开历史记录驱动，天气网站的正文来自本机录制服务。复用了原问题和原始当地时间，测试没有把回放日当作预报起点。


## 日常客户端

本机原网页库以标准迁移入口从版本 8 扩展到 9。迁移前、迁移后及最终构建后均为 346 条网页操作，原事件的四笔已完成操作全部保留。固定日常入口完成仅构建，校验了当前源码、Runtime、worker 和应用包内的桌面可执行文件。易界 App 保持关闭，专用服务正常退出。

日常构建的 worker 使用独立的编译缓存，产物摘要与先前隔离构建不同。因此对日常选定的实际 Runtime 和 worker 又做了一次隔离回归。服务端和录制网页接收端均为一次读取，实际三条同文进度折叠为一条。日常产物验证中的最终正文为 531 个字符，供应商与桌面摘要同为 `fcb5f468987cc9ed3e2e77047017e108029b6f8dd9d69977320b922082781613`，七天的天气、页面所列温度和来源均匹配。亮、暗两种 Chromium 界面均显示一条进度和一份最终答案。[分层结果、构建摘要及额度记录](references/hangzhou-fetch-20261124-result.json)
