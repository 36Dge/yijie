## 架构方案比较

| 方案 | 结果与代价 | 结论 |
| --- | --- | --- |
| 自动安装、自动勾选旧 kimi-web，延长 Broker TTL | 继续耦合选集／审批，仍会关闭普通原生搜索；也不能解决新用户无 Key | 不选 |
| 应用标准 MCP＋服务端托管，复用原生发现／调度／权限 | 能取消前置操作和额外审批，保留确定的 REST 适配及双模型入口；需补公开服务与薄接线 | 推荐 |
| 新 Runtime web.run／自建统一搜索引擎 | 将第三方业务接入放进 Runtime，增加维护及兼容，已有 MCP 可覆盖主要能力 | 不选 |

| 路由方案 | 取舍 |
| --- | --- |
| 原生模型选择＋明确工具语义＋schema＋eval | 复用最多，无额外分类请求；无法保证 hosted 预检索绝对排他，当前推荐 |
| 明确任务／Skill 范围在 turn 前配置工具表 | 可做确定范围，但不能变成每次必须人工选连接器；未结构化自然语言仍不能自动推定 |
| Host 关键词分类或额外 LLM 分类 | 错判、多一轮费用和第二套调度；不作为本期方案 |

## 风险与解决条件

| ID | 风险 | 控制／验收 |
| --- | --- | --- |
| R01 | 本机预置冒充分发能力 | 新设备／干净账户无 Kimi Key 的真实服务验收；Key 仅服务端 |
| R02 | 无意产生原生＋Pro 双重搜索 | 实际 wire／供应商事件统计重复率；门槛不达标不宣称稳定，不能删失败样本 |
| R03 | 仅去 Broker 倒计时却遗漏 Host 反向请求拒绝 | 补 canonical elicitation 薄投影，正常等待后批准和取消各有真实 Runtime 用例 |
| R04 | 历史保留旧 web_search=disabled 或旧工具定义 | 正常 idle/unsubscribe/resume 与旧历史读取；实际请求工具表检查，不清历史 |
| R05 | App 默认能力造成费用失控 | 服务端资格／用量／并发／幂等准入；运营额度和资费值上线前配置；无自动业务重试 |
| R06 | 移动 adapter 后产生两份不同归一化逻辑 | 提取 Connectors 内部共享模块、同源生成类型；禁止重写 Go／前端解析器 |
| R07 | 改名漏过 Runtime 检索 guard | 保留三个稳定名称后缀；不增加工具 alias 或伪装原生 web_search Item |
| R08 | 只把 renderer 名称改掉，结果不显示 | 普通 native MCP Item 到现有 WebRetrievalResult 的实际 UI 验证 |
| R09 | 原生只读 auto 被误写成所有工具 approve | 精确 server/tool 配置；其他市场写操作不变，默认与 prompt 分别验收 |
| R10 | 子代理未继承 MCP，被误当作工具已全局可用 | 保持原继承边界，记录实际可用范围；不为研究开启全部第三方 MCP 继承 |

查询、页面和工具结果是外部数据，不授予新的执行权限。参数／URL／响应大小、秘密脱敏沿既有安全边界；用正常输入、正常拒绝与只读审查验证，不执行攻击注入、恶意 fixture、权限破坏或强杀。

## ADR 与开放事项

[ADR-0027](../../adr/ADR-0027-builtin-web-retrieval.md) 记录应用内置归属、市场例外和服务端密钥边界，状态 Proposed。用户这次目标取代 kimi-web 的旧选用前提；不能据此改写 ADR-0021 对其他连接器的已接受要求。

仍需在完整设计／公开上线前落实：正常产品身份的可用发布基线、部署区域／域名、运营账户、默认额度及收费政策。若要求“完全匿名、无任何 App 身份”，须另审访客额度和滥用控制；不能默认为客户端设备 ID 即可信。完整方案审阅不等于授权这些生产操作。
