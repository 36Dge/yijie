## 修复

`contract-impact = semantic`。在启用了普通聊天发布协议的 Kimi 根轮次中，Runtime 记录对当前用户输入实际完成发布的进度正文。托管搜索后，可能相同的流式前缀先暂存。新字符表明正文有变化时，原有消息继续正常发布。完整正文确认为同文进度时，其供应商原始响应进入同一轮审计记录，公开消息的开始、预览、正文增量、完成和历史进度事件均不会产生。明确的最终回答按其原始阶段处理。用户追加输入后重新建立该段记录。

出现已播报的进展和经工具回执确认的空目标查询时，下一次判断是否继续工作的采样通过 Kimi 的严格 JSON Schema 约束文本部分。模型可以选择交付，也可以通过原有工具读取已知来源或针对确切缺项请求补查。文本判断本身保持私有，公开答复由原生作答流程交付。同期返回的新材料、已接纳的补查和其他未结束的工作继续适用原有执行规则。[Kimi Responses 文本输出格式](https://platform.kimi.com/docs/api/responses)

## 计数口径

- 供应商端按完成的原始消息 ID 和正文统计。保留完整文本摘要，并与本轮 JSONL 中保存的原始模型响应逐条核对。
- 实际播报分别取自原生实时 `item/completed`、落盘 `event_msg.agent_message` 和 `thread/read`。还按消息 ID 检查开始、预览和正文增量，防止被拦消息曾经短暂出现。
- 每组均包含开场。模型在同一响应中提出的工具调用与进度分别核验。缺 30 日的样本核对补查前实际可见的六行材料、补查理由和查询，以及最终交付的七行天气。[回归入口](references/check-hangzhou-hosted.py) · [原生核对](../../../../yijie-agent-host/internal/codex/hosted_search_followup_integration_test.go)
