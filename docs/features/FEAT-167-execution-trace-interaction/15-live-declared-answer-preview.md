# 普通与专家会话的正文流式预览

2026-11-21 本机开发候选。适用于 MiniMax-M3 和 Kimi K3.1 Pro 的普通与专家根会话。此前两次普通对话的正式正文分别为 2,015 和 1,472 个字符，Host 各在轮次结束前约 13 和 15 毫秒发出一个完整分片。

## 发布与阅读

- 供应商原生阶段和预先确定用途的采样继续沿用原生消息生命周期。在尚可调用工具的采样里，Runtime 流式解析完整公开声明，对通过既有解析器的助手正文发出独立的 `item/agentMessage/previewDelta`。每片携带原消息 ID 和 UTF-8 字节偏移。阶段冲突后由正式发布规则确定归属。
- 新能力需要已配对 Runtime、公开消息 v2 和显式预览协商。Host 为预览订阅保留独立连续游标。普通提交和模型选择复用已鉴权的 HTTP 协商。专家正式提交走 Native 专属控制管道，由启动子进程的 Native 明确选入同一预览能力，原授权与回执继续生效。已加载会话变更发布能力时复用原生空闲检查、退订和恢复操作。
- Native 在内存中拼接有界预览，正式快照和持久化仍使用原有数据格式。重复偏移去重，缺少开头时等待能够证明来源的正文。正式消息可按真实后续工作归入处理过程。成功、停止和失败的状态由原生事件决定。
- 桌面在合并渲染帧前记录本轮新到达的消息。同一帧收到完整正文和完成事件时，首次实时展示仍使用原有阅读节奏。历史重开直接读取完整正文。正式终答触发一次自动折叠，后续更新尊重手动展开。
- 契约影响按新增协商能力交付。Runtime 本地提交为 `1e517e2c7a0c69bfb9fbc27a69b0dbf7e3f06dc9`，Contracts 本地提交为 `a1101880f60726c056bf859bb61389e299df6e66`。相对前一版本的 Native OpenAPI 定向 breaking 检查通过，两个 Runtime 的正式消息开始、正文增量、消息结束、轮次结束及线程读取 Schema 逐字节相同。

## 验收方法

用本机回环响应端按已知间隔返回两次截图的正文，并独立检查只在完成时返回全文、先声明终答后调用工具、用户正常停止、重复事件和旧订阅。记录供应商开始发送可见正文的本机时间，以及完整易界桌面窗口首次出现部分文字的时间。这个区间包括本机传输、Runtime、Host、Native 和渲染。生成中必须能观察到至少两个严格递增的正文长度。

仓内复验入口为 Desktop 的 `scripts/replay-public-message-publication.py --preview`、Host 的 `TestPublicMessagePublicationExchange`、Native 的 `publication_sse_sqlcipher_reopen`，以及 `scripts/check-public-message-browser.mjs <exchange> --expect-preview`。浏览器回放验证分片对应的画面，完整桌面实测单独计时。证据目录位于工作区 `.local/audits/declared-stream-20261121/`。

| 旧版订阅与恢复 | 同一会话降为 v2 时预览计数为零，恢复协商后重新收到 14 个预览分片。两个订阅的游标均独立连续。 |
| 专家私有管道 | 两个模型各完成一次真实本机专家资源安装、授权和提交流程，各收到两段连续预览和唯一正式答复，重复读取回执没有触发生成。 |

## 最终候选的真实前台首字 P95

2026-11-21 17:22:28 至 17:30:39（北京时间），在真实易界桌面客户端的前台 WKWebView 上完成 80 次有效计时。每个模型分别测 20 次短对话和 20 次连续长对话。计时期间保持自然滚动位置。目标为 P95 ≤ 200 毫秒，每组取从小到大第 19 个样本。

| 模型 | 短对话 P95 | 短对话 200 ms 内可见 | 长对话 P95 | 长对话 200 ms 内可见 |
|---|---:|---:|---:|---:|
| MiniMax-M3 | 50.2 ms，达标 | 20/20 | >3,500 ms，未达标 | 8/20 |
| Kimi K3.1 Pro | 51.2 ms，达标 | 20/20 | >3,500 ms，未达标 | 8/20 |

短对话在发送前有 0–4 轮历史，连续长对话有 47–86 轮。短、长两组等权汇总后，MiniMax-M3 的 P95 为 >3,500 ms，Kimi K3.1 Pro 为 >3,500 ms。两种模型的整体首字延迟均超出 200 ms 目标。

计时起点为本机回放端发送首段可见正文，终点为 macOS 确认前台窗口对应位置能命中本轮回答文字。长对话里，可访问性树出现首字的 P95 分别为 54.1 ms 和 56.5 ms。屏幕取证显示，部分新回答已经生成，但可见区域仍停留在上一轮，首字坐标命中底部输入区。截图中的长对话样本为 `PERF-3206-k`，可见区域的最新回答仍为 `PERF-3205`。

每轮最长观察 3,500 ms。MiniMax 有 6 次、Kimi 有 5 次在完整观察窗内仍未见首字。超过观察窗的样本以最后一次确认不可见的时刻作为下界计入，长对话的 P95 因此报告为下界。另有 2 次在前台已确认超过 200 ms 后窗口失焦，这些样本同样计入超时。有 1 次试验在能判断 200 ms 指标前失去前台，原始记录保留，并为对应位置补采。
