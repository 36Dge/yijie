# 普通会话公开消息阶段与折叠验收

2026-11-20，本地开发候选，适用 MiniMax-M3 和 Kimi K3.1 Pro 的普通／专家根会话。

## 发布规则

Runtime 在首次发出公开的 `item/started` 时写入 `commentary` 或 `final_answer`。随后每个正文增量引用相同的 item ID，`item/completed` 和历史记录保留同一决定。模型的原始响应继续作为模型上下文保存。

混合用途的采样请求先暂存没有充分证据的文字。提供方的原生阶段优先。Runtime 校验完整条目中的声明，接受明确的进度说明；同一步骤内实际出现后续工作时，先发出此前完成的待判定消息，并记录来源 `subsequent_work`。成功提交整轮时，Runtime 按最终实际采用的 ID 发布答复。有效终答声明记为 `declaration`，无声明的终答记为 `turn_commit`。来源、顺序和前序条目支持延迟发送和重开。混合用途下的完整终答可能在供应商已经生成完毕后才开始展示。此发布逻辑复用原采样请求。

已经预定用途的步骤可以按既定阶段流式展示。中断、失败、被替代或触及显示上限的待判定文字可以通过有界的 `unpublishedText` 详情查看。显示缓冲上限为单项 256 KiB、每轮 2 MiB 和 128 个待定项。

Desktop 用本轮第一条带 `final_answer` 的可读正文触发一次自动收起。空开始事件、进度、重复事件和轮次结束保留当前实时开合状态。点击重新展开后，后续正文保留该选择。全新打开历史会话时，过程默认收起，回答正文可读。

## 验收结果

事件序号来自各会话独立的 Host SSE 流。“首次公开”取第一条公开助手文字的 `item/started`，折叠计数取 Chrome 中实际 ChatTurnGroup 按钮的 `aria-expanded`。Native 逐条消费真实 HTTP/SSE 字节并保存到 SQLCipher，再关闭数据库、重开并将读回的视图交给全新页面。另起一个 Runtime 进程执行 `thread/read` 比对公开消息 ID、顺序、阶段、来源和正文。

| 场景 | 首次公开 | 正式答复首次公开 | 进度期间折叠 | 整轮自动折叠 | 历史结果 |
| --- | --- | --- | ---: | ---: | --- |
| MiniMax Blink 回放 | #7 commentary | #91 final_answer，declaration | 0 | 1 | 11 条一致，回答可见 |
| Kimi E25 回放 | #4 commentary | #10 final_answer，turn_commit | 0 | 1 | 3 条一致，回答可见 |
| MiniMax 真实供应商 | #7 commentary | #10 final_answer，declaration | 0 | 1 | 2 条一致，回答可见 |
| Kimi 真实供应商 | #206 commentary | #248 final_answer，declaration | 0 | 1 | 2 条一致，回答可见 |

Blink 回放保留了原始 11 个公开消息 ID、10 次采样边界、13 次本地 MCP 调用及 3 次提供方网页调用。MCP 从本机返回记录中的结果，包括两次失败。9 条无声明的过程说明全部由后续工作确认为 `commentary`。E25 的归档保存了三条正文和时间，缺少原始消息 ID 与工具参数。回放分配了三个可复现的 ID，未重放缺失参数的工具操作。第三条原始终答共 998 字。

两次正式供应商验收均从本机 Host 的模型会话和权限轮次 HTTP 入口发起，每个供应商各返回两次响应。验收仅提交独立的单位换算题，每次上限 2048 个输出 token，工具关闭。原案例商业正文仅用于离线回放。浏览器逐修订重放 Native 输出，供应商用量不包含浏览器重放和历史重开。四个场景中，读者手动展开后都保持展开。

使用正常的 `turn/interrupt` 在 E25 最后一条文字发送中取消，折叠 0 次。已收到的 96 个字符以中断详情保存，重新打开仍可查看。重复同一 SSE 游标未产生额外提交。原始 Blink SQLCipher 格式 6 的 44 项仍可读，其中 9 条旧消息仍无阶段。

## 易界桌面窗口复核

从标准开发入口构建并启动隔离的易界 AI.app，使用固定回环响应服务，分别选择 Kimi 和 MiniMax，在任务输入框提交完整轮次。两次均在正式回答出现后显示收起的“已完成”按钮。点击后可看到两条进度；从侧栏重新打开两段会话时，过程收起，最终正文可见。通过应用退出命令正常关闭后，只读检查这两轮的 SQLCipher 记录。两轮均为格式 7，三条助手消息的首次事件和最终快照均为 commentary、commentary、final_answer，ID 和来源一致。窗口复核独立于表中两轮真实供应商调用，桌面记录位于本地证据目录的 desktop-ui/receipt.json。
