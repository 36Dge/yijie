## 原生 MCP 审批薄适配设计

选用固定 Runtime 默认启用的稳定 `ToolCallMcpElicitation`（features/src/lib.rs:1264），工具配置 `approval_mode=prompt`。不关闭此 feature，不启用实验性 `item/tool/requestUserInput` 兼容分支。Codex 决定是否请求审批及实际执行；started 可以先于审批，不能当作远端已执行的证据。

主路径为 `mcpServer/elicitation/request`：原生 core/src/mcp_tool_call.rs:1321/1681 产生 `mode=form`、空对象 requestedSchema，Prompt 无本期会话/永久授权选项。Host/Desktop 只承接请求并转交本次用户决定。

1. 真正关联字段是 JSON-RPC request ID、threadId、可空 turnId、serverName。原生协议没有 itemId/可靠结构化 toolName，禁止解析问句、到达时间或唯一活跃 Tool 来猜卡片归属。显示为对应线程/轮的“原生 MCP 请求”面板。
2. 本期只支持已核实配置的 sorftime、可信当前非空 thread/turn、普通空表单、无待填必填字段及已知确认形状。仅投影 manifest 允许的普通站点/ASIN。原始 URL、metadata、错误对象及可激活链接不进入 UI。metadata 只帮助识别/展示，不能作为许可或工具身份权威。
3. 其它服务器、未知形状、无可信 turn、一般表单、URL、openai/form、安装认证、requestUserInput 保持拒绝。接受来源必须是用户对当前实际请求的明确决定，不由只读注解、模型文字或本地推断批准。
4. 本次接受原生响应为 action=accept、content={}、_meta=null；用户拒绝为 decline；主动取消按原生 cancel 语义。原生失效显示“已失效”，不能伪装用户拒绝。没有 persist 或自动记忆权限。
5. 复用已有有界 RPC callback 与 `serverRequest/resolved {threadId,requestId}`；Runtime 管 pending 请求及 Turn 变更取消。允许短期回调/响应回执关联，不新建审批业务状态机、不持久保存回调、不设本地超时制造终态。断开/原生失效后禁用旧操作，晚到点击不补发或复活请求。
6. 保持 FEAT-152 三模式语义，首期验收使用请求批准；不把 MCP 伪装成 Command，也不切“帮我批准/完全访问”来替代适配。FEAT-137 不恢复。

## 兼容方案与实现边界

本次只更新文档，实际 contract-impact=none。未来功能保守 breaking：现有权限 kind/status 和 NativeItem 均有闭合边界，新增请求类型、字段和持久读取不能假设 additive。

1. Contracts 先依固定 canonical schema 定义最小安全 MCP 请求/响应及 Tool 投影，保留 nullable turn、无 Item 关联和 native action。决定真正需要的版本/字段，不机械沿用旧 v8 提议、不原地改旧 schema。
2. 固定 Host/Desktop 兼容 reader 与生成类型；验证旧 v7、历史 DTO 与 native_views 可访问、新字段/新枚举的方向行为。当前 deny_unknown_fields 可能使单个新 Item 破坏整批历史，不能按旧 HEAD 自动 unknown 假设回滚。
3. reader 就绪后才允许 Host 新投影、新审批请求和新持久字段写入。不能先生产新值再补 reader。旧消费者不兼容时明确版本拒绝，不破坏旧历史或删新事实回滚。
4. 复用唯一 NativeDisplayBuffer、SQLCipher、thread/read/resume，完整 Item 直接替换；审批 callback 不进入持久层。保留真实 v4/v5 兼容消费者，不新建状态推演/历史重建/正文对账/自动封口。仅受影响来源更新真实 commit/digest/pin。
