# FEAT-176 · MiniMax M3.1-Flash 接入与默认模型切换

2026-11-24 · 修订 2 · 需求草案 · 本机未公开产品 · 工程实施待评审

升级后打开易界，新聊天的输入框直接选中 **MiniMax M3.1-Flash**。展开模型目录，默认项也是它。用户可以直接发送第一条消息，易界通过 M3 已配置的 API Key 调用 `MiniMax-M3.1-Flash`，每次默认明确发送 `reasoning.effort = "xhigh"`。MiniMax M3 仍是可手动选择的独立模型。

## 产品约定

| 项目 | 本需求定义 |
| --- | --- |
| 显示与身份 | 显示名 `MiniMax M3.1-Flash`，API 模型 ID `MiniMax-M3.1-Flash`，供应商 `minimax`。建议易界 profile ID 为 `minimax-m3-1-flash-xhigh-v1`，便于精确关联选择、执行和轮次。 |
| 两个默认值 | 全新草稿和成功受理后的下一份新草稿默认 Flash。易界目录的 `default_profile`、初始菜单选中项和首次实际提交一致。底层 Codex `model/list` 的唯一 `isDefault` 也指向 Flash。用户在当前草稿主动另选模型后，刷新目录尊重这次选择。 |
| 思考深度 | 首版提供一个 Flash 配置 `xhigh`。普通回合、标题、计划草案及沿用该模型的工具后续请求都取此配置。模型菜单沿用现有交互，无须先选择档位。 |
| 同一把 Key | Flash 与 M3 共用已有 MiniMax 凭据来源及轮换方式。在产品的其他基础服务就绪、仅配置 MiniMax 模型凭据时，正常客户端也能启动并发送。Kimi 专属网页工具可单独显示不可用。目录的“可用”表示本地配置及 Runtime 就绪，账户是否获准调用 Flash 由供应商实际响应确认。 |
| 计划与其他入口 | 计划对话同样使用聊天框默认值。新建、独立选择执行模型的计划表单继承目录默认 Flash，用户可以改选。有目标聊天的新版计划沿用该聊天确认的选择。 |
| 交付范围 | 用户明确产品尚未公开，可一次升级全部组件。实施目标是当前本机普通入口。历史聊天、已保存计划和旧回执兼容均已移出需求。 |

MiniMax 公布的上下文窗口为 1,000,000 tokens。Flash 始终开启推理，支持 `low`、`medium`、`high`、`xhigh`、`max`，省略档位会使用 `max`。易界采用既有 Responses API。该协议的字段是嵌套的 `reasoning.effort`，Chat Completions 和 Anthropic 的字段只适用于各自协议。[模型调用指南](https://platform.minimax.cn/docs/guides/text-generation#chat) · [Responses API](https://platform.minimax.cn/docs/api-reference/responses-create)

## 用户操作与反馈

1. 从易界当前本机入口打开新聊天。输入框显示 Flash 与 MiniMax 图标。目录加载完成且模型可用后可直接发送，打开页面或单纯选择模型产生零次推理请求。
2. 发送一条消息。思考、回答和工具活动使用现有展示区。回答上的模型标签取自本轮提交的模型。用户可以正常停止、继续聊天，在空闲时切到 M3 或 Kimi，再切回 Flash。
3. 在普通或专家聊天使用已启用的技能、附件、检索和工具。批准、拒绝和工具结果沿现有链路回到原轮次。创建新计划时先审阅执行模型，再保存或授权。
4. 目录加载期间禁用发送。完整目录的四项全不可用时，保留菜单可见的模型并显示各自原因。收到空数组、重复项或错误默认值时提示目录不一致并允许刷新。默认 Flash 不可用时仍显示所选模型，用户可以明确改选可用的 M3。模型请求结果不明时先查询原操作。
5. 本地受理前失败保留可编辑草稿。受理后供应商拒绝或中断，原问题和所选模型留在该轮，用户可查看原因再决定是否重试。一次 Flash 权限错误不会触发后台改用 M3 再发一遍。

## Must 验收

以下验收均使用升级后创建的会话、计划和操作。步骤、观测点及真实供应商验证范围见[验收方案](02-verification.md)。

| 编号 | 可观察的交付结果 |
| --- | --- |
| AC-001 | 新聊天、易界目录、Codex 原生目录和首次实际提交一致。当前草稿手选生效，下一个新聊天恢复默认。 |
| AC-002 | 仅配置一份 MiniMax 模型 Key 时，正常客户端能启动并通过该凭据使用 Flash 与 M3。能区分本地缺配置和供应商拒绝。 |
| AC-003 | 同一原生请求链在首轮、多轮和工具结果续答中实际发送 Flash 模型 ID 与 `xhigh`，使用正确的 Responses 字段。 |
| AC-004 | 同一新版会话可在空闲时切换模型。新轮次的标签、有效模型、思考深度和原生 thread 对得上。活动回合与待审批时按现有规则锁定。 |
| AC-005 | 文本、图片及现有文件上下文能走完发送和流式回答。推理、正文、上下文用量、自然失败和正常停止均按原生事实展示。 |
| AC-006 | 函数工具、技能、子代理、自动审批和已有文档及媒体入口遵循现有权限。继承 Flash 的子调用使用 `xhigh`，工具结果可继续生成回答。 |
| AC-007 | Flash 能使用已启用的原生网页搜索。来源属于相应的搜索项，有可靠标题时显示标题，仅有网址时显示网址。专家和连接器遵循各自的工具权限。 |
| AC-008 | 自动标题与计划草案按 Flash/xhigh 生成并通过本地格式校验。无效标题不影响主回答，无效草案不能保存或授权。有效的新计划按审阅过的执行模型运行。 |
| AC-009 | 正常入口启用新数据库格式并能重开，Native 能接收 Flash 的创建、读取及恢复回执，本版会话、计划和轮次均可正常写入。 |
| AC-010 | 在真实易界界面无需点选模型即可取得 Flash 的可读回答。可区分供应商用量、已受理请求与本地未派发操作，恢复或查看状态不会产生隐式重发。 |
