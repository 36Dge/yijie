## 3. Alpha主流程与状态

打开正常产品App→选用Kimi连接器→沿原七个场景输入执行→通过原审批→本例应有工具成功→聊天区出现回答。保留七个会话、八个用户回合：E5两回合，E7单回合Pro→Fetch；不换成点名工具的三个冒烟用例。允许逐例累计通过，不为完整fresh批次重跑已通过项。

| 状态 | Alpha处理 |
|---|---|
| idle | 沿用原Key和选择器，缺凭据时正常提示 |
| loading | 正常等待模型/审批/工具；运行中不算工具成功 |
| success | 对应工具成功且回答可见即可通过，不评判回答内容 |
| empty | 工具成功空结果后有回答亦通过，不要求非空chunks或正文 |
| error/denied | 未成功调用或没有回答则不通过；不伪造成功 |
| retry | 正常修复或显式重试未通过项，不因标准层缺项重跑已通过项 |
| cancel | 沿应用正常取消/退出；取消本身不是成功 |

保持现有UI和权限，不安排额外视觉、历史重开或failure/retry验收。正常产品行为不因Alpha而移除。
