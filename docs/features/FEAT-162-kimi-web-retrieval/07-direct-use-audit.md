# FEAT-162 直接可用流程审计

2026-10-24。用户要求认真审计调整方案后实施，并进一步明确取消“本地绑定、已配置未启用”，要求安装易界客户端后可直接使用。本文先于本轮产品代码修改。05与06保留为上一版本方案和验证历史，不能据其PASS推导新要求已经完成。

## 审计结论

现有方案的密钥复用和单次调用边界可以沿用，但产品激活流程需要重做；不能仅把界面标签改成“已启用”。当前仍为local/demo_fast候选，完整的新安装分发并未通过上一轮验收。真实/models、Search、Fetch及模型调用继续禁止。

| 项目 | 当前证据 | 判断与处理 |
|---|---|---|
| 用户操作 | Desktop connectorPrimaryAction仍提供configure/enable；Provider Auth只绑定并返回disconnected/not_qualified | 与新要求不符。取消Kimi单独配置和人工启用流程，由客户端自动准备 |
| 新设备凭据来源 | launcher只在本机已有文件时设置YIJIE_KIMI_API_KEY_FILE；Native验证owner-only文件，Host加载此值 | 新安装不能自动取得开发机凭据。需要用户明确采用“已有模型凭据自动复用”还是“服务端统一提供能力”；不得假设打包共享Key |
| 每次启动可用性 | Native从SQL恢复历史configuration/authorization，但明确重置connected/effectiveEnabled；现有observe仅查已建立的活能力 | 自动可用必须重建当前Host下的工具能力；不能把持久状态直接当成有效授权或网络验证 |
| /models前置条件 | Kimi Probe目前真实GET/models后才登记本地工具 | 与零网络自动准备冲突。若采用已有模型Key自动复用，准备只验证本地来源、固定描述和当前scope，实际401/403/余额等在用户真实调用时处理；不得将本地准备称为供应商认证已验证 |
| 用户停用与卸载 | 当前有独立安装generation、desiredEnabled、suspend/forget及原操作回执 | 自动准备须保留明确停用/卸载意图，避免刷新或重启后自动恢复用户已关闭的服务；现有本任务安装记录继续保留 |
| 凭据载体 | Host只以匿名FD3传已加载快照；值不进入新增env/argv/public IPC/Keyring | 范围符合已授权复用。模型和连接器按同一Host生命周期取值；密钥变更沿正常重启 |
| 描述符失败清理 | worker成功打开FD副本后，先判断FIFO再接管原始FD；非FIFO返回会遗留原始FD | 局部清理缺口。若保留该载体，需在验证后所有退出路径关闭已确认有效的原始FD。只做普通资源/EOF验证，不制造故障或攻击注入 |
| 不必要的Keyring依赖 | Kimi Forget仍走通用credentials::forget，而新流程不再保存Kimi Keyring值 | 新流程应明确是否保留历史独立配置迁移；当前本地候选实际未保存过独立Kimi Key。不得让新用户的移除动作依赖另一份不存在的密钥 |
| 调用控制 | Gateway保留当前选集、scope/generation、每次批准和单次HTTP；REST禁重试/重定向，结果使用SecretGuard | 保留。自动准备不发送业务请求，也不自动批准、重放历史或新增Agent循环 |
| 验收证据 | 06只证明已配置未启用及无HTTP；D4明确NOT RUN | 需新增首次启动、当前已有安装、重启恢复、无来源和用户停用保持等证据。真实供应商权限/质量仍不能标PASS |

## 必须先确定的一个产品输入

用户已选择第1项：自动复用客户端已有模型凭据。以下保留审计时的边界比较：

1. 客户端已拥有Kimi模型凭据时自动复用，不再配置/启用连接器。这延续现有Host/Connectors架构；无模型凭据的新设备仍须完成统一模型配置。
2. 新用户连模型Key也无需配置。需要服务端持有Kimi凭据，客户端使用易界账号/服务身份访问受控能力；需要现有服务端的身份、权限、配额/计费与部署来源，不能靠前端默认已启用实现。

该输入现已明确，按08实施方案开始第1项的实现。继续保留原生搜索、Codex内核、现有调用审批和用户的零收费调用限制。

## 实施顺序与验收标准

1. 确定上述来源后，先更新05的产品流程和权威契约语义。整体FEAT-162保持breaking；当前仍只允许local candidate/release:false，不推送或发布。
2. 定义Kimi内置默认安装、自动准备、明确停用/卸载保持与当前启动代际重新准备。使用原Native权限、安装/操作回执、Host控制和Broker，不创建新Agent循环。
3. 完成凭据/后端准备后，界面直接呈现可使用状态；来源缺失、准备中和实际调用错误如实显示，不再呈现“本地绑定”按钮。
4. 普通测试覆盖首次安装、已有Kimi记录、重开、合法空来源、重复刷新不重复建记录、停用保持、当前选集和每次调用审批不变。只用普通合成值、内存和正常EOF。
5. 正规生成同步和来源freeze/build全部通过后，再验收真实App。当前不执行/models、Search、Fetch或模型请求；“已准备可调用”与“真实供应商调用成功”分别记录。
6. 收尾记录最终来源、UI与未执行项，正常退出并释放共享App；不改写其他Feature的实现或验收结论。
