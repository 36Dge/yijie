## 2. 决策取舍与场景闭环

期限选择保留旧模式，避免为了新能力改变已有合法晚批准；不采取所有模式一律要求满预算或扩大TTL。双截止同时覆盖批准前过期、及时批准后越A、投递迟延、执行到D和撤权取消；2秒是产品预留，不是时延保证。可信外层MCP预算未核定时禁止激活新模式，这一实施前置不能以worker接收时刻推算冒充。

结果选择“新模式部分保留+明确计数”，不因一页缺URL丢掉所有有效来源。无效字段整页舍弃，避免再引入复杂逐chunk错误协议；正文裁剪用一个content_status表达，不重复增加page.truncated。旧Basic/Fetch严格保持原结构和错误语义；新旧reader及加密历史兼容必须由Z1证明。参数、空/部分/错误、重复/取消/恢复、期限、UI可访问性、授权/费用/日志及回退分别由22号对应规则和Z1—Z10覆盖，没有将计划检查记为已执行。

验收选择保留真实产品工具集合，接受“费用前置不满足就暂不运行”，不靠删工具/强制选择或额外提示得到通过。新增E6/E7覆盖本次核心默认路由及受约束串联，E5采用自然的两回合选择，不能把第二回合当失败后的纠偏。
