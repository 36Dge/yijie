## 2. Alpha三项与通过条件

为缩短执行，Alpha不再跑七组复合场景；只覆盖三个实际Kimi工具各一次成功可用性。可明确点名工具，采用短提示和普通公开网页，不测试模型自动意图分流能力，也不新增分类调用。

| 用例 / Must AC | 操作 | 唯一通过条件 | 当前结果 |
|---|---|---|---|
| A1 / AC-A01 | 实际App中选用Kimi连接器，请使用Basic搜索一个普通公开主题并回答；工具名kimi_web_search，默认摘要模式 | **该工具调用成功，并在聊天区看到回答** | NOT RUN |
| A2 / AC-A02 | 请使用Pro搜索一个普通公开主题并回答；工具名kimi_web_search_pro，不要求站点/日期过滤 | **该工具调用成功，并在聊天区看到回答** | NOT RUN |
| A3 / AC-A03 | 给定一个普通公开URL，请使用Fetch读取并回答；工具名kimi_web_fetch | **该工具调用成功，并在聊天区看到回答** | NOT RUN |

“成功”指真实Kimi工具调用结束并被正常产品标为成功，不能只停留在提案/待审批/运行中，也不能以错误返回或mock结果代替。“看到回答”指聊天区出现非空助手回答文本；只有思考中、进度提示或工具卡不算回答。成功空结果后出现“没有找到”等回答也算通过；不评判这段回答是否正确、完整、好用或引用充分，不额外要求完整usage或另做终态材料核对。

**A1、A2、A3全部通过，即FEAT-162本期Alpha通过，可据此将本需求标为通过并关闭。** 不要求七例全跑，不强制工具串联、E5第二轮、Basic正文模式、Pro筛选、新历史重开、视觉专项或另做failure/retry。允许在同一可用App中逐项完成并累计结果；不要求为了凑一次fresh批次重复全部已通过项或反复构建。修复后只复验实际受影响的项。

非预期额外工具或原生搜索不会单独使Alpha失败；本例仍须实际成功调用其对应的Kimi工具并看到回答。只调用原生搜索不能替代三项Kimi工具。未观察到这两个事实的项记FAIL或NOT RUN，不从旧日志推定通过。

## 3. 不作为Alpha判定的内容

- 回答正确性、完整性、摘要/正文质量、非空chunks质量或充分性。
- 引用准确性、来源关系、搜索结果顺序、Pro→Fetch URL一致性及日期/站点核对。
- 完整usage、逐笔费用、账单、费用记录对账或历史未知费用补齐。
- 标准层的模型自动路由准确性、严格调用序列、逐例请求次数和一次fresh全量验收。

不收集以上材料来决定Alpha是否通过，也不因其缺失/未知将已符合两项事实的用例改判失败。标准验收的原规则没有删除或降低，只是本期不执行这些核对。

最小结果记录仅需：A1/A2/A3、实际工具名、成功是否可见、回答是否可见、结论；可引用现成会话或一张截图，不要求额外搭建证据系统。记录“未核对质量/来源/费用”，不得写成这些项目已PASS。

## 4. 执行边界及费用约定

本次只变更文档与本期通过定义，**不自动恢复App构建/启动或收费调用**。第08、09代、全部历史App/备份/证据/账本继续保留。既有20元软停止约定并未被“不核对费用记录”撤销：允许在途超过20元，已知达到阈值后不再发起后续收费；不要求费用硬上界或补齐费用记录才能判Alpha通过，未完成项照实保留。旧费用记录原样保留，无需为Alpha重新核对或补账。
