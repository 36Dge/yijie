# FEAT-162 Kimi 模型密钥复用调整方案

状态：2026-10-24，用户明确要求先给方案再改配置流程；本文件先于本轮产品代码修改落盘。此前“必须独立填写Key”的决策被本轮明确授权取代。真实收费API仍禁止；本轮也不执行/models联网检查或模型回合。

## 用户流程

1. 原有Kimi网页检索保持一个连接器、两个工具。已安装/取消过的安装继续使用原记录，不清库或删除历史。
2. 详情显示“复用已配置的Kimi模型密钥，无需重复填写”；主操作改为“使用现有Kimi密钥”。点击只绑定现有凭据、返回已配置但未验证/未启用，不创建浏览器凭据页、不执行任何HTTP。
3. 缺少可用模型Key时返回安全的not_configured状态，提示先完成Kimi模型配置；不能退回要求在连接器再次填写，也不回显路径、Key或源异常。
4. 完成本地绑定后，主操作为“检查连接并启用”，明确会访问Kimi的/models基础接口；只有用户之后执行该步骤才沿原Probe完成连接资格。基础检查不证明Search/Fetch权限、余额或正文质量。
5. 任务显式选用、ask逐次批准和一次HTTP许可保持。安装、绑定、启用与收费工具调用分别表达，绑定成功不能冒充联网验证。
6. 停用/卸载只撤销连接器权限和绑定；不会清除Kimi模型Key。允许既有forget清理历史独立连接器alias，但不会把它当作新的凭据来源。

## 实现与边界

- Host当前已从Native认可的owner-only文件加载Kimi Key，模型运行时使用该进程内值。本轮直接复用该已加载值，避免再按另一个文件时间点读取而与模型不一致。
- Host→Connectors worker增加单次、私有、匿名启动管道，固定FD3和非秘密来源标识；最多16KiB，与Host原有上限一致。私有流使用版本前缀、Key及末尾换行后EOF，缺少结尾标记拒绝，避免部分写入被误认成完整Key。Key不放argv/env、JSONL控制协议、公共IPC、配置文件或日志。worker在建立线程/子进程前一次性读取并关闭FD，限于kimi-web适配器的进程内引用。
- 不重建Agent循环、不修改yijie-codex内核、不增加第三方包或新服务。原控制协议、Gateway、Keyring其他服务、逐次审批和HTTP无重试保留。
- 模型与连接器在同一个Host生命周期使用同一Key快照。更换模型Key沿既有正常应用重启重新加载，两者同时更新；旧worker停止撤销全部连接资格。不后台监听/热替换Key，不自动复制Keyring，不新增第二份持久密钥。
- Kimi配置动作只校验已接收的本地凭据存在且格式有效，返回authorization=authorized（本地来源绑定）、connection=disconnected、qualification=not_qualified、executionAvailable=false；专属界面文案明确“尚未联网验证”。只有启用Probe保留原GET/models语义。
- 新增provider安全错误not_configured，映射到现有Native/UI的not_configured。缺失来源不会阻塞其他连接器或整个Host，不会误报“用户取消”。
- 私有来源错误只产出闭集安全错误，不记录密钥内容或原始OS错误；SecretGuard继续保护工具参数与结果。

## 验证与交付

- 普通合成Key仅在内存/匿名管道验证：同值交接、无源、合法格式边界、无HTTP的configure结果、正常EOF及关闭；不伪造可执行文件、不改坏权限、不注入攻击fixture、不强杀。
- Host/worker测试验证Key不进入argv/env/control响应，其他服务保持原有路径。旧独立Kimi表单改为不可达，不再要求用户重复输入。
- UI测试：复用提示、按钮、缺失来源说明、本地绑定已配置但未启用、启用入口明确网络检查、卸载不声称删除模型Key。
- 真实App只执行本地“使用现有Kimi密钥”，不输出/人工读取Key，不点击“检查连接并启用”，不做Search/Fetch或模型回合。核对状态及正常重开。
- 保留当前账户Search/Fetch能力、模型驱动MCP及D4为NOT RUN。方案和实际命令、失败、产物摘要、截图、已跳过项写入本Feature；不提交/推送/发布。
