# ADR-0024 应用托管文档环境与普通对话内置能力

## 状态

Accepted。2026-11-09 13:45:10 +08:00记录；Owner：段成威。用户在本聊天明确确认FEAT-171需求、技术方案和ADR-0024，并授权按方案实施和相关无计费验证。真实模型测试需另申请额度；暂不提交、推送或发布。前序D0的Proposed状态保留在审计记录中，不冒称当时已批准。

## 背景

当前原生产物已支持格式接收和预览，普通模型仍可能选择依赖缺失的系统环境。专家脚本不能作为零市场安装的普通聊天底座。需要参照Codex的独立workspace依赖、内置指南、原生执行与桌面查看器分层，确定长期跨仓职责。

## 已确认技术决定

1. 九格式属于应用基础能力。Desktop拥有平台依赖包、字体及安装升级；Host负责原生配置和文档工具薄适配；Runtime保留执行、审批、发现与图片查看权威，并在原进程生命周期中增加通用cooperative_only策略候选以关闭已发现的强杀兜底缺口；Native保持产物持久化、身份及用户预览权威。
2. 使用应用专用路径和版本绑定，不默认系统环境、Codex缓存、源码工作区或现有专家/技能/连接器服务。内置指南可以复用原生扩展点，但市场关闭不能使基础能力消失。
3. 首期macOS14+ Apple Silicon arm64、最低8GiB/推荐16GiB、完整离线依赖包，文档就绪独立于无关工作流。模型联网和身份沿既有权限，不宣称离线模型。
4. 首期不增数据库迁移/版本树；复用现有artifact_id、session/turn和sha256，保持7天保留并提示另存。同generation ACK由只读get_artifact_status确认，失忆返回unknown。文件/版本为本地产物事实源，复用publisher/spool/Native提交ACK/保存/右栏。生成、解析、用户预览与QA分层且同digest绑定。模型查看QA图必须复用原生view_image。
5. 不复制OpenAI私有Artifact Tool、签名应用或缓存二进制。选择可再分发组件、自有可复现构建及SBOM；源级锁版本、官方摘要及许可履约见FEAT-171/06，资源预算见07；最终制品hash/SBOM/签名留实施发行门禁。不另造planner、执行循环或权限例外。

## 备选方案

系统环境自动安装不满足可复现与零配置；默认启用现有专家违反用户边界；复制私有包缺少分发资格。推荐自有资源包与薄文档适配，保留既有原生机制。

## 影响与后续动作

增加安装体积、依赖维护和字体治理；需要版本配对、正常升级回退及清洁环境验收。工具/部署边界先源契约，私有存储按兼容迁移。本轮无公开权限变更、签名发行、日常迁移。
